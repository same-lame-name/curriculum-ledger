# 087 — Chokudai's Demand (Counting X by Distance Threshold)

**Difficulty:** ★×5 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_ci
**Source:** AtCoder Typical90 #087 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
AtCoder 国には N 個の街があり、それぞれ 1,2,…,N と番号付けられています。任意の 2 つの街の間には道路があり、交通費 （単位：スヌーク） を支払うことで一方の街から他方の街へ移動することができます。

AtCoder 国の大臣は、最初に正の整数 X を決めた後、それぞれの (i, j) [i ≠ j] の組について交通費を以下のように設定することにしました。
> A[i][j] ≠ -1 のとき：街 i と街 j の間を結ぶ道路の交通費は A[i][j] スヌーク
> A[i][j] = -1 のとき :街 i と街 j の間を結ぶ道路の交通費は X スヌーク

また、チョクダイ国王の意向により、以下の要件を満たさなければなりません。
> 経路を適切に選ぶことで、街 i から街 j まで合計 P スヌーク以下で到達可能であるような
> 組 (i, j) [1 ≦ i < j ≦ N] がちょうど K 個存在する。

チョクダイ国王の意向を満たすような X の選び方はいくつ存在しますか。 
ただし、無限個の場合はそのことを報告してください。

【制約】
・2 ≦ N ≦ 40
・1 ≦ P ≦ 10^9
・0 ≦ K ≦ N(N-1)/2
・i ≠ j ならば 1 ≦ A[i][j] ≦ 10^8 または A[i][j]=-1
・i = j ならば A[i][j]=0
・A[i][j]=A[j][i]
・入力は全て整数
```

## Statement (English translation)
There are N cities in the country of AtCoder, numbered 1, 2, ..., N. There is a road between every pair of cities, and by paying a travel fare (unit: Snuke), one can travel from one city to the other.

The minister of the country of AtCoder decided that, after first choosing a positive integer X, they would set the travel fares for each pair (i, j) [i ≠ j] as follows.
> When A[i][j] ≠ -1: the travel fare of the road connecting city i and city j is A[i][j] Snuke
> When A[i][j] = -1: the travel fare of the road connecting city i and city j is X Snuke

In addition, by the intention of King Chokudai, the following requirement must be satisfied.
> By choosing routes appropriately, there are exactly K pairs (i, j) [1 ≦ i < j ≦ N] such that one can reach from city i to city j with a total of at most P Snuke.

How many ways are there to choose X such that King Chokudai's intention is satisfied?
However, if there are infinitely many, report that fact.

## Constraints
```
【制約】
・2 ≦ N ≦ 40
・1 ≦ P ≦ 10^9
・0 ≦ K ≦ N(N-1)/2
・i ≠ j ならば 1 ≦ A[i][j] ≦ 10^8 または A[i][j]=-1
・i = j ならば A[i][j]=0
・A[i][j]=A[j][i]
・入力は全て整数
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 全点対間最短経路はワーシャルフロイド法 (all-pairs shortest paths → Warshall–Floyd) — P1. P2's keyword is 答えで二分探索 (binary search on the answer).
- **Core idea:** Let f(x) be the number of vertex pairs whose shortest distance is at most P when every undetermined edge (-1) is given length x. We must count the integers x with f(x) = K. Increasing x only lengthens edges, so no shortest distance ever decreases: f is 広義単調減少 (non-increasing). Hence {x : f(x) = K} is one contiguous interval, and it is exactly [L, R) where L = min{x : f(x) ≤ K} and R = min{x : f(x) < K}, so the answer is R − L. Each evaluation of f(x) is one all-pairs shortest-path computation (Warshall–Floyd, O(N^3)), and the two boundaries are found by binary search.
- **Editorial steps:**
  - **Step 1 (P1 ステップ 1 — how to compute f(x) for a given x):** “まず、整数 x が与えられたとき f(x) の値を求める方法を考えましょう。” Computing f(x) only needs 全頂点間の最短経路 (all-pairs shortest paths). First method offered: for each vertex i, find the shortest-path lengths from i to every vertex, i.e. run Dijkstra from all N vertices (“頂点 1,2,3,…,N それぞれについて…「頂点 i から各頂点への最短経路の長さ」を求める”). Since the graph here has N vertices and O(N^2) edges, this is O(N^3 log N) by Dijkstra (▶典型 013), and “もちろんこの方法でも問題ありません (※)”. Footnote (※): besides the O(|E| log |V|) Dijkstra there is an O(|V|^2) version; using it computes all-pairs shortest paths in O(N^3).
  - **Step 2 (P1 ステップ 2 — the cheaper way: Warshall–Floyd):** “しかし、全点対間最短経路を計算するにあたって、もっと簡単かつ高速な方法があります。ワーシャルフロイド法です。” With A[i][j] the length of edge (i,j): initialize `dist[i][j] = A[i][j]` for all i,j and `dist[i][i] = 0` (“最初、初期値を辺の長さにする”), then for k = 1…N, i = 1…N, j = 1…N update `dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j])` (“最短距離の長さを更新していく”). The slide stresses the implementation is extremely short (“このように、非常に簡単に実装することができます”), costs O(N^3), is fast enough to get AC (“AC を出すには十分高速です”), and points to https://algo-logic.info/warshall-floyd/ for details.
  - **Step 3 (P1 ステップ 3 — shape of y = f(x)):** “次に、f(x) = K となる整数 x の個数を考えてみましょう。実は、まだ決まっていない辺の長さをすべて x にした場合における「最短距離が P 以下の頂点対の個数」を f(x) とすると、y = f(x) のグラフは次のようになります。” The plot (x horizontal, y vertical, level K marked) shows a step-like curve that only goes down, with the x-axis split at L and R into a red left part, a yellow middle part of width R − L, and a green right part. The stated reason: “特に、「辺の長さを増やしていく場合、一度最短距離が P を超えた頂点対が P 以下に戻ることがない」という重要な性質があります。したがって、関数 f(x) は広義単調減少となります。”
  - **Step 4 (P2 ステップ 1 — rephrase the answer with two boundaries):** “求める答えである「f(x) = K となる整数 x の個数」は以下のように言い換えることができます。” (i) let L be the smallest x with f(x) ≤ K; (ii) let R be the smallest x with f(x) < K; (iii) then the answer is R − L. The two predicates are monotone in x, which is what makes boundary binary search legal: “ある一定値までは f(x) ≤ K が成り立たず、ある一定値 (x = L) から成り立つ”, and likewise “ある一定値までは f(x) < K が成り立たず、ある一定値 (x = R) から成り立つ”, therefore “境界を二分探索することが可能です”. The accompanying table (columns x = 0, 1, …, …, L, …, R, …) marks “f(x) ≤ K か?” as × × × × ○ ○ ○ ○ and “f(x) < K か?” as × × × × × × ○ ○.
  - **Step 5 (P2 ステップ 2 — numeric trace, K = 3):** “例えば K = 3 であり、f(x) の値が次の表の通りである場合を考えてみてください”: x = 0,1,2,3,4,5,6,7 with f(x) = 9,6,5,3,3,2,1,0, and “最初から 0 ≤ L ≤ 7 だと分かっている場合”, the value of L is pinned down in three queries. (1) ask f(3) ≤ K? — Yes, so L ∈ {0,1,2,3} (“今回はこちら”). (2) ask f(1) ≤ K? — No (f(1) = 6), so L ∈ {2,3} (“今回はこちら”). (3) ask f(2) ≤ K? — No (f(2) = 5), so L = 3 (“今回はこちら”). Each query halves the candidate set (“ちょうど半分ずつに候補が分かれる”). Running the same procedure with the predicate f(x) < K on this table would give R = 5 (f(5) = 2 < 3, f(4) = 3), hence R − L = 2 (x = 3, 4); note the slide itself traces only the L queries.
  - **Step 6 (P2 ステップ 3 — combine, and handle infinity):** “このように、境界で二分探索することによって O(log Z) 回 f(x) の値を調べることで、L, R が求められます。(Z は L, R としてあり得る最大の値です)”. Combining Warshall–Floyd with binary search solves the problem in O(N^3 log Z). Implementation warning: “実装の際には答えが infinity となる場合の処理に注意してください。R のみが +∞ となるケース、(L, R) = (+∞, +∞) となるケース両方があり得ます。(後者の場合答えは 0)”. The slide also notes this boundary-binary-search idea is the origin of the very first problem of 「競プロ典型 90 問」 and has already appeared as ▶典型 001.
- **Complexity:** One evaluation of f(x): O(N^3) with Warshall–Floyd (P1 also gives O(N^3 log N) for N Dijkstras, or O(N^3) with the O(|V|^2) Dijkstra of the footnote). With O(log Z) evaluations: O(N^3 log Z), where Z is the largest candidate value of L, R (no numeric value for Z is given on the slides). Memory: Not stated on the slides.
- **Author's takeaway / typical pattern (典型):** Two transferable moves. (1) 全点対間最短経路 → ワーシャルフロイド法: N is tiny (N ≤ 40) and the graph is dense (O(N^2) edges), so the triple loop is both the simplest and fast enough, beating N Dijkstras. (2) 答えで二分探索: when the quantity being counted is governed by a non-increasing step function, don't enumerate x — binary search the two boundaries of the plateau and subtract them (R − L).
- **Related problems (類題):** ABC020-C 「壁抜け」, ABC155-D 「Pairs」. In-set pointer: ▶典型 001, cited as the origin of the boundary-binary-search idea.
- **Flags:** (a) Monotonicity of f is asserted as “重要な性質” and justified in one line (“一度最短距離が P を超えた頂点対が P 以下に戻ることがない”); the underlying argument (raising x lengthens only the -1 edges, so every dist[i][j] is non-decreasing in x) is left implicit — derive it. Boundary to test: paths that use several -1 edges, and ties exactly at distance = P (the count uses ≤ P). (b) The Step 2 init `dist[i][j] = A[i][j]` is written with A as “the length of edge (i,j)”, but the input matrix stores -1 for undetermined edges; the substitution -1 → x is never spelled out on the slides (the reference code does `if (A[i][j] == -1) dist[i][j] = lens;`). Leaving -1 in dist silently breaks the min. (c) The statement requires a positive integer X, while the slides speak of “整数 x” and their trace table starts at x = 0; the counted interval [L, R) must be intersected with x ≥ 1. (d) Z is defined only as “L, R としてあり得る最大の値”, with no numeric bound; and the infinity criterion (how to detect R = +∞ / (L, R) = (+∞, +∞)) is described only qualitatively, so the threshold choice is left to the implementer (the reference code searches up to 5·10^9 and prints `Infinity` when R − L ≥ 2·10^9). Boundaries to test: K = 0 and K = N(N−1)/2. (e) The P1 graph is schematic — the plotted points inside the yellow band do not sit exactly at y = K, so read it as “red: f > K, yellow: f = K, green: f < K”, not as literal values.

## Author's Reference Solution
`087.cpp` — Runs Floyd–Warshall for a given X to count pairs with distance at most P, binary-searches the smallest X for which that count is at most K and at most K−1, and prints the difference (or `Infinity` when the range is extremely wide).

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

long long N, P, K, A[69][69];
long long dist[69][69];

int count_number(long long lens) {
	for (int i = 1; i <= N; i++) {
		for (int j = 1; j <= N; j++) {
			if (A[i][j] == -1) dist[i][j] = lens;
			if (A[i][j] != -1) dist[i][j] = A[i][j];
		}
	}
	for (int k = 1; k <= N; k++) {
		for (int i = 1; i <= N; i++) {
			for (int j = 1; j <= N; j++) dist[i][j] = min(dist[i][j], dist[i][k] + dist[k][j]);
		}
	}
	int cnt = 0;
	for (int i = 1; i <= N; i++) {
		for (int j = i + 1; j <= N; j++) {
			if (dist[i][j] <= P) cnt++;
		}
	}
	return cnt;
}

long long get_border(long long cnts) {
	long long cl = 1, cr = 5000000000LL, cm, minx = 5000000000LL;
	for (int i = 0; i < 40; i++) {
		cm = (cl + cr) / 2LL;
		int res = count_number(cm);
		if (res <= cnts) { cr = cm; minx = min(minx, cm); }
		else { cl = cm; }
	}
	return minx;
}

int main() {
	cin >> N >> P >> K;
	for (int i = 1; i <= N; i++) {
		for (int j = 1; j <= N; j++) cin >> A[i][j];
	}

	long long L = get_border(K);
	long long R = get_border(K - 1);
	if (R - L >= 2000000000LL) cout << "Infinity" << endl;
	else cout << R - L << endl;
	return 0;
}
```
