# 079 — Two by Two (Adding to 2×2 Blocks)

**Difficulty:** ★×3 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_ca
**Source:** AtCoder Typical90 #079 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
H×W の 2 次元配列 A が与えられます。あなたは以下の 2 種類の操作を好きな順番で何度でも行うことが出来ます。

・整数 x, y (1 ≦ x < H, 1 ≦ y < W) を選び、A[x, y], A[x+1, y], A[x, y+1], A[x+1, y+1] の値をそれぞれ 1 ずつ増やす。
・整数 x, y (1 ≦ x < H, 1 ≦ y < W) を選び、A[x, y], A[x+1, y], A[x, y+1], A[x+1, y+1] の値をそれぞれ 1 ずつ減らす。

操作を 0 回以上行うことで A を B に一致させることは可能でしょうか。
もし可能ならば、最小の操作回数も答えてください。
```

## Statement (English translation)
You are given a two-dimensional array A of size H×W. You may perform the following two kinds of operations any number of times, in any order.

・Choose integers x, y (1 ≦ x < H, 1 ≦ y < W) and increase each of the values A[x, y], A[x+1, y], A[x, y+1], A[x+1, y+1] by 1.
・Choose integers x, y (1 ≦ x < H, 1 ≦ y < W) and decrease each of the values A[x, y], A[x+1, y], A[x, y+1], A[x+1, y+1] by 1.

Is it possible to make A equal to B by performing the operations zero or more times?
If it is possible, also answer the minimum number of operations.

## Constraints
```
【制約】
・2 ≦ H, W ≦ 100
・0 ≦ A[i, j] ≦ 10^5
・入力は全て整数
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 操作順序によらない (independent of the operation order)
- **Core idea:** Each operation adds ±1 to one fixed 2×2 block, so the final array depends only on *how many times* each block was operated on, not on the order. That lets you fix an order (row-major, from the top-left block) and, at each block, read off the only possible count: when block `(i,j)` is reached, `A[i][j]` can no longer be changed by any other operation, so the count is forced to be `B[i][j] − A[i][j]` (apply it `|d|` times with the appropriate sign). After all `(H−1)(W−1)` blocks the top-left region matches B; the remaining `H + W − 1` entries decide Yes/No. Because every count is forced, this also gives the minimum number of operations.
- **Editorial steps:**
  - **Step 1 (the final array does not depend on the order):** if the *set* of operations performed is the same, any order yields the same final array — 「配列の値が「各要素について何回 1 足されるか / 何回 1 引かれるか」のみに依存することを考えると分かりやすいです」. The figure starts from `[[1,4,1],[4,2,1],[3,5,6]]` and applies the same three operations in two orders: `+1` on block (1,1), `+1` on block (2,2), `−1` on block (2,1). Top path: (1,1) → `[[2,5,1],[5,3,1],[3,5,6]]`, then (2,2) → `[[2,5,1],[5,4,2],[3,6,7]]`, then (2,1) → `[[2,5,1],[4,3,2],[2,5,7]]`. Bottom path: (2,1) → `[[1,4,1],[3,1,1],[2,4,6]]`, then (1,1) → `[[2,5,1],[4,2,1],[2,4,6]]`, then (2,2) → `[[2,5,1],[4,3,2],[2,5,7]]`. Same result. Hence doing the operations in the order `(1,1) → (1,2) → (1,3) → … → (H−1,W−1)` (top-left to bottom-right) is legitimate.
  - **Step 2 (each count is forced):** `A_{1,1}` can only be changed by the `(x,y) = (1,1)` operation, so with `v` = the current value of element (1,1) *minus* its target, `v > 0` means performing the "decrease by 1" operation `|v|` times and `v < 0` means performing the "increase by 1" operation `|v|` times. The worked figure takes `A = [[1,4,1],[4,2,1],[3,5,6]]` and `B = [[3,5,3],[5,3,5],[3,5,3]]` and applies `+2` to the top-left block, producing `[[3,6,1],[6,4,1],[3,5,6]]`. Next `A_{1,2}`: since the `(x,y) = (1,1)` operation has already been performed, only the `(x,y) = (1,2)` operation can still change it, so the number of operations is again forced by the current value of element (1,2).
  - **Step 3 (repeat, then check the rest):** repeating this "read the value of element (i,j), then fix block (i,j)" procedure makes the `(H−1)(W−1)` values `A_{1,1}, …, A_{H−1,W−1}` agree with B. Continuing the same example: `+2` on (1,1) → `[[3,6,1],[6,4,1],[3,5,6]]`; `−1` on (1,2) → `[[3,5,0],[6,3,0],[3,5,6]]`; `−1` on (2,1) → `[[3,5,0],[5,2,0],[2,4,6]]`; `+1` on (2,2) → `[[3,5,0],[5,3,1],[2,5,7]]`. The four top-left values now match B, and 「あとは、残りの H + W − 1 個の要素が一致するかどうかを判定すれば、Yes/No が分かります」.
  - **Step 4 (minimality):** when the answer is Yes, for every `(i,j)` the number of times the `(x,y) = (i,j)` operation must be applied is uniquely determined, so the Step 2 procedure attains the minimum number of operations (「ステップ 2 の方法が操作回数最小となります」).
- **Complexity:** `O(HW)` (right column: 「計算量 O(HW) で本問題を解くことができます」). Memory `O(HW)` for the two arrays; the slide does not state it.
- **Author's takeaway / typical pattern (典型):** focus on the fact that the array's values do not depend on the operation order; problems of this kind are often combined with parity arguments (パリティの性質 → 典型 024).
- **Related problems (類題):** ABC090-C「Flip, Flip, and Flip」, ABC125-D「Flipping Signs」, ARC119-C「ARC Wrecker 2」
- **Flags:** (1) The key invariant of the greedy — that after block `(i,j)` has been fixed, no later block can change `A[i][j]`, so the counts are forced — is asserted, never proved; the induction on row-major order is what makes both the algorithm and the minimality claim work. (2) The sign convention is ambiguous on the slide: it says 「現時点で要素 (1,1) の値を v とするとき、v > 0 では |v| 回だけ「1 減らす操作」を…」, but its own figure applies `+2` to go from `A[1][1] = 1` to `B[1][1] = 3`, so `v` must be read as current minus target (`1 − 3 = −2` ⇒ increase twice). A reader who takes `v` literally as the value `1` gets the wrong direction. (3) The slide's worked example is in fact a **No** instance: the final array `[[3,5,0],[5,3,1],[2,5,7]]` does not equal `B = [[3,5,3],[5,3,5],[3,5,3]]` (mismatches at (1,3), (2,3), (3,1), (3,3)), but the slide never says so, so it can be mistaken for a Yes example. (4) Intermediate values may become negative in general (the trace already reaches 0); the statement only requires the final array to equal B, which the slide does not discuss. (5) Invariant to test although not mentioned: each operation changes the total sum by ±4, so `sum(A) ≡ sum(B) (mod 4)` is necessary — a cheap filter the slide's "parity" remark hints at but never states. Other boundaries: `H = W = 2` (the single block is the whole grid), `H = 2` or `W = 2` (one row/column of blocks, so the leftover strip is `H + W − 1` cells), and the accumulated operation count, which can reach `(H−1)(W−1)·10^5 ≈ 10^9`.

## Author's Reference Solution
`079.cpp` — Applies the required difference to each 2×2 block in row-major order, accumulates the number of operations, and finally compares A with B.

```cpp
#include <cmath>
#include <vector>
#include <iostream>
using namespace std;
int main() {
	int H, W;
	cin >> H >> W;
	vector<vector<long long> > A(H, vector<long long>(W)), B(H, vector<long long>(W));
	for (int i = 0; i < H; ++i) {
		for (int j = 0; j < W; ++j) {
			cin >> A[i][j];
		}
	}
	for (int i = 0; i < H; ++i) {
		for (int j = 0; j < W; ++j) {
			cin >> B[i][j];
		}
	}
	long long ans = 0;
	for (int i = 0; i < H - 1; ++i) {
		for (int j = 0; j < W - 1; ++j) {
			int d = B[i][j] - A[i][j];
			A[i][j] += d;
			A[i][j + 1] += d;
			A[i + 1][j] += d;
			A[i + 1][j + 1] += d;
			ans += abs(d);
		}
	}
	if (A == B) {
		cout << "Yes" << endl;
		cout << ans << endl;
	}
	else {
		cout << "No" << endl;
	}
	return 0;
}
```
