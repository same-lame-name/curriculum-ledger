# 063 — Monochromatic Subgrid (row-subset bitmask enumeration)

**Difficulty:** ★×4 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_bk
**Source:** AtCoder Typical90 #063 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
縦 H 行、横 W 列のグリッドがあり、上から i 行目、左から j 列目のマスを (i, j) で表します。マス (i, j) には整数 P[i][j] が書かれています。

さて、このグリッドから（連続するとは限らない）1 つ以上の行と 1 つ以上の列を選ぶことでできる「部分グリッド」であって、次の条件を満たすものを良い部分グリッドと呼びます。

・選んだ行を i[1], i[2], ..., i[A] (1 ≦ i[1] < i[2] < ... < i[A] ≦ H) とし、選んだ列を j[1], j[2], ..., j[B] (1 ≦ j[1] < j[2] < ... < j[B] ≦ W) とすると、マス (i[a], j[b]) (1 ≦ a ≦ A, 1 ≦ b ≦ B) に書かれている整数はすべて同じである。

良い部分グリッドの大きさとしてあり得る最大値を求めてください。
ただし A 個の行・B 個の列からなる部分グリッドの大きさは A×B であるとします。
```

## Statement (English translation)
There is a grid with H rows and W columns, and the cell in the i-th row from the top and the j-th column from the left is denoted by (i, j). An integer P[i][j] is written in cell (i, j).

Now, among the "subgrids" that can be made by choosing one or more (not necessarily contiguous) rows and one or more (not necessarily contiguous) columns from this grid, those satisfying the following condition are called good subgrids.

・Let the chosen rows be i[1], i[2], ..., i[A] (1 ≦ i[1] < i[2] < ... < i[A] ≦ H), and the chosen columns be j[1], j[2], ..., j[B] (1 ≦ j[1] < j[2] < ... < j[B] ≦ W); then the integers written in the cells (i[a], j[b]) (1 ≦ a ≦ A, 1 ≦ b ≦ B) are all equal.

Find the maximum possible size of a good subgrid.
Here, the size of a subgrid consisting of A rows and B columns is A×B.

## Constraints
```
【制約】
・1 ≦ H ≦ 8
・1 ≦ W ≦ 10000
・1 ≦ P[i][j] ≦ HW
・入力はすべて整数
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 変な制約に着目する／状態数が少ない変数を全探索 (pay attention to the odd constraint / brute-force the variable with few possible states)
- **Core idea:** H ≤ 8 while W ≤ 10000, so the row set is the only cheap dimension: enumerate all 2^H − 1 non-empty row subsets. Once the rows are fixed, a column may be chosen exactly when all chosen rows carry the same integer in it, and among those columns the subgrid must use a single integer — so the answer for a fixed row subset is (number of chosen rows) × (largest multiplicity among the common column values). Maximise over subsets → O(2^H × W log W).
- **Editorial steps:**
  - **Step 1 — enumerate the rows (not the columns):** 「まず、W に比べて H の方が圧倒的に小さいので、H 個の行の中から「どの A 個を選ぶか」を全探索しましょう。（H ≦ 8 なので bit 全探索などの手法を使っても間に合います）」. The slide's 4 × 12 example grid, with the arrow 「選び方を全探索」 pointing at rows 2 and 3, is
    ```
    row1 : 1 2 3 1 4 2 3 3 1 3 2 2
    row2 : 3 1 5 5 2 5 4 2 3 1 4 2   <- chosen
    row3 : 5 1 5 3 2 4 4 2 3 2 1 2   <- chosen
    row4 : 3 1 5 3 5 2 2 3 1 3 2 4
    ```
  - **Step 2 — a column survives only if the chosen rows agree:** 「そこで、選ぶ整数は全部同じでなければならないので、選んだ行について同じ整数が書かれていない列を選ぶことはできません」. The second figure repeats the grid with rows 2 and 3 highlighted, the agreeing columns painted yellow (columns 2, 3, 5, 7, 8, 9, 12, reading 1, 5, 2, 4, 2, 3, 2) and the disagreeing columns (1, 4, 6, 10, 11) greyed out.
  - **Step 3 — the reduced problem:** 「すると、「整数 R_1, R_2, …, R_T の中に同じ整数は最大何個ありますか」を求める問題に帰着できました。（その答えがそのまま選べる列数の最大値になります）例えば左表の場合 R = (1, 5, 2, 4, 2, 3, 2) となります」. On that R the value 2 occurs three times, so rows 2 and 3 admit 2 × 3 = 6 cells (the slide prints neither the 3 nor the 6).
  - **Step 4 — count with a map:** 「これは、std::map などを用いて各値が出現する個数を計算すれば、計算量 O(W log W) で求められます。（std::map を知らない人は調べてみてください。典型 027 などでも出題済みです）」. The slide's snippet is
    ```
    // ステップ 2 のみのサンプルコード
    int maximum_same(vector<int> R) {
        map<int, int> Map; int ret = 0;
        for (int i = 0; i < R.size(); i++) {
            Map[R[i]] += 1;
            ret = max(ret, Map[R[i]]);
        }
        return ret;
    }
    ```
  - **Step 5 — total and the general lesson:** 「このように、行について bit 全探索することで、計算量 O(2^H × W log W) でこの問題を解くことができました。今回の問題で問われた、探索すべき場合の数が小さそうな変数を決め打ちして全探索するテクニック、そして N ≦ 8, N ≦ 40, A_i ≦ 9 など変な制約に着目する手法は、ABC に限らず ARC などでも問われる重要な典型です」.
- **Complexity:** O(2^H × W log W) as stated. Memory: not stated on the slides (the reference code keeps the grid `P[19][10009]` and a fresh `map` per subset).
- **Author's takeaway / typical pattern (典型):** look at the constraint that is disproportionately small (here H ≤ 8), 決め打ちして全探索 that variable, and solve the rest greedily/efficiently; the same instinct covers 「N ≦ 8」「N ≦ 40」「A_i ≦ 9」-style constraints in ABC and ARC.
- **Related problems (類題):** ARC 119-A「119×2^23+1」, ABC 159-E「Dividing Chocolate」, 三井住友信託銀行プログラミングコンテスト 2019 D「Lucky PIN」, ABC 089-C「March」.
- **Flags:** (1) The objective A × B is never written: Step 3 says only 「（その答えがそのまま選べる列数の最大値になります）」, so multiplying by the number of chosen rows is left to the reader (the code does `cntH * cntW`). Boundary: reading it as A + B changes the answer — test one row chosen with three usable columns (answer 3, not 4). (2) The stated O(2^H × W log W) hides an O(H) factor: for each subset and each column the chosen rows must be compared (`063.cpp` does this with a triple loop k over H), and the row count is also an O(H) scan; with H ≤ 8 the factor is harmless but the quoted bound is not literally what the code costs. (3) The example is shown but never evaluated: the yellow columns of rows 2 and 3 are 2, 3, 5, 7, 8, 9, 12 with values R = (1, 5, 2, 4, 2, 3, 2), whose maximum multiplicity is 3 (value 2) and whose answer is 6; the slide stops at the R vector. (4) 「W に比べて H の方が圧倒的に小さい」 is the stated premise, yet nothing says what to do when W < H (transpose the grid so that the enumeration stays on the small dimension) — under H ≤ 8 correctness never breaks, but the transferable rule 「状態数が少ない変数を全探索」 needs that check. (5) Subsets are non-empty by the statement (「1 つ以上の行」), which the code encodes as `for (int i = 1; i < (1 << H); i++)` — the slide never says the empty row set must be excluded, and it is exactly the boundary at which an all-different grid reduces to the single-row case (answer = 1 × 1 = 1). (6) `maximum_same(vector<int> R)` takes R by value, copying up to W = 10000 ints per subset (255 × 10^4 copies); harmless, but the slide presents it as the cost model.

## Author's Reference Solution
`063.cpp` — Enumerates every non-empty subset of the H rows, keeps the columns whose values are identical across the chosen rows, counts the most frequent of those values with a map, and maximizes (number of chosen rows) × (that count).

```cpp
#include <iostream>
#include <vector>
#include <map>
#include <algorithm>
using namespace std;

int H, W;
int P[19][10009];

int maximum_same(vector<int> R) {
	map<int, int> Map; int ret = 0;
	for (int i = 0; i < R.size(); i++) {
		Map[R[i]] += 1;
		ret = max(ret, Map[R[i]]);
	}
	return ret;
}

int main() {
	// Step #1. 入力
	cin >> H >> W;
	for (int i = 0; i < H; i++) {
		for (int j = 0; j < W; j++) cin >> P[i][j];
	}

	// Step #2. 全探索
	int Answer = 0;
	for (int i = 1; i < (1 << H); i++) {
		vector<int> R;
		for (int j = 0; j < W; j++) {
			int idx = -1; bool flag = false;
			for (int k = 0; k < H; k++) {
				if ((i & (1 << k)) == 0) continue;
				if (idx == -1) idx = P[k][j];
				else if (idx != P[k][j]) flag = true;
			}
			if (flag == false) R.push_back(idx);
		}

		int cntH = 0, cntW = maximum_same(R);
		for (int j = 0; j < H; j++) {
			if ((i & (1 << j)) != 0) cntH += 1;
		}
		Answer = max(Answer, cntH * cntW);
	}
	cout << Answer << endl;
	return 0;
}
```
