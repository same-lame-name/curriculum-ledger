# 043 — Maze Challenge with Lack of Sleep (Minimum Direction Changes in a Maze)

**Difficulty:** ★×4 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_aq
**Source:** AtCoder Typical90 #043 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
縦 H マス、横 W マスのグリッド状の迷路があり、上から i 行目・左から j 列目のマスを (i,j) とします。マス (i,j) は S[i][j] = '#' のとき壁で、S[i][j] = '.' のとき壁ではありません。

あなたは上下左右に隣接する壁でないマスへの移動を繰り返してマス (rs,cs) からマス (rt, ct) に移動したいです。ただし、移動する方向が変わる回数が多いと脳が疲れてしまうため好ましくありません。また、迷路の外へ出るような移動は許されません。

移動する方向が変わる回数の最小値を求めてください。

【制約】
・2 ≦ H, W ≦ 1000
・1 ≦ rs, rt ≦ H
・1 ≦ cs, ct ≦ W
・(rs, cs) ≠ (rt, ct)
・H, W, rs, cs, rt, ctは整数
・S[i][j] は '#' または '.'
・S[rs][cs], S[rt][ct] は '.'
・マス (rs,cs) からマス (rt,ct) への移動が可能
```

## Statement (English translation)
There is a grid-shaped maze with H rows and W columns, and the cell at the i-th row from the top and j-th column from the left is (i, j). Cell (i, j) is a wall when S[i][j] = '#', and is not a wall when S[i][j] = '.'.

You want to move from cell (rs, cs) to cell (rt, ct) by repeatedly moving to a non-wall cell adjacent up, down, left, or right. However, because your brain gets tired when the direction of movement changes many times, that is undesirable. Also, moves that leave the maze are not allowed.

Find the minimum number of times the direction of movement changes.

## Constraints
```
【制約】
・2 ≦ H, W ≦ 1000
・1 ≦ rs, rt ≦ H
・1 ≦ cs, ct ≦ W
・(rs, cs) ≠ (rt, ct)
・H, W, rs, cs, rt, ct は整数
・S[i][j] は '#' または '.'
・S[rs][cs], S[rt][ct] は '.'
・マス (rs, cs) からマス (rt, ct) への移動が可能
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 拡張 BFS・ダイクストラ (BFS / Dijkstra on an expanded graph).
- **Core idea:** The quantity being minimized is the number of direction changes, which no cell-only state can express, so expand every cell into four states — dist[i][j][d] = the minimum number of turns needed to stand at (i,j) facing direction d. Moving forward in the direction you already face costs 0 and changing direction costs 1; since all edge costs are 0 or 1, a 0-1 BFS solves the expanded graph in O(HW).
- **Editorial steps:**
  - **Step 1 (why plain BFS fails; the two-step model):** If the objective were the number of moves, this would be an ordinary shortest-path problem on cells and plain BFS (幅優先探索) would solve it efficiently. But here the number of 方向転換 (direction changes) must be minimized, so it does not become a "simple shortest-path on each cell". Tidying the problem up: the walk consists of repeating one of two kinds of steps — ① move one cell in the direction you currently face (cost 0); ② change the direction you face (cost 1) — and the task is to minimize the total cost from start to goal.
  - **Step 2 (four distances per cell):** Record, for every cell, the following four kinds of "shortest path" and compute them as a shortest-path problem: dist[i][j][0] = minimum number of turns to be at (i,j) facing up; dist[i][j][1] = … facing right; dist[i][j][2] = … facing down; dist[i][j][3] = … facing left.
  - **Step 3 (solve on the expanded graph):** Once each cell carries its direction, the state transitions make the whole thing a shortest-path problem, solved efficiently with Dijkstra's algorithm or with 0-1 BFS (the algorithm for the case where every edge cost is 0 or 1). The slide's figure is a 4 × 6 grid where every cell shows its four values (up/left/right/down): the start cell is 0 in all four, the corridor along the first row keeps "right" = 0 while the other three read 1, the two open cells of the last column read 2/2/2/1, and the bottom row reads up/right/down = 3 with left = 2; the caption says 「方向転換の最小値は 2 と求めています」 — the answer is read off the goal.
  - **Step 4 (footnotes: alternative formulation and complexity):** The alternative reading — "one move advances straight until you turn" — is also a shortest-path problem, but it costs O(HW(H + W)) (※1). Dijkstra runs in O(HW log HW) and 0-1 BFS in O(HW) (※2); the slide advises knowing both, and notes that in Java or Python Dijkstra is hard to pass while 0-1 BFS is accepted.
- **Complexity:** O(HW) with 0-1 BFS; O(HW log HW) with Dijkstra. Memory not stated on the slide (the reference code keeps dist[H][W][4]).
- **Author's takeaway / typical pattern (典型):** The idea of 「頂点を拡張して状態を管理する」 — expanding each vertex so the state can be carried — widens the reach of shortest-path algorithms. The slide notes this idea is also called 「拡張ダイクストラ」 (extended Dijkstra).
- **Related problems (類題):** JOI 2017 予選 6「ヘビの JOI 君」, JOI 女性部門 (JOIG 2021) 問題 5「バレード」, ABC 132-E「Hopscotch Addict」.
- **Flags:** (1) The initial direction is never discussed: the reference code sets all four dist[sx][sy][i] = 0 and answers with the minimum over the four goal states, i.e. the starting direction is free — which is exactly what makes sample 2 answer 0, but the slide never states the convention. (2) 0-1 BFS is only named, not specified: its requirement (push to the front on a cost-0 edge, to the back on a cost-1 edge, and relax whenever a strictly smaller distance is found) is absent from the slide, and `043.cpp` follows exactly that pattern with no visited array — the boundary to test is a cell reachable with the same cost from two different directions. (3) The figure's numbers belong to the slide's own grid, not to any sample; the 「2」 is the answer of that grid only and must not be read as sample 1's 2. (4) The O(HW(H + W)) bound for the "advance until you turn" formulation is asserted without derivation, as is the claim that Dijkstra is too slow in Java/Python.

## Author's Reference Solution
`043.cpp`

```cpp
#include <deque>
#include <iostream>
using namespace std;
const int inf = 1012345678;
const int dx[4] = { 1, 0, -1, 0 };
const int dy[4] = { 0, 1, 0, -1 };
int H, W, sx, sy, gx, gy, dist[1009][1009][4]; char S[1009][1009];
struct state {
	int x, y, dir;
};
int main() {
	cin.tie(0);
	ios_base::sync_with_stdio(false);
	cin >> H >> W >> sx >> sy >> gx >> gy;
	--sx, --sy, --gx, --gy;
	for (int i = 0; i < H; ++i) {
		cin >> S[i];
	}
	for (int i = 0; i < H; ++i) {
		for (int j = 0; j < W; ++j) {
			dist[i][j][0] = inf;
			dist[i][j][1] = inf;
			dist[i][j][2] = inf;
			dist[i][j][3] = inf;
		}
	}
	deque<state> deq;
	for (int i = 0; i < 4; ++i) {
		dist[sx][sy][i] = 0;
		deq.push_back({ sx, sy, i });
	}
	while (!deq.empty()) {
		state u = deq.front(); deq.pop_front();
		for (int i = 0; i < 4; ++i) {
			int tx = u.x + dx[i], ty = u.y + dy[i], cost = dist[u.x][u.y][u.dir] + (u.dir != i ? 1 : 0);
			if (0 <= tx && tx < H && 0 <= ty && ty < W && S[tx][ty] == '.' && dist[tx][ty][i] > cost) {
				dist[tx][ty][i] = cost;
				if (u.dir != i) deq.push_back({ tx, ty, i });
				else deq.push_front({ tx, ty, i });
			}
		}
	}
	int answer = inf;
	for (int i = 0; i < 4; ++i) {
		answer = min(answer, dist[gx][gy][i]);
	}
	cout << answer << endl;
	return 0;
}
```
