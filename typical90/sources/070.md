# 070 — Plant Planning (Sum of Manhattan Distances)

**Difficulty:** ★×4 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_br

## Statement (original Japanese)
```
二次元平面上に N 棟の工場があり、i 番目の工場は座標 (X[i], Y[i]) にあります。

これからあなたは二次元平面上の好きな場所を 1 つ選び、発電所を建設します。
発電所の不便さを、発電所から各工場までのマンハッタン距離の総和と定義するとき、不便さとしてありうる最小の値を求めてください。
```

## Statement (English translation)
There are N factories on a two-dimensional plane, and the i-th factory is at coordinates (X[i], Y[i]).

You will now choose one location you like on the two-dimensional plane and build a power plant there.
When the inconvenience of the power plant is defined as the sum of the Manhattan distances from the power plant to each factory, find the smallest possible value of the inconvenience.

## Constraints
```
【制約】
・1 ≦ N ≦ 10^5
・-10^9 ≦ X[i], Y[i] ≦ 10^9
・入力はすべて整数
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** x, y 独立に考える (treat the x and y coordinates independently)
- **Core idea:** Manhattan distance splits coordinate-wise: dist((X_i,Y_i),(a,b)) = |X_i−a| + |Y_i−b|, so the total inconvenience is f_x(a) + f_y(b) with f_x(a) = Σ|X_i−a| and f_y(b) = Σ|Y_i−b|. The two terms share no variable, so each is minimised separately, and each is minimised at a median of the corresponding coordinates: answer = ans_x + ans_y.
- **Editorial steps:**
  - **Step 1 (separation of the coordinates):** For a plant at (a,b) the inconvenience is dist((X_1,Y_1),(a,b)) + dist((X_2,Y_2),(a,b)) + … + dist((X_N,Y_N),(a,b)) = |X_1−a| + |Y_1−b| + |X_2−a| + |Y_2−b| + … + |X_N−a| + |Y_N−b| = (|X_1−a| + |X_2−a| + … + |X_N−a|) + (|Y_1−b| + |Y_2−b| + … + |Y_N−b|). Hence, with ans_x = min_a Σ|X_i−a| and ans_y = min_b Σ|Y_i−b|, the minimum inconvenience is ans_x + ans_y. The slide's figure reads 不便さ 7 = 絶対値計 4 + 絶対値計 3.
  - **Step 2 (why the median — the one-step difference):** Let f(a) = |X_1−a| + |X_2−a| + … + |X_N−a|. Increasing a by 1 raises by 1 every term whose point lies to the left of a and lowers by 1 every term whose point lies to the right (the slide compares this with the derivative idea). Thus f changes by (#points on the left) − (#points on the right): if more points are on the left it is better to move left, if more are on the right it is better to move right. The minimum is therefore attained when a is a median of X_1, X_2, …, X_N.
  - **Step 3 (compute both minima):** Sort X ascending (std::sort) to obtain the median in O(N log N) — the slide calls the sorting the bottleneck and the reference uses nth_element — then evaluate Σ|X_i − median|; do the same for Y; output ans_x + ans_y.
- **Complexity:** O(N log N) overall (「全体計算量 O(N log N)」); sorting the arrays is the bottleneck. Memory not stated on the slides.
- **Author's takeaway / typical pattern (典型):** 「中央値で絶対値最小」 (the median minimises the sum of absolute deviations) is a reusable fact; ABC102-C 「Linear Approximation」 asks essentially this form. Splitting into x and y is the standard move for Manhattan-distance optimisation.
- **Related problems (類題):** ABC102-C 「Linear Approximation」 (中央値), ARC122-B 「Insurance」 (中央値), ARC071-D 「井井井」 (x, y 独立), ABC127-E 「Cell Distance」 (x, y 独立), JOI2008 春合宿 「Abduction」 (x, y 独立), Tenka1 Programmer Contest 2017 E 「Cartesian Coordinate」 (x, y 独立).
- **Flags:** (1) The median claim is justified only by the one-step difference; there is no convexity/unimodality statement, and points lying exactly at a (whose |X_i−a| also grows by 1 when a moves right) are not discussed. (2) For even N every a between the two middle order statistics minimises f; the slide says "the median" without discussing the interval, and the reference picks the upper median X[N/2]. (3) Coordinates up to 10^9 with N up to 10^5 make the answer up to ~2×10^14, so a 64-bit accumulator is needed; the slide does not say this (the reference uses long long). (4) The statement lets the plant be any point in the plane; the slide never remarks that the optimum can be taken at an input coordinate, so it is not explicit why the integer-median answer is integral (the reference returns the summed deviations, which are integers).

## Author's Reference Solution
`070.cpp` — Selects the median X coordinate and the median Y coordinate with nth_element, then sums the absolute deviations in both axes.

```cpp
#include <cmath>
#include <vector>
#include <iostream>
#include <algorithm>
using namespace std;
int main() {
	int N;
	cin >> N;
	vector<int> X(N), Y(N);
	for (int i = 0; i < N; ++i) {
		cin >> X[i] >> Y[i];
	}
	nth_element(X.begin(), X.begin() + N / 2, X.end());
	nth_element(Y.begin(), Y.begin() + N / 2, Y.end());
	long long ans = 0;
	for (int i = 0; i < N; ++i) {
		ans += abs(X[i] - X[N / 2]);
		ans += abs(Y[i] - Y[N / 2]);
	}
	cout << ans << endl;
	return 0;
}
```
