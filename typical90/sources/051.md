# 051 — Choose exactly K items with total price at most P

**Difficulty:** ★×5 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_ay
**Source:** AtCoder Typical90 #051 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
典型商店には N 個の区別できる品物があります。i 番目の品物 i の値段は A[i] 円です。
あなたは商店に売られている品物からちょうど K 個を選んで、選んだ値段の合計が P 円以下となるように買い物をしたいです。あり得る品物の選び方は何通りあるでしょうか？
なお、2 通りの品物の選び方は、ある品物 i があって、品物 i が一方では選ばれており他方では選ばれていないときに区別されます。

## Statement (English translation)
The "Typical Shop" has N distinguishable items. The price of the i-th item is A[i] yen.
You want to choose exactly K items from those sold at the shop so that the sum of the chosen prices is at most P yen. How many possible ways of choosing items are there?
Two ways of choosing items are considered distinct if there is some item i that is chosen in one way but not in the other.

## Constraints
・1 ≦ K ≦ N ≦ 40
・1 ≦ P ≦ 10^{18}
・1 ≦ A[i] ≦ 10^{16}
・入力はすべて整数

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 半分全列挙をしよう (meet-in-the-middle)
- **Core idea:** N up to 40 makes 2^N ≈ 10^12 too large to enumerate directly, so split the items into two groups of roughly N/2 each. Enumerate all subsets of each half, bucket the subset sums by how many items were chosen, sort each bucket, and then for every subset of the first half binary-search how many subsets of the second half complete it to exactly K items with total ≤ P.
- **Editorial steps:**
  - **Step 1:** N is slightly large, so enumerating all 2^N cases directly is difficult. Therefore split the items as evenly as possible into two groups (call them "Group 1" and "Group 2") and enumerate each of them. If split evenly, the number of items in one group is N/2; hence enumerating "which items to choose" within a group can be done in O(N × 2^{N/2}).
  - **Step 2:** For Groups 1 and 2, we can compute the total price for each choice of items, but that alone is not enough — we must efficiently combine the results of the two to get the answer. To do this, the following devices are necessary:
    - For each group, record the result of the exhaustive search per "number of items chosen".
    - For each record in Group 1, check how many records in Group 2 satisfy the condition. At this time, since the records are sorted, the number of such records can be found at high speed by binary search.
  - (Diagram example, K = 3, P = 15: Group 1 sums by count → 0 items: {0}, 1 item: {2,5,7}, 2 items: {7,9,12}, 3 items: {14}; Group 2 → 0: {0}, 1: {3,6}, 2: {9,9,12}, 3: {15}. A lower/upper bound window over the sorted Group-2 records is shown.)
- **Complexity:** O(N × 2^{N/2}). Furthermore, the log can be dropped by using two pointers instead of sorting + binary search, giving O(2^{N/2}); the author encourages trying this.
- **Author's takeaway / typical pattern (典型):** This technique of splitting the elements in half, searching within each group, and combining the results well is called 半分全列挙 (meet-in-the-middle). Using it, the problem can be solved in a total of O(N × 2^{N/2}).

- **Flags:** none — the editorial is clear and matches the reference code (buckets by chosen count, sort, lower_bound).

## Author's Reference Solution
`051.cpp` — meet-in-the-middle: enumerate both halves into `vec1[cnt]` / `vec2[cnt]` (subset sum bucketed by number of chosen items), sort each bucket, then for each `h` and each sum in `vec1[h]`, add the number of entries in `vec2[K-h]` that are ≤ `P - sum` via `lower_bound`.

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

long long N, K, P, Answer = 0;
long long A[100];
vector<long long> vec1[100], vec2[100];

int main() {
	// Step #1. 入力
	cin >> N >> K >> P;
	for (int i = 0; i < N; i++) cin >> A[i];

	// Step #2. 半分全列挙
	int mid = N / 2;
	for (int i = 0; i < (1 << mid); i++) {
		long long cnt1 = 0, cnt2 = 0;
		for (int j = 0; j < mid; j++) {
			if ((i & (1 << j)) != 0) { cnt1 += A[j]; cnt2 += 1; }
		}
		vec1[cnt2].push_back(cnt1);
	}
	for (int i = 0; i < (1 << (N - mid)); i++) {
		long long cnt1 = 0, cnt2 = 0;
		for (int j = 0; j < N - mid; j++) {
			if ((i & (1 << j)) != 0) { cnt1 += A[mid + j]; cnt2 += 1; }
		}
		vec2[cnt2].push_back(cnt1);
	}
	
	// Step #3. 答えを求める
	for (int i = 0; i <= N; i++) {
		sort(vec1[i].begin(), vec1[i].end());
		sort(vec2[i].begin(), vec2[i].end());
	}
	for (int h = 0; h <= K; h++) {
		for (int i = 0; i < (int)vec1[h].size(); i++) {
			int pos1 = lower_bound(vec2[K - h].begin(), vec2[K - h].end(), P - vec1[h][i] + 1) - vec2[K - h].begin();
			Answer += (long long)pos1;
		}
	}

	// Step #4. 出力
	cout << Answer << endl;
	return 0;
}
```
