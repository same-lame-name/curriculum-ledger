# 040 — Get More Money (Houses, Keys and Costs)

**Difficulty:** ★×7 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_an
**Source:** AtCoder Typical90 #040 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
AtCoder 共和国には N 軒の家があり、1 から N までの番号が付けられています。
それぞれの家に入るには、その家の鍵をすべて集めた上で W 円を支払う必要があります。

家 i の中には、A[i] 円と家 c[i][1], c[i][2], …, c[i][k[i]] の鍵が置いてあり、家に入るとこれを回収することができます。
このとき、任意の 1 ≦ j ≦ k[i] について、c[i][j] > i が保証されます。

入る家をうまく選んだ時、最終的にあなたが得る金額の最大値を求めてください。
すなわち、家に入って回収した金額の合計を I 円、家に入るために支払ったコストを O 円として、I - O を最大化してください。
ただし、あなたは開始時点で十分な金額を持っており、家に入るための費用は必要ならいつでも払えるものとします。

## Statement (English translation)
The AtCoder Republic has N houses, numbered 1 through N.
To enter each house, you need to collect all of the keys of that house and then pay W yen.

Inside house i there are A[i] yen and the keys of houses c[i][1], c[i][2], …, c[i][k[i]], and you can collect these by entering the house.
At this time, for every 1 ≦ j ≦ k[i], it is guaranteed that c[i][j] > i.

Find the maximum value of the amount of money you finally obtain when you choose the houses to enter well.
That is, letting I yen be the total amount of money collected by entering houses and O yen be the cost paid to enter houses, maximize I - O.
However, you have a sufficient amount of money at the starting point, and you can pay the cost to enter a house at any time if necessary.

## Constraints
【制約】
・2 ≦ N ≦ 100
・0 ≦ W ≦ 10^7
・0 ≦ A[i] ≦ 10^7
・0 ≦ k[i] ≦ N-i
・i < c[i][j] ≦ N
・c[i][j] ≠ c[i][k] (j ≠ k)
・入力は全て整数

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 「燃やす埋める問題」に帰着させる (reduce to the "burn-or-bury problem").
- **Core idea:** The "burn-or-bury" problem — each item must be burned at cost x_i or buried at cost y_i, and each rule "burn a_j and bury b_j" adds a fine c_j — is exactly an s-t min cut: source→i with capacity y_i, i→sink with capacity x_i, a_j→b_j with capacity c_j, so a cut pays precisely the chosen per-item costs plus the violated rules. This problem maps onto it: "visit house i" costs W, "do not visit" costs A[i], and "visit c_ij while not visiting i" is forbidden with an infinite fine; the answer is ΣA − (min cut).
- **Editorial steps:**
  - **Step 1 (what 「燃やす埋める問題」 is):** There are N items, each of which must be "burned" or "buried"; burning item i costs x_i (≧ 0) yen, burying it costs y_i (≧ 0) yen. There are also M rules of the form 「品物 a_j を燃やして品物 b_j を埋めると、罰金 c_j (≧ 0) 円かかる」. How few yen are needed in total? The problem is solved efficiently by reducing it to the minimum cut problem. In the slide's figure red vertices are the "burn" items and blue vertices the "bury" items (items 3 and 4 are burned, items 1 and 2 are buried). The stated cost of this approach is O(N² × (N + M)).
  - **Step 2 (the min-cut construction):** Build the graph with the following N + 2 vertices: edge from vertex 0 to i with capacity y_i; edge from vertex i to N + 1 with capacity x_i; edge from vertex a_i to b_i with capacity c_i. The minimum cut between vertex 0 and vertex N + 1 is the answer to the burn-or-bury problem. In the figure the cut puts {0, 3, 4} on the source side and {1, 2, 5} on the sink side; only the four dashed edges cross it — 0→1 (10), 0→2 (20), 3→5 (60), 4→5 (10) — totalling 10 + 20 + 60 + 10 = 100, which is the caption's 「最小コスト = 100」.
  - **Step 3 (this problem):** Since you may consider visiting the houses in increasing index order, this problem also reduces to the burn-or-bury problem: house i costs W yen if 「訪れる」 and A[i] yen if 「訪れない」; if house c_ij is 「訪れる」 while house i is 「訪れない」, a fine of ∞ yen is paid. Letting the answer of that min cut be X, the answer to this problem is (a_1 + a_2 + … + a_N) − X. The overall complexity is O(N^4).
  - **Step 4 (turning the cut into a flow):** Because of the property (最大フロー) = (最小カット), the minimum cut is obtained by computing a maximum flow (footnote ※: on a graph with V vertices and E edges, Dinic's method computes the maximum flow in O(V² × E)).
- **Complexity:** O(N^4) for this problem, and O(N² × (N + M)) for the burn-or-bury problem itself, both by the footnote's O(V² × E) with V = N + 2 and E = O(N² + Σk). Memory not stated on the slides (the reference code keeps a flow graph of N + 2 vertices).
- **Author's takeaway / typical pattern (典型):** 「燃やす埋める問題」 is one way of looking at the minimum cut problem; a problem that at first glance looks difficult can sometimes be reduced to it and solved efficiently. And because (max flow) = (min cut), computing a maximum flow yields the minimum cut.
- **Related problems (類題):** yukicoder No.957「植林」, ARC 085-E「MUL」.
- **Flags:** (1) (最大フロー) = (最小カット) is used as a black box with no proof. (2) The direction of the ∞ edge is the crux and is carried only by the sentence 「家 c_ij を「訪れて」家 i を「訪れない」と、罰金 ∞ 円かかる」; the summary bullet 「家 i を「訪れる」と W 円、「訪れない」と a_i 円」 never says which side of the cut means "visit" (it is the source side, which is why `040.cpp` adds the ∞ edge as c→i), so the mapping of "burn/bury" onto "visit/not visit" must be checked by the reader. (3) Complexity conflict: the slide says O(N^4) via Dinic's O(V²E), while the reference code is a capacity-scaling augmenting-path max flow whose header comment says O(N^4 log W) — the two bounds differ; the algebraic step from ΣA − X to "the gain of the visited set" is also left implicit. (4) Boundaries: W = 0 and A[i] = 0 are allowed by the constraints, so zero-capacity edges occur; the answer can be 0 (sample 2), i.e. visiting nothing must be allowed, which is what the "ΣA − X" form guarantees.

## Author's Reference Solution
`040.cpp` — Builds a flow network (source to each house with capacity A[i], each house to the sink with W, key edges with a large capacity), runs max-flow and prints the sum of A minus the flow.

```cpp
// Time Complexity: O(N^4 log W)

#include <vector>
#include <iostream>
#include <algorithm>
#include <functional>
using namespace std;
const int inf = 1012345678;
class edge {
public:
	int to, cap, rev;
	edge() : to(-1), cap(0), rev(-1) {};
	edge(int to_, int cap_, int rev_) : to(to_), cap(cap_), rev(rev_) {};
};
bool find_augment(int pos, int tar, int step, vector<vector<edge> >& G, vector<bool>& vis) {
	if (pos == tar) return true;
	vis[pos] = true;
	for (edge& e : G[pos]) {
		if (!vis[e.to] && e.cap >= step) {
			bool res = find_augment(e.to, tar, step, G, vis);
			if (res) {
				e.cap -= step;
				G[e.to][e.rev].cap += step;
				return true;
			}
		}
	}
	return false;
}
int max_flow(int src, int tar, int maxstep, vector<vector<edge> >& G) {
	int flow = 0;
	int step = 1;
	while (step * 2 <= maxstep) {
		step *= 2;
	}
	while (true) {
		vector<bool> vis(G.size(), false);
		bool res = find_augment(src, tar, step, G, vis);
		if (!res) {
			if (step == 1) break;
			step >>= 1;
		}
		else {
			flow += step;
		}
	}
	return flow;
}
int main() {
	int N, W;
	cin >> N >> W;
	vector<int> A(N);
	for (int i = 0; i < N; ++i) {
		cin >> A[i];
	}
	vector<vector<edge> > G(N + 2);
	function<void(int, int, int)> add_edge = [&](int va, int vb, int cap) {
		G[va].push_back(edge(vb, cap, G[vb].size()));
		G[vb].push_back(edge(va, 0, G[va].size() - 1));
	};
	for (int i = 1; i <= N; ++i) {
		int K, c;
		cin >> K;
		for (int j = 0; j < K; ++j) {
			cin >> c;
			add_edge(c, i, inf);
		}
	}
	for (int i = 1; i <= N; ++i) {
		add_edge(0, i, A[i - 1]);
		add_edge(i, N + 1, W);
	}
	int res = max_flow(0, N + 1, W, G);
	int answer = -res;
	for (int i = 0; i < N; ++i) {
		answer += A[i];
	}
	cout << answer << endl;
	return 0;
}
```
