# 029 — Top Height of Each Brick When Stacked

**Difficulty:** ★×5 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_ac
**Source:** AtCoder Typical90 #029 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
左右に W 個のマスが並んだ部分があります。
最初、すべての部分について、高さは 0 です。

ここに N 個の高さ 1 のレンガを順に積みます。
i 番目に積むレンガは、左から L[i] 番目から R[i] 番目のマスをちょうど覆うように置きます。
このとき、レンガが覆う範囲の中で最も高い水平な面で接着します。

各レンガについて、上面の高さを求めてください。

## Statement (English translation)
There is a row of W cells side by side.
Initially, the height of every part is 0.

We stack N bricks of height 1 here in order.
The i-th brick to be stacked is placed so that it exactly covers cells L[i] through R[i] from the left.
At this time, it is glued onto the highest horizontal surface within the range it covers.

For each brick, find the height of its top surface.

## Constraints
・2 ≦ W ≦ 500000
・1 ≦ N ≦ 250000
・1 ≦ L[i] ≦ R[i] ≦ W
・入力はすべて整数

【小課題】
1. W ≦ 9000，N ≦ 9000
2. N ≦ 9000
3. 追加の制約はない

## Author's Editorial — Concept & Essence
The editorial gives one approach per subtask.

### P1 — 小課題 1 & 2
- **Keyword (キーワード):** 「座標圧縮」で効率化
- **Core idea:** There is no need for a complicated simulation: it suffices to keep each cell's current height. For each brick, the top height is (max of the covered cells) + 1, and then all covered cells are set to that height. For 小課題 2, coordinate-compress the coordinates so that the number of distinct positions is at most 2N, reducing the cost.
- **Editorial steps:**
  - 小課題 1: no need for a complex simulation. It can be simulated by looking at each cell's current height, in O(NW): with heights h₁, h₂, …, h_W initially 0 and i = 1, 2, …, Q in order, ① the brick's top height h′ is (the maximum of h_{L_i}, h_{L_i+1}, …, h_{R_i}) + 1; ② set h_{L_i}, h_{L_i+1}, …, h_{R_i} all to h′.
  - 小課題 2: the 小課題 1 solution has the following flaw — even if the number N of bricks is small, it takes time when W is large. This can be made efficient with the technique of coordinate compression. By compressing L_i, R_i even when coordinates are large, the coordinates can be placed on 1 … 2N, giving O(N²).
  - (Slide note: this can also be solved by reducing to a "longest path in a DAG" problem.)
- **Complexity:** 小課題 1: O(NW); 小課題 2: O(N²)
- **Author's takeaway / typical pattern (典型):** Coordinate compression removes wasteful computation when coordinates are large, allowing the problem to be solved with a computation amount matching the data size N. Problems that would otherwise have constraints like "(compressed coordinate) ≦ N" even though the coordinates are large can be handled this way.
- **Related problems (類題):** ABC113-C 「ID」, ABC188-D 「Snuke Prime」, JOI 2013 予選 問題5 「魚の生息範囲」

### P2 — 小課題 3
- **Keyword (キーワード):** 区間に対する処理は「セグメント木」
- **Core idea:** On the length-W height array, we need ① range maximum over [L, R] and ② range assignment of a value x over [L, R]. A lazy (delay-evaluation) segment tree performs both in O(log W), giving O(W + N log W) overall.
- **Editorial steps:**
  - 小課題 3: against the 小課題 1 solution, for the length-W array h₁, h₂, …, h_W the following two kinds of processing are needed: ① given L, R, find the maximum of h_L, h_{L+1}, …, h_R; ② given L, R, x, rewrite h_L, h_{L+1}, …, h_R all to x. With the current method both take O(W), which is inefficient.
  - Using a lazy segment tree, each of these can be done in O(log W). A lazy segment tree supports the following in O(log W): adding x to an interval (update) / add; and finding the minimum/maximum/sum of an interval.
  - A plain segment tree can find the maximum of any interval in O(log W) (RMQ); for a single-point value update, only one place per level changes, so O(log W). However, a range update changes many places, so to speed it up we use a "lazy" trick: delaying part of the segment-tree value update until "the value is needed".
- **Complexity:** O(W + N log W). (Slide note: since initializing the segment tree costs O(W), the total is O(W + N log W); combining with the coordinate-compression idea of 小課題 2 also gives O(N log N).)
- **Author's takeaway / typical pattern (典型):** Interval processing can be handled efficiently with a segment tree; however, when updates are performed on an interval, lazy evaluation is necessary.
- **Related problems (類題):** ABC 185-F 「Range Xor Query」, s8pc #2-H 「Counting 1's」, JOI 2010 春合宿 「Hide-and-seek」
- **Flags:** none.

## Author's Reference Solution
- `029-01.cpp` — Subtask 1: naive array simulation; for each brick take `max_element(A+L, A+R)` + 1 and `fill` the range with it.
- `029-02.cpp` — Subtask 2: coordinate-compress all L, R endpoints, then run the same max/fill simulation on the compressed array of size 2N.
- `029-03.cpp` — Subtask 3: lazy segment tree supporting range max and range assignment; per brick query max on [L−1, R) and update the same range to that value + 1.

```cpp
// 029-01.cpp
#include <iostream>
#include <algorithm>
using namespace std;
int W, N, A[524288];
int main() {
	cin.tie(0);
	ios_base::sync_with_stdio(false);
	cin >> W >> N;
	for (int i = 0; i < N; ++i) {
		int L, R;
		cin >> L >> R; --L;
		int height = *max_element(A + L, A + R) + 1;
		fill(A + L, A + R, height);
		cout << height << '\n';
	}
	return 0;
}
```

```cpp
// 029-02.cpp
#include <vector>
#include <iostream>
#include <algorithm>
using namespace std;
int main() {
	cin.tie(0);
	ios_base::sync_with_stdio(false);
	int W, N;
	cin >> W >> N;
	vector<int> L(N), R(N);
	for (int i = 0; i < N; ++i) {
		cin >> L[i] >> R[i];
		--L[i];
	}
	vector<int> compression;
	for (int i = 0; i < N; ++i) {
		compression.push_back(L[i]);
		compression.push_back(R[i]);
	}
	sort(compression.begin(), compression.end());
	compression.erase(unique(compression.begin(), compression.end()), compression.end());
	for (int i = 0; i < N; ++i) {
		L[i] = lower_bound(compression.begin(), compression.end(), L[i]) - compression.begin();
		R[i] = lower_bound(compression.begin(), compression.end(), R[i]) - compression.begin();
	}
	vector<int> h(compression.size() - 1);
	for (int i = 0; i < N; ++i) {
		int height = *max_element(h.begin() + L[i], h.begin() + R[i]) + 1;
		fill(h.begin() + L[i], h.begin() + R[i], height);
		cout << height << '\n';
	}
	return 0;
}
```

```cpp
// 029-03.cpp
#include <vector>
#include <iostream>
#include <algorithm>
using namespace std;
class segment_tree {
private:
	int sz;
	std::vector<int> seg;
	std::vector<int> lazy;
	void push(int k) {
		if (k < sz) {
			lazy[k * 2] = max(lazy[k * 2], lazy[k]);
			lazy[k * 2 + 1] = max(lazy[k * 2 + 1], lazy[k]);
		}
		seg[k] = max(seg[k], lazy[k]);
		lazy[k] = 0;
	}
	void update(int a, int b, int x, int k, int l, int r) {
		push(k);
		if (r <= a || b <= l) return;
		if (a <= l && r <= b) {
			lazy[k] = x;
			push(k);
			return;
		}
		update(a, b, x, k * 2, l, (l + r) >> 1);
		update(a, b, x, k * 2 + 1, (l + r) >> 1, r);
		seg[k] = max(seg[k * 2], seg[k * 2 + 1]);
	}
	int range_max(int a, int b, int k, int l, int r) {
		push(k);
		if (r <= a || b <= l) return 0;
		if (a <= l && r <= b) return seg[k];
		int lc = range_max(a, b, k * 2, l, (l + r) >> 1);
		int rc = range_max(a, b, k * 2 + 1, (l + r) >> 1, r);
		return max(lc, rc);
	}
public:
	segment_tree() : sz(0), seg(), lazy() {};
	segment_tree(int N) {
		sz = 1;
		while (sz < N) {
			sz *= 2;
		}
		seg = std::vector<int>(sz * 2, 0);
		lazy = std::vector<int>(sz * 2, 0);
	}
	void update(int l, int r, int x) {
		update(l, r, x, 1, 0, sz);
	}
	int range_max(int l, int r) {
		return range_max(l, r, 1, 0, sz);
	}
};
int main() {
	cin.tie(0);
	ios_base::sync_with_stdio(false);
	int W, N;
	cin >> W >> N;
	segment_tree seg(W);
	for (int i = 0; i < N; ++i) {
		int L, R;
		cin >> L >> R;
		int height = seg.range_max(L - 1, R) + 1;
		seg.update(L - 1, R, height);
		cout << height << '\n';
	}
	return 0;
}
```
