# 058 — Original Calculator (functional graph cycle detection)

**Difficulty:** ★×4 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_bf
**Source:** AtCoder Typical90 #058 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
あなたは奇妙な電卓を持っています。この電卓は 0 以上 99999 ( = 10^5-1) 以下の整数を 1 つ表示できます。電卓には ボタンA があり、これを 1 回押すと、次の処理が順番に行われます。

> 現在電卓に表示されている整数を x とする。
> 1. x を十進法で表したときの各桁の和を計算し、これを y とする。
> 2. 電卓に表示される整数を「x+y を 10^5 で割ったあまり」に変更する。

いま、この電卓に N が表示されています。 ボタンA を K 回押した後に表示されている整数を求めて下さい。
```

## Statement (English translation)
You have a strange calculator. This calculator can display one integer between 0 and 99999 ( = 10^5-1) inclusive. The calculator has a Button A, and pressing it once performs the following processing in order.

> Let x be the integer currently displayed on the calculator.
> 1. Compute the sum of the digits of x written in decimal notation, and let this be y.
> 2. Change the integer displayed on the calculator to "the remainder of x+y divided by 10^5".

Currently, N is displayed on this calculator. Find the integer displayed after Button A is pressed K times.

## Constraints
```
【制約】
・0 ≦ N ≦ 99999 ( = 10^5-1)
・1 ≦ K ≦ 10^18
・入力はすべて整数
```

# 入力形式
N K

# 出力例 3

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 周期性を考える (think in terms of periodicity)
- **Core idea:** The map x ↦ (x + digit_sum(x)) mod 10⁵ is a deterministic function on only 10⁵ states, so a walk from N must eventually revisit a state, and from the first repeated state on the walk is purely periodic. Detect the entry point and the period with a visited array, then reduce K by the period with a division instead of simulating up to 10¹⁸ presses.
- **Editorial steps:**
  - **Step 1 (study the tiny case 0–9 first):** 「いきなり大きいケースで考えるのは難しいので、試しに小さないケース（0〜9 の場合）で考えてみましょう」. The slide's transition table いまの数 → 次の数 is 0→0, 1→2, 2→4, 3→6, 4→8, 5→0, 6→2, 7→4, 8→6, 9→8 — that is x ↦ 2x mod 10, since a single digit's digit sum is itself. Drawing the arrows gives a functional graph: 0 is a fixed point with a self-loop and 5 → 0; 2 → 4 → 8 → 6 → 2 is a 4-cycle, fed by 1 → 2, 3 → 6, 7 → 4 and 9 → 8. The slide's traces: 例 1 「3 → 6 → 8 → 4 → 2 → 6 → …」 and 例 2 「5 → 0 → 0 → 0 → 0 → 0 → …」, from which 「ボタン A を押すにつれて、右図のサイクルをたどる感じで、周期的に値が変わっていくのが分かるでしょう」.
  - **Step 2 (the real 0–99999 case — detect the cycle):** 「この問題（0〜99999 の場合）でも、先ほどと同様にサイクルをたどる感じになります。2 度目に同じ値に到達したときから、値の変化は周期的になります」. The slide's procedure: (1) initialise vis[i] = false for 0 ≤ i ≤ 99999; (2) set x = N and repeat — update x to 「次の数 z」, and if vis[x] = true you have detected that you are entering the cycle's second lap, so break out of loop 2.
  - **Step 3 (reduce K using the cycle):** Once the time at which the cycle is entered and the period are known, 「それ以降でサイクルを何周もする必要はなく、K 回後にどの数にいるかは割り算で求められます」 — reduce K modulo the period (after subtracting the entry time) and follow the short remaining walk. Overall complexity 「O(N)」.
- **Complexity:** O(N) as stated on the slide (see Flags: the loop is bounded by the 10⁵ states, not by the initial value N, and K ≤ 10¹⁸ is never iterated). Memory not stated on the slides (the reference code keeps a 100000-entry next array and a 100000-entry visit-time array).
- **Author's takeaway / typical pattern (典型):** 「周期性があれば『単純計算では処理できない、10⁹ 番目や 10¹⁸ 番目の値』なども求められる場合があったりとか、いろいろな場面で使われます。AtCoder ではよく出題されるので、すぐに思いつけるようにするためにも、周期性のアイデアを頭に入れておきましょう」.
- **Related problems (類題):** ABC 167-D 「Teleporter」, ABC 174-C 「Repsept」, ABC 179-E 「Sequence Sum」, ARC 113-B 「A^B^C」, ABC 175-D 「Moving Piece」.
- **Flags:** (1) The printed procedure is incomplete: it never assigns vis[x] = true (nor records the visit time), so as written the loop can never fire its break — the real algorithm needs the first-visit time of every state, then K ← (K − entry) mod period + entry. (2) 「2 周目に入ったと検知」 is loose: the first repeated state is the cycle entry, and the walk may have a tail before the cycle starts; a fixed point (such as 0, or anything with x + digit_sum(x) ≡ x) makes the period 1. (3) The stated O(N) silently conflates the initial value N (≤ 99999) with the number of steps: the walk length is bounded by the 10⁵ states, not by N, and the 10⁵ bound is never written on the slide. (4) 例 1's trace contradicts both the table and the drawn arrows: they give 6 → 2, 2 → 4, 4 → 8, 8 → 6, so the walk from 3 is 3 → 6 → 2 → 4 → 8 → 6 → …, whereas the slide prints 3 → 6 → 8 → 4 → 2 → 6 → … (the cycle read in the reverse direction). 例 2 agrees with the table. (5) The 0–9 table works only because digit_sum(x) = x ≤ 9, i.e. the map is 2x mod 10; the slide uses it purely as an analogy and never sketches why 10⁵ behaves the same way (it does, for the same finiteness reason). (6) Boundaries to test: N = 0 (0 + 0 = 0, a fixed point — the card's sample 2 is 0 100 → 0), K = 1 (the answer must be the state after one press, not the start), and the convention that the visit time of the start state is 0 — the off-by-one that decides between printing the state before or after the K-th press.

## Author's Reference Solution
`058.cpp` — Precomputes the next value `(x + digit_sum(x)) % 100000` for every state, walks from N recording the first visit time of each state until a state repeats, shrinks K using the cycle length, and prints the state whose visit time equals K.

```cpp
#include <vector>
#include <iostream>
using namespace std;
int digit_sum(int x) {
	int ans = 0;
	while (x > 0) {
		ans += x % 10;
		x /= 10;
	}
	return ans;
}
int main() {
	const int mod = 100000;
	int N; long long K;
	cin >> N >> K;
	vector<int> nxt(mod);
	for (int i = 0; i < mod; ++i) {
		nxt[i] = (i + digit_sum(i)) % mod;
	}
	vector<int> time_stamp(mod, -1);
	int pos = N, cnt = 0;
	while (time_stamp[pos] == -1) {
		time_stamp[pos] = cnt;
		pos = nxt[pos];
		++cnt;
	}
	int cycle = cnt - time_stamp[pos];
	if (K >= time_stamp[pos]) {
		K = (K - time_stamp[pos]) % cycle + time_stamp[pos];
	}
	int answer = -1;
	for (int i = 0; i < mod; ++i) {
		if (time_stamp[i] == K) {
			answer = i;
		}
	}
	cout << answer << endl;
	return 0;
}
```
