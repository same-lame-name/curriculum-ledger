# 046 — I Love 46 (Triples with Sum Divisible by 46)

**Difficulty:** ★×3 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_at
**Source:** AtCoder Typical90 #046 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
3つの長さ N の数列 A = (A[1], A[2], ..., A[N]), B = (B[1], B[2], ..., B[N]), C = (C[1], C[2], ..., C[N]) が与えられます。
A[i] + B[j] + C[k] が 46 の倍数となるような (i, j, k) (1 ≦ i,j,k ≦ N) の選び方の総数を出力してください。

【制約】
・1 ≦ N ≦ 10^5
・0 ≦ A[i],B[i],C[i] ≦ 10^9
・入力は全て整数
```

## Statement (English translation)
Three sequences A = (A[1], A[2], ..., A[N]), B = (B[1], B[2], ..., B[N]), C = (C[1], C[2], ..., C[N]) of length N are given.
Output the total number of ways to choose (i, j, k) (1 ≦ i, j, k ≦ N) such that A[i] + B[j] + C[k] is a multiple of 46.

## Constraints
```
【制約】
・1 ≦ N ≦ 10^5
・0 ≦ A[i], B[i], C[i] ≦ 10^9
・入力は全て整数
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 同じ意味のものをまとめて考える (group together the things that "mean the same")
- **Core idea:** A_i, B_j, C_k may be as large as 10^9, but only their residues mod 46 matter, because the residue of a sum depends only on the residues: A_i + B_j + C_k ≡ (A_i mod 46) + (B_j mod 46) + (C_k mod 46) (mod 46). Replacing every value by its residue collapses each sequence into 46 classes, so (x, y, z) has only 46^3 = 97336 possibilities and can be brute-forced. With a_x = #{i : A_i ≡ x} (and b_y, c_z likewise) the number of index triples realizing (x, y, z) is a_x × b_y × c_z, so the answer is the sum of a_x b_y c_z over x + y + z ≡ 0 (mod 46).
- **Editorial steps:**
  - **Step 1 (only the residue matters):** The two boxes on the slide: 「A_i + B_j + C_k を 46 で割った余り」＝「(A_i mod 46) + (B_j mod 46) + (C_k mod 46) を 46 で割った余り」. Example: if A_3 = 271, replacing A_3 by 41 (= 271 mod 46) does not change which (i, j, k) have a sum divisible by 46. Hence 「A_i, B_j, C_k をそれぞれ 46 で割った余りに変えることで、「同じ意味」のものをまとめて考えるようになります」. Footnote: 0, 46, 92, 138, … all mean the same thing; 1, 47, 93, 139, … the same; 2, 48, 94, 140, … the same; etc.
  - **Step 2 (the search space collapses):** After the replacement the values appearing in A_i, B_j, C_k are 0, 1, …, 45, i.e. 46 kinds, so the number of possible (A_i, B_j, C_k) triples is 46^3 = 97336, small enough for 全探索.
  - **Step 3 (count occurrences, then multiply):** Count a_x = #{i : A_i = x}, b_y = #{j : B_j = y}, c_z = #{k : C_k = z} (after the mod). The number of index triples with (A_i, B_j, C_k) = (x, y, z) is a_x × b_y × c_z, and the answer is the sum of these over all (x, y, z) whose sum is a multiple of 46.
- **Complexity:** Not stated on the slides as a bound — the slide argues only that 46^3 = 97336 triples is small enough to enumerate (one O(N) counting pass plus an O(46^3) triple loop). Memory: not stated on the slides.
- **Author's takeaway / typical pattern (典型):** 「値の種類数が少ないと、まとめて処理できたり、従来より高速に解ける場合があります」 — when the number of distinct values is small, group them. 「同じ意味のものをまとめて考えるのは、競プロにおいて有効な手段です。本問題のように 46 で割った余りに限らず、偶奇を問われる問題などでも重要なお考え方になります」 (parity is the same idea with mod 2).
- **Related problems (類題):** ABC 089-C「March」, ABC 200-C「Ringo's Favorite Number 2」, ABC 194-C「Squared Error」, AGC 023-A「Zero-Sum Ranges」, ABC 164-D「Multiple of 2019」
- **Flags:** (1) The slide's box writes the third term as (C_j mod 46); it should be (C_k mod 46) — a typo inside an otherwise correct identity. (2) The congruence is asserted without proof; the fact to check is that the residue of a sum depends only on the residues (and 0 ≤ A_i ≤ 10^9 includes the boundary A_i = 0, whose residue is 0). (3) a_x b_y c_z can be as large as (10^5)^3 = 10^15 over the whole 46^3 sum, so the accumulator must be 64-bit — never mentioned (the reference casts the first factor: `(long long)(am[i]) * bm[j] * cm[k]`). (4) The slide silently uses that indices are distinguishable — the answer counts (i, j, k) *triples*, not value triples — and the multiplication a_x b_y c_z is exactly the step where that is assumed; boundary: N = 1 and heavy duplication of values.

## Author's Reference Solution
`046.cpp`

```cpp
#include <vector>
#include <iostream>
using namespace std;
int main() {
	int N;
	cin >> N;
	vector<int> A(N), B(N), C(N);
	for (int i = 0; i < N; ++i) cin >> A[i];
	for (int i = 0; i < N; ++i) cin >> B[i];
	for (int i = 0; i < N; ++i) cin >> C[i];
	vector<int> am(46), bm(46), cm(46);
	for (int i = 0; i < N; ++i) {
		++am[A[i] % 46];
		++bm[B[i] % 46];
		++cm[C[i] % 46];
	}
	long long ans = 0;
	for (int i = 0; i < 46; ++i) {
		for (int j = 0; j < 46; ++j) {
			for (int k = 0; k < 46; ++k) {
				if ((i + j + k) % 46 == 0) {
					ans += (long long)(am[i]) * bm[j] * cm[k];
				}
			}
		}
	}
	cout << ans << endl;
	return 0;
}
```
