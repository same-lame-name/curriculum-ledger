# 075 — Magic For Balls (Splitting Balls into Primes)

**Difficulty:** ★×3 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_bw
**Source:** AtCoder Typical90 #075 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
整数 x が書かれたボールを叩くと、整数 a が書かれたボールと整数 b が書かれたボールの 2 つに分裂します。
整数 a, b は ab = x かつ a≧2, b≧2 を満たすものから自由に選ぶことができます。ただし、x が素数の場合はなにも起きません。

魔法を 1 回使うと、現在あるすべてのボールを叩くことができます。

はじめに、整数 N が書かれたボールが 1 個あります。
すべてのボールに書かれている数を素数にするためには、最小で何回の魔法を使う必要がありますか？
```

## Statement (English translation)
When you strike a ball with the integer x written on it, it splits into two balls, one with the integer a written on it and one with the integer b written on it.
The integers a, b may be chosen freely from those satisfying ab = x, a ≧ 2, b ≧ 2. However, if x is prime, nothing happens.

Using the magic once lets you strike all the balls that currently exist.

At first there is one ball with the integer N written on it.
What is the minimum number of times you need to use the magic in order to make the numbers written on all the balls prime?

## Constraints
```
《制約》
・2 ≦ N ≦ 10^12
・N は整数
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** O(√N) での素因数分解 (prime factorization in O(√N))
- **Core idea:** However the magics are ordered, the pieces left at the end are the prime factors of N with multiplicity, so their number K = Ω(N) is fixed — for `N = 120 = 2×2×2×3×5` the multiset `(2,2,2,3,5)` always remains. One magic strikes every ball at once and each strike splits a ball into at most 2, so x magics yield at most `2^x` pieces; the answer is the smallest x with `2^x ≧ K`. Computing K needs only trial division up to √N.
- **Editorial steps:**
  - **Step 1 (the leaves are forced):** start with the case `N = 120 = 2×2×2×3×5`. No matter how the magic is used, what finally remains is `(2,2,2,3,5)`. Two different split trees are drawn: `120 → 10, 12 → {2,5}, {3,4} → 2,5,3,2,2`, and `120 → 3, 40 → 3, {10,4} → 3, {5,2}, {2,2}`; both leave the same five primes.
  - **Step 2 (general K, and the log bound):** in general, if `N = p_1 × p_2 × … × p_K` is written as a product of primes, then in the end `(p_1, p_2, …, p_K)` — K pieces — remain. Now count how fast the piece count can grow (the slide's bullets speak of 切断, the cuts in the split tree): 1 cut splits into 2 pieces, 2 cuts into 4 pieces, 3 cuts into 8 pieces (「以下略」). Hence the minimum number of operations is the smallest x satisfying `2^x ≧ K`.
  - **Step 3 (factorize by trial division):** how should one decompose N into a product of primes? It suffices to trial-divide by every integer up to `B`, the largest integer not exceeding √N. For `N = 44`, `B = 6`, and the slide's list is: `i = 2`: 44 is divisible twice (`44 ÷ 2 ÷ 2 = 11`); `i = 3`: 11 is not divisible by 3; `i = 4`: not divisible by 4; `i = 5`: not divisible by 5; `i = 6`: not divisible by 6. Hence `44 = 2 × 2 × 11`. Justification: a composite M is always divisible by some integer between 2 and √M, so the remaining integer is always 1 or prime. The slide's C++ excerpt: `long long rem = N; vector<long long> p; for (long long i = 2; i*i <= N; i++) { while (rem % i == 0) { rem /= i; p.push_back(i); } } if (rem != 1LL) p.push_back(rem);`
- **Complexity:** O(√N) (「全体計算量 O(√N) でこの問題を解くことができました」). The right column adds that primality testing and divisor enumeration can also be done in O(√N) by a similar method. Memory not stated on the slide.
- **Author's takeaway / typical pattern (典型):** fast prime factorization is the whole problem; O(√N) trial division is the standard tool, and the same shape gives O(√N) primality tests and divisor enumeration — 「頻出なので理解しておくようにしましょう」.
- **Related problems (類題):** ABC149-C「Next Prime」, ABC180-C「Cream Puff」, ABC144-C「Walk on Multiplication Table」, ABC084-D「2017-like Number」
- **Flags:** (1) The invariance is asserted, not proved: the slide says any magic order leaves `(2,2,2,3,5)` and, in general, `(p_1,…,p_K)`, but never argues it (it needs "a split replaces x by a·b with ab = x, so the multiset of prime factors with multiplicity is unchanged", plus uniqueness of factorization). (2) `2^x ≧ K` is derived from an upper bound on the number of pieces only; that the bound is attainable (i.e. that one can always keep splitting every non-prime ball so that no branch is idle) is not argued. Boundary: `K = 1` (N prime, e.g. `N = 53`) must give 0, not 1 — the sample confirms 0. (3) K counts prime factors *with multiplicity* — the 120 example counts 2 three times — while the answer from the number of *distinct* primes would differ; the slide never says "with multiplicity" explicitly. (4) The slide's own example contains a typo: it writes 「残った整数は 44 であるため、44 = 2 × 2 × 11」 although after dividing out 2 twice the remainder is 11. (5) Cosmetic: the product is printed as `p_1 × p_2 × p_3 × … × p_N` while the tuple one line later is `(p_1, p_2, …, p_K)`. (6) The code's loop guard is `i*i <= N` (the original N) while the prose justifies the bound with √(the remaining value); both work here, but `N = p·q` with p, q near 10^6 is exactly where the distinction matters.

## Author's Reference Solution
`075.cpp` — Collects the prime factors of N by trial division, then prints the smallest i such that 2^i is at least the number of collected factors.

```cpp
#include <iostream>
#include <vector>
using namespace std;

vector<long long> prime_factors(long long N) {
	long long rem = N;
	vector<long long> p;
	for (long long i = 2; i * i <= N; i++) {
		while (rem % i == 0) {
			rem /= i;
			p.push_back(i);
		}
	}
	if (rem != 1LL) p.push_back(rem);
	return p;
}

int main() {
	// Step #1. Input
	long long N;
	cin >> N;
	
	// Step #2. Get Answer
	int Answer = 0;
	vector<long long> vec = prime_factors(N);
	for (int i = 0; i <= 20; i++) {
		if ((1 << i) >= (int)vec.size()) { Answer = i; break; }
	}
	cout << Answer << endl;
	return 0;
}
```
