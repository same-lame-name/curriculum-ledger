# 035 — Preserve Connectivity (Minimum Edges Keeping a Query Set Connected)

**Difficulty:** ★×7 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_ai
**Source:** AtCoder Typical90 #035 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
N 頂点の木があり、頂点には 1, 2, ..., N と番号付けられています。
i (1 ≦ i ≦ N-1) 番目の辺は、頂点 A[i] と B[i] を結んでいます。

以下の形式の質問が Q 個与えられるので、順に答えてください。
j (1 ≦ j ≦ Q) 番目の質問は次のようになります：
・頂点 V[j][1], V[j][2], ..., V[j][K[j]] すべてが互いに連結になるようにしたい。
・N - 1 本の辺のうち、最小で何本の辺を残す必要があるか？

## Statement (English translation)
There is a tree with N vertices, and the vertices are numbered 1, 2, ..., N.
The i-th edge (1 ≦ i ≦ N-1) connects vertex A[i] and vertex B[i].

Q questions of the following form are given, so answer them in order.
The j-th question (1 ≦ j ≦ Q) is as follows:
・We want all of vertices V[j][1], V[j][2], ..., V[j][K[j]] to be connected to each other.
・Among the N - 1 edges, what is the minimum number of edges that need to be kept?

**Subtasks (小課題)**
1. (2 points) N, Q ≦ 5000
2. (1 point) K[i] = 2
3. (1 point) K[i] = 3
4. (3 points) No additional constraints

## Constraints
【制約】
・2 ≦ N ≦ 100000
・1 ≦ A[i] < B[i] ≦ N
・1 ≦ Q ≦ 100000
・2 ≦ K[j] ≦ N
・1 ≦ V[j][1] < V[j][2] < ... < V[j][K[j]] ≦ N
・K[1] + K[2] + ... + K[Q] ≦ 200000
・与えられるグラフは木である
・入力はすべて整数


【小課題】
1. (2 点) N, Q ≦ 5000
2. (1 点) K[i] = 2
3. (1 点) K[i] = 3
4. (3 点) 追加の制約はない

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** P1「木 DP をしよう」(let's do tree DP). P2「木の経路の長さは LCA」(the length of a path in a tree is given by its LCA). P3「木の"座標圧縮"を O(K log N) で」(the tree's "coordinate compression" in O(K log N)).
- **Core idea:** An edge must be kept exactly when deleting it separates the query's chosen vertices into two non-empty parts, i.e. when the number of chosen vertices in the subtree below the edge is between 1 and K−1. Deciding that for every edge is one bottom-up tree DP per query (P1, O(QN)). For small K the answer collapses to path lengths: K = 2 is dist(V1,V2), K = 3 is (d12+d23+d31)/2, and in general it is half the length of the closed walk that visits the K chosen vertices in DFS order — every distance being computable with the LCA in O(log N) (P2, P3).
- **Editorial steps:**
  - **Step 1 (P1, 小課題 1, O(QN)) — when is an edge necessary?** If deleting an edge makes the chosen vertices no longer reach each other, that edge must be kept. In the figure the red edge is deleted and the chosen vertices fall into two groups of 2, so it must be kept: if the chosen vertices split into α and K − α, then 1 ≦ α ≦ K − 1 is exactly the condition "this edge must be kept". To decide it for all edges, root the tree at an arbitrary vertex and compute for every vertex how many of the chosen vertices lie in its subtree (footnote: the subtree of v = the set of vertices from which v can be reached by tracing upward). Computing this bottom-up aggregates all of it in O(N) per query, and the number of vertices whose value is between 1 and K − 1 is the answer to that query (the root always has K, so it never counts). This makes the whole problem O(QN). Computing bottom-up over a tree like this is the technique called 木 DP (tree DP), used often in competitive programming; a recursive function implements it concisely.
  - **Step 2 (P2, 典型 = 最近共通祖先 LCA, 小課題 2 and 3, O((N+Q) log N)) — doubling and LCA:**
    - ダブリング (doubling) prepares, for every vertex, its 1st, 2nd, 4th, …, 2^k-th ancestor par[k][v]. The table is filled by par[k+1][v] = par[k][par[k][v]] (the 2^(k+1)-th ancestor is the 2^k-th ancestor of the 2^k-th ancestor) in O(N log N).
    - With that table the d-th ancestor costs O(log d): the 37-th ancestor of v is the 1st ancestor of the 4th ancestor of the 32nd ancestor (37 = 32 + 4 + 1), read off the array par.
    - LCA(x, y) in O(log N): (1) equalize the depths of x and y using "the d-th ancestor"; (2) if x = y at that point then the LCA is x (= y); (3) otherwise, for k = log N, …, 2, 1, 0 in that order, if par[k][x] ≠ par[k][y] then replace x, y by par[k][x], par[k][y]; (4) the LCA is par[0][x] (= par[0][y]).
    - Path length: dist(x, y) = depth[x] + depth[y] − 2 × depth[LCA(x, y)], where depth[x] is the distance from the root and is precomputed in O(N).
    - 小課題 2 (K = 2): the answer is exactly dist(V1, V2). 小課題 3 (K = 3): the answer is (dist(V1,V2) + dist(V2,V3) + dist(V3,V1)) / 2. Each query costs O(log N), so the total is O((N + Q) log N). (Footnote ※1: LCA can also be obtained by combining "the d-th ancestor" with a binary search on the depth, but that costs O(log² N).)
  - **Step 3 (P3, full score, O((N + K1 + … + KQ) log N)) — the DFS tour, and the Auxiliary Tree:**
    - 小課題 3 answered by (length of the walk around the 3 vertices) ÷ 2. Generalize with the tour of the tree that traverses every edge twice, of length 2 × (N − 1): the walk that goes once around the tree, which can be produced in DFS order (the numbering in the figure).
    - The edges this problem keeps are "a part of that tour" (the red edges in the figure): once the DFS numbers are attached, the closed walk that goes 2 → 4 → 5 → 7 → 2 — i.e. visits the chosen vertices in increasing DFS-number order and returns — is precisely the set of edges that remain.
    - Procedure: (1) sort V1, V2, …, VK by DFS number; (2) the tour length is dist(V1,V2) + dist(V2,V3) + … + dist(VK,V1), and half of it is the number of edges that must be kept. Total O((N + K1 + K2 + … + KQ) log N).
    - The same slide generalizes this as the Auxiliary Tree (木の"座標圧縮"): choose vertices v1, …, vk and compress the tree without losing the positional relations among them. If the vertices are sorted in DFS order, the Auxiliary Tree contains only v1, v2, …, vk, LCA(v1,v2), LCA(v2,v3), …, LCA(v(k−1), vk), and this tree of at most 2k − 1 vertices can be built in O(k log N) with the LCA and a stack.
- **Complexity:** P1: O(QN) (小課題 1). P2: O((N + Q) log N) (小課題 2, 3). P3: O((N + K1 + K2 + … + KQ) log N) (満点). Memory not stated on the slides (the reference code keeps adjacency lists, a bits × N ancestor table and a depth array).
- **Author's takeaway / typical pattern (典型):** 木 DP for bottom-up aggregation on a tree; ダブリング for "the d-th ancestor" and the LCA; and the idea of extracting only the needed vertices from a tree (Auxiliary Tree = 木の"座標圧縮") which applies to many problems. The slide's closing point is that using the tour idea lets the problem be reduced to an LCA problem and thus solved fast.
- **Related problems (類題):** P1: ABC 026-C「高橋君の給料」, ABC 036-D「塗り絵」, ABC 138-D「Ki」, JOI2007 本選 5「最軽量のモビール」. P2: ABC 014-D「閉路」, AOJ 2677「BFS by Foxpower」, JOI 2010 春合宿「Highway」. P3: ABC 133-F「Colorful Tree」, 天下一プログラマーコンテスト 2015 本戦 問題F「根付き木のみさわさん」, GigaCode 2019 問題G「ギギ国の道路事情」.
- **Flags:** (1) Step 1's "1 ≦ α ≦ K−1 ⇒ the edge must be kept" is argued only from one figure; the converse direction (a kept edge always splits the chosen vertices nontrivially) is not written out. (2) 小課題 3's formula (d12 + d23 + d31)/2 is asserted with no proof, and so is dist(x,y) = depth[x] + depth[y] − 2·depth[LCA]. (3) Step 3's central claim — that half of the DFS-order closed walk equals the number of kept edges — is only illustrated by 2 → 4 → 5 → 7 → 2; both the "÷2" and the need for DFS order need justification. (4) The Auxiliary Tree is described only by its vertex set (構築は「LCA とスタックなどを使って」); the construction and the 2k − 1 bound are not shown. (5) Boundary: K = 2 (the statement's minimum) makes the Step 3 walk V1 → V2 → V1, so the formula degenerates to dist(V1,V2) and agrees with 小課題 2 — the slide never checks the two formulas agree. (6) Slide-vs-code difference: the slide's condition is 1 ≦ (subtree count) ≦ K−1, while `035-01.cpp` only tests c[v] ≠ 0 for v ≠ sel[0]; the two agree only because sel[0] is the root, so no other vertex's subtree can contain all K chosen vertices.

## Author's Reference Solution
`035-01.cpp` — For each query, one DFS from the first selected vertex marks the vertices whose subtree contains a selected vertex and counts them.

```cpp
#include <vector>
#include <iostream>
#include <algorithm>
#include <functional>
using namespace std;
int main() {
	cin.tie(0);
	ios_base::sync_with_stdio(false);
	int N;
	cin >> N;
	vector<vector<int> > G(N);
	for (int i = 0; i < N - 1; ++i) {
		int A, B;
		cin >> A >> B; --A, --B;
		G[A].push_back(B);
		G[B].push_back(A);
	}
	int Q;
	cin >> Q;
	for (int i = 0; i < Q; ++i) {
		int verts;
		cin >> verts;
		vector<int> sel(verts);
		for (int j = 0; j < verts; ++j) {
			cin >> sel[j]; --sel[j];
		}
		vector<int> c(N);
		for (int j = 0; j < verts; ++j) {
			++c[sel[j]];
		}
		function<void(int, int)> tree_dp = [&](int pos, int pre) {
			for (int i : G[pos]) {
				if (i == pre) continue;
				tree_dp(i, pos);
				c[pos] += c[i];
			}
		};
		tree_dp(sel[0], -1);
		int need = 0;
		for (int i = 0; i < N; ++i) {
			if (i != sel[0] && c[i] != 0) {
				++need;
			}
		}
		cout << need << '\n';
	}
	return 0;
}
```

`035-02.cpp` — Builds a binary-lifting LCA table and answers only the queries with K = 2 from the two depths and the LCA.

```cpp
#include <vector>
#include <iostream>
#include <algorithm>
#include <functional>
using namespace std;
int main() {
	cin.tie(0);
	ios_base::sync_with_stdio(false);
	int N;
	cin >> N;
	vector<vector<int> > G(N);
	for (int i = 0; i < N - 1; ++i) {
		int A, B;
		cin >> A >> B; --A, --B;
		G[A].push_back(B);
		G[B].push_back(A);
	}
	int bits = 0;
	while ((1 << bits) < N) ++bits;
	vector<vector<int> > par(bits, vector<int>(N));
	vector<int> depth(N);
	function<void(int, int)> build_tree = [&](int pos, int pre) {
		par[0][pos] = pre;
		for (int i : G[pos]) {
			if (i == pre) continue;
			depth[i] = depth[pos] + 1;
			build_tree(i, pos);
		}
	};
	build_tree(0, 0);
	for (int i = 1; i < bits; ++i) {
		for (int j = 0; j < N; ++j) {
			par[i][j] = par[i - 1][par[i - 1][j]];
		}
	}
	function<int(int, int)> lca = [&](int va, int vb) {
		if (depth[va] < depth[vb]) swap(va, vb);
		for (int i = bits - 1; i >= 0; --i) {
			if (depth[va] - depth[vb] >= (1 << i)) {
				va = par[i][va];
			}
		}
		if (va == vb) return va;
		for (int i = bits - 1; i >= 0; --i) {
			if (par[i][va] != par[i][vb]) {
				va = par[i][va];
				vb = par[i][vb];
			}
		}
		return par[0][va];
	};
	int Q;
	cin >> Q;
	for (int i = 0; i < Q; ++i) {
		int verts;
		cin >> verts;
		if (verts == 2) {
			int va, vb;
			cin >> va >> vb; --va, --vb;
			cout << depth[va] + depth[vb] - 2 * depth[lca(va, vb)] << '\n';
		}
	}
	return 0;
}
```

`035-04.cpp` — Sorts each query's vertices by DFS entry time and sums depth[v] - depth[lca(v, next v)] along the cyclic order.

```cpp
#include <vector>
#include <iostream>
#include <algorithm>
#include <functional>
using namespace std;
int main() {
	cin.tie(0);
	ios_base::sync_with_stdio(false);
	int N;
	cin >> N;
	vector<vector<int> > G(N);
	for (int i = 0; i < N - 1; ++i) {
		int A, B;
		cin >> A >> B; --A, --B;
		G[A].push_back(B);
		G[B].push_back(A);
	}
	int bits = 0;
	while ((1 << bits) < N) ++bits;
	vector<vector<int> > par(bits, vector<int>(N));
	vector<int> depth(N), id(N);
	int vert_id = 0;
	function<void(int, int)> build_tree = [&](int pos, int pre) {
		par[0][pos] = pre;
		id[pos] = vert_id++;
		for (int i : G[pos]) {
			if (i == pre) continue;
			depth[i] = depth[pos] + 1;
			build_tree(i, pos);
		}
	};
	build_tree(0, 0);
	for (int i = 1; i < bits; ++i) {
		for (int j = 0; j < N; ++j) {
			par[i][j] = par[i - 1][par[i - 1][j]];
		}
	}
	function<int(int, int)> lca = [&](int va, int vb) {
		if (depth[va] < depth[vb]) swap(va, vb);
		for (int i = bits - 1; i >= 0; --i) {
			if (depth[va] - depth[vb] >= (1 << i)) {
				va = par[i][va];
			}
		}
		if (va == vb) return va;
		for (int i = bits - 1; i >= 0; --i) {
			if (par[i][va] != par[i][vb]) {
				va = par[i][va];
				vb = par[i][vb];
			}
		}
		return par[0][va];
	};
	int Q;
	cin >> Q;
	for (int i = 0; i < Q; ++i) {
		int verts;
		cin >> verts;
		vector<int> sel(verts);
		for (int j = 0; j < verts; ++j) {
			cin >> sel[j];
			--sel[j];
		}
		sort(sel.begin(), sel.end(), [&](int va, int vb) {
			return id[va] < id[vb];
			});
		int answer = 0;
		for (int j = 0; j < verts; ++j) {
			answer += depth[sel[j]];
			answer -= depth[lca(sel[j], sel[(j + 1) % verts])];
		}
		cout << answer << '\n';
	}
	return 0;
}
```
