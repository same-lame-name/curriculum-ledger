# 085 — Counting Triples (a, b, c) with a·b·c = K and a ≤ b ≤ c

**Difficulty:** ★×4 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_cg
**Source:** AtCoder Typical90 #085 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
正の整数 K が与えられます。
abc = K を満たす正の整数 (a, b, c) (a ≦ b ≦ c) の組がいくつあるかを求めてください。

## Statement (English translation)
A positive integer K is given.
Find the number of triples of positive integers (a, b, c) with a ≦ b ≦ c such that a·b·c = K.

## Constraints
・1 ≦ K ≦ 10^12

## Samples

# 出力例 1

# 入力例 2

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 約数の個数は少ない (P1) ／ 工夫した全探索／約数列挙の復習 (P2)
- **Core idea:** Every one of a, b, c must be a divisor of K, and K has very few divisors (at most 6720 for K ≤ 10^12). Enumerating all divisor triples is still too slow (≈ d(K)³/6 ≈ 5×10^10), but once a and b are fixed, c = K/(a·b) is uniquely determined, so only divisor pairs (a, b) with a ≤ b must be enumerated — about d(K)²/2 ≈ 2×10^7.
- **Editorial steps:**
  - **ステップ1:** 最初に思いつく解法として「(a, b, c) の組合せを全パターン試す方法」が考えられます。しかし、残念ながら K ≦ 10^12 と制約が大きく、この解法だと実行時間制限超過 (TLE) してしまいます。
  - ではどうすれば良いのでしょうか。実は以下の性質が成り立ちます：「a, b, c は必ず K の約数である」。
  - この性質を使って、K = 9 の場合を解いてみましょう。元々の解法では 1 ≦ a ≦ b ≦ c ≦ 9 を満たす全ての組 (a, b, c) について全探索していたので、全部で 165 通りのパターンを調べていました。一方、上の性質を使うと a, b, c ∈ {1,3,9} だと分かるため、調べるパターンは (a,b,c) = (1,1,1), (1,1,3), (1,1,9), (1,3,3), (1,3,9), (1,9,9), (3,3,3), (3,3,9), (3,9,9), (9,9,9) のみです。全部で 10 通りしかないのです。
  - 次に一般の場合について考える。K の約数の個数を d(K) とするとき、調べるパターンの数は d(K)³/6 回程度になります (典型055)。d(K) の最大値について、以下が知られています：10^6 以下の場合 K=720720 で最大 d(K)=240、10^9 以下の場合 K=735134400 で最大 d(K)=1344、10^12 以下の場合 K=963761198400 で最大 d(K)=6720。
  - K ≦ 10^12 の制約で 10000 個以内に収まり、約数の個数は K に比べて非常に少ないことが分かります。しかし、085-01.cpp のような候補を約数に絞ったうえで全探索しても、なお TLE になってしまいます。なぜなら 6720³/6 ≈ 5×10^10 であるのに対し、コンピュータは 1 秒に 10^8 〜 10^9 回程度しか計算できないからです。なんと、計算量 O(d(K)³) では間に合わないのです。
  - **ステップ2:** 次に、典型016 と同じ要領で全探索を工夫してみましょう。実は a, b の値が決まれば c = K ÷ (a × b) と一意に定まるので、(a, b) の組だけを全探索すれば良いです（c が整数にならない場合、a ≦ b ≦ c を満たさない場合は答えにカウントしないことに注意してください）。
  - そこで、K の約数の個数は高々 6720 個であるため、計算回数はおよそ 6720² ÷ 2 ≈ 2×10^7 回となり、AC を出すことができます。
  - 実装にあたっての注意：① 約数列挙を計算量 O(√K) の実装で行う (典型075)。計算量 O(K) の愚直な方法の場合、これだけで TLE してしまう。② オーバーフローに注意して実装する (典型038)。実際、K ÷ (a×b) を計算する際の a×b の値は最大 10^24 となる。
- **Complexity:** O(√K + d(K)²)
- **Author's takeaway / typical pattern (典型):** 「約数の個数は少ない」のように、ざっくり何通りを見積もるスキルは、競技プログラミングで重要です (典型072)。(a, b) が決まれば c も決まる性質を生かして全探索を工夫すると、全体計算量 O(√K + d(K)²) で本問題を解くことができます。工夫した全探索とその類題については「典型016」の解説を、計算量 O(√K) での約数列挙や素因数分解とその類題については「典型075」の解説を参照。

## Author's Reference Solution
`085.cpp` — Enumerate all divisors of K in O(√K), sort them, then double-loop over divisor pairs (a, b) with a ≤ b, checking K % (a·b) == 0 and deriving c = K/(a·b), counting when b ≤ c.

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
	// Step #1. Input
	long long K;
	cin >> K;

	// Step #2. Enumerate Divisors
	vector<long long> vec;
	for (long long i = 1; i * i <= K; i++) {
		if (K % i != 0LL) continue;
		vec.push_back(i);
		if (i != K / i) vec.push_back(K / i);
	}
	sort(vec.begin(), vec.end());

	// Step #3. Brute Force
	long long Answer = 0;
	for (int i = 0; i < vec.size(); i++) {
		for (int j = i; j < vec.size(); j++) {
			long long a = vec[i], b = vec[j], c = 0;
			if ((K / a) < b) continue;
			if (K % (a * b) != 0LL) continue;
			c = K / (vec[i] * vec[j]);
			if (b <= c) Answer += 1;
		}
	}

	// Step #4. Output
	cout << Answer << endl;
	return 0;
}
```
