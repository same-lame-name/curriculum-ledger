## Statement (English translation)
There is an integer sequence A = (A[1], A[2], ..., A[N]) of length N. At first, you know nothing about this integer sequence.
Q pieces of information and questions about the integer sequence A (together called events) are given. The i-th event from the beginning (1 ≦ i ≦ Q) is represented by a quadruple of integers (T[i], X[i], Y[i], V[i]), and it is as follows.

《Information | when T[i] = 0》
The information A[X[i]] + A[Y[i]] = V[i] is given. (Here, X[i] + 1 = Y[i] always holds.)

《Question | when T[i] = 1》
Assuming A[X[i]] = V[i], what is the value of A[Y[i]]?

Process the events in order and answer each question. However, when A[Y[i]] is not determined uniquely at the time of the question, output "Ambiguous" instead.

## Constraints
```
【制約】
・1 ≦ N ≦ 10^5
・1 ≦ Q ≦ 10^5
・T[i] = 0 もしくは T[i] = 1
・1 ≦ X[i], Y[i] ≦ N
・T[i] = 0 のとき、X[i] + 1 = Y[i]
・0 ≦ V[i] ≦ 2×10^9
・矛盾する入力は与えられない
・入力はすべて整数
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** クエリ先読み / std::set (pre-reading queries / std::set)
- **Core idea:** Treat each T=0 information as an edge between positions x and x+1. Then A_Y is determined by A_X exactly when X and Y lie in the same connected component of the relations known so far; otherwise the answer is "Ambiguous". Union-Find tests connectivity, and because a connected chain determines every value from one value with alternating signs, pre-reading all T=0 relations lets one compute a reference pattern per component and recover A_Y by a ± difference.
- **Editorial steps:**
  - **Step 1 (when the answer is determined):** For X < Y, if all relations 「A_X と A_{X+1}」, 「A_{X+1} と A_{X+2}」, …, 「A_{Y−1} と A_Y」 are known, propagating from A_X along the chain gives A_Y uniquely; the case X > Y is symmetric. Otherwise the answer is not unique and the output is "Ambiguous" (the slide's figure shows the chain split into separate components). Union-Find (▶典型 012) decides this quickly: on T=0 add an edge between vertices x and x+1 (the relation discovered is between A_x and A_{x+1}); on T=1 test whether vertices x and y are currently connected.
  - **Step 2 (the std::set alternative):** Initially put S = {1, 2, …, N−1}. On T=0 erase x from S; on T=1 use `S.lower_bound()` to test whether any element ≤ Y−1 remains (for the X < Y orientation) — if none remains, all relations on the chain X..Y are known and the value is determined.
  - **Step 3 (monotonicity — why pre-reading is legal):** Once the answer is no longer "Ambiguous", it has become uniquely determined, so newly discovered relations cannot change it. Therefore it is allowed to pre-read all T=0 queries, then answer T=1 using the full set of relations.
  - **Step 4 (recovering the value — two patterns and the ±1 alternation):** Suppose the relations A_1A_2, …, A_{N−1}A_N are all known. Raising A_1 by 1 changes alternating entries by +1 and −1 (from A_i + A_{i+1} = V_i). The slide's trace with V = (5,7,6,7,9) shows the pattern for A_1 = 0 as (0,5,2,4,3,6), for A_1 = 1 as (1,4,3,3,4,5), for A_1 = 2 as (2,3,4,2,5,4). Worked instance on the slide: if A_2 = 0, then the top pattern differs from it by 5, so A_5 = 3 + 5 = 8 and A_6 = 6 − 5 = 1. Therefore, after processing all T=0 queries, examine two patterns per connected component and take the difference (e.g. for one fully connected component compare the patterns with A_1 = 0 and A_1 = 1).
- **Complexity:** O(N + Q·α(N)) with Union-Find (「全体計算量 O(N + Q·α(N))」). The complexity of the std::set variant is not stated on the slide; memory is not stated on the slides either.
- **Author's takeaway / typical pattern (典型):** クエリ先読み (offline query processing) is versatile: besides processing one query type first as here, it can mean processing in increasing order of a parameter such as L_i, and it applies to tree and graph problems as well.
- **Related problems (類題):** ABC128-E 「Roadwork」 (クエリ先読み), ABC202-E 「Count Descendant」 (クエリ先読み), PAST 第1回 K 問題 「巨大企業」 (クエリ先読み), ABC203-E 「White Pawn」 (std::set).
- **Flags:** (1) The monotonicity claim 「一度 "Ambiguous" でなくなったら、新たな関係性が判明しても答えは変わらない」 is asserted without proof; the missing argument is that a uniquely determined value cannot be contradicted because the input is guaranteed non-contradictory. (2) Step 4 never writes the formula, only the ±1 pattern and one worked difference. The sign depends on the parity of the distance between the reference and the queried index: with p[i] the pattern having the component's first value 0, A_Y = V + (p[Y] − p[X]) when X, Y have the same parity and A_Y = (p[X] + p[Y]) − V otherwise (what `068a.cpp` implements) — the reader must derive this. (3) The std::set check is stated only for the X < Y orientation (「x より Y−1 以下の要素」); the X > Y case is left implicit. (4) The std::set variant's complexity is not given. (5) The numeric trace assumes the whole segment is connected; the slide never shows a multi-component example with the two patterns, which is exactly the case that needs the per-component reference.

## Author's Reference Solution
- `068a.cpp` — Keeps the known adjacent sums in prefix form and a union-find over positions, printing "Ambiguous" whenever the two queried positions are not yet connected.
- `068b.cpp` — Keeps the known adjacent sums in alternating prefix form plus a set of the positions whose sum is already known, and answers each query by testing whether a known position lies in between.

```cpp
#include <vector>
#include <iostream>
using namespace std;
class union_find {
private:
	int N;
	vector<int> par;
public:
	union_find() : N(0), par() {}
	union_find(int N_) : N(N_) {
		par.resize(N);
		for (int i = 0; i < N; ++i) {
			par[i] = i;
		}
	}
	int root(int x) {
		if (x == par[x]) return x;
		return par[x] = root(par[x]);
	}
	void link(int x, int y) {
		par[root(x)] = root(y);
	}
	bool connected(int x, int y) {
		return root(x) == root(y);
	}
};
int main() {
	int N, Q;
	cin >> N >> Q;
	vector<int> T(Q), X(Q), Y(Q), V(Q);
	for (int i = 0; i < Q; ++i) {
		cin >> T[i] >> X[i] >> Y[i] >> V[i];
		--X[i], --Y[i];
	}
	vector<int> sum(N - 1, 0);
	for (int i = 0; i < Q; ++i) {
		if (T[i] == 0) {
			sum[X[i]] = V[i];
		}
	}
	vector<long long> potential(N, 0);
	for (int i = 0; i < N - 1; ++i) {
		potential[i + 1] = sum[i] - potential[i];
	}
	union_find uf(N);
	for (int i = 0; i < Q; ++i) {
		if (T[i] == 0) {
			uf.link(X[i], Y[i]);
		}
		if (T[i] == 1) {
			if (!uf.connected(X[i], Y[i])) {
				cout << "Ambiguous" << endl;
			}
			else if ((X[i] + Y[i]) % 2 == 0) {
				cout << V[i] + (potential[Y[i]] - potential[X[i]]) << endl;
			}
			else {
				cout << (potential[X[i]] + potential[Y[i]]) - V[i] << endl;
			}
		}
	}
	return 0;
}
```

```cpp
#include <set>
#include <vector>
#include <iostream>
#include <algorithm>
using namespace std;
int main() {
	int N, Q;
	cin >> N >> Q;
	vector<int> T(Q), X(Q), Y(Q), V(Q);
	for (int i = 0; i < Q; ++i) {
		cin >> T[i] >> X[i] >> Y[i] >> V[i];
		--X[i], --Y[i];
	}
	vector<int> sum(N - 1, 0);
	for (int i = 0; i < Q; ++i) {
		if (T[i] == 0) {
			sum[X[i]] = V[i];
		}
	}
	vector<long long> pot(N, 0);
	for (int i = 0; i < N - 1; ++i) {
		pot[i + 1] = sum[i] - pot[i];
	}
	set<int> s;
	for (int i = -1; i < N; ++i) {
		s.insert(i);
	}
	for (int i = 0; i < Q; ++i) {
		if (T[i] == 0) {
			s.erase(X[i]);
		}
		else {
			int p = min(X[i], Y[i]), q = max(X[i], Y[i]);
			set<int>::iterator it = s.lower_bound(p);
			if (*it > q - 1) {
				cout << ((q - p) % 2 == 0 ? pot[Y[i]] + (V[i] - pot[X[i]]) : pot[Y[i]] - (V[i] - pot[X[i]])) << endl;
			}
			else {
				cout << "Ambiguous" << endl;
			}
		}
	}
	return 0;
}
```
