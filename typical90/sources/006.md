# 006 — Smallest Subsequence (Greedy over Next Occurrences)

**Difficulty:** ★×5 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_f
**Source:** AtCoder Typical90 #006 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
英小文字からなる文字列 S が与えられます。
S の部分文字列の中で K 文字のもののうち、辞書順で最も早いものを出力してください。
ただし、部分文字列は連続しなくても良いものとします。
```

## Statement (English translation)
A string S consisting of lowercase English letters is given.
Among the subsequences of S that consist of K characters, output the lexicographically smallest one.
Here, a subsequence does not have to be contiguous.

## Constraints
```
【制約】
・1 ≦ K ≦ |S| ≦ 10^5
・K は整数
・S は英小文字からなる
※文字列 S の長さを |S| とします
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 辞書順最小は前から貪欲法 (lexicographically smallest ⇒ greedy from the front)
- **Core idea:** A string whose 1st character is 'b' can never beat a string whose 1st character is 'a', no matter how early its remaining characters are. So the lexicographically smallest length-K subsequence is built left to right: at each position append the smallest character ch that can still be extended to K characters. "Can be extended" means that taking everything from the leftmost occurrence of ch after the previously chosen position yields at least K characters in total. Precomputing the next-occurrence table c[i][j] makes each greedy step O(1), for O(|S|L) overall (L = alphabet size, 26).
- **Editorial steps:**
  - **Step 1 (characterise the optimum):** Intuitively, a string starting with 'b' loses to one starting with 'a' however early the rest is, so the lexicographically smallest string satisfies: ① among all strings that can be made, the 1st character is the earliest (closest to 'a'); ② among those satisfying ①, the 2nd character is the earliest; ③ among those satisfying ②, the 3rd character is the earliest; … [以下略 — and so on]. Hence repeatedly appending 「次の文字に置けるものとして最も早い文字 ch」 greedily yields the answer. The placement condition (in red on the slide) is: 「前選んだ文字の右にある文字 ch の中で最左のもの以降全部選んで K 文字以上になること」 — take the leftmost ch after the previously chosen character and count all characters from there onward; that count must be ≥ K.
  - **Step 1 numeric example:** S = "bacbcba", K = 3, with 'a' chosen as the 1st character (the 'a' at position 2). If the trailing 'a' (position 7) is chosen as the 2nd character, only 2 characters in total can be achieved; but if 'b' is chosen (position 4), 5 characters in total can be achieved ("bacbcba"), so the best 2nd character is 'b'.
  - **Step 2 (why the naive greedy TLEs):** Finding 「前選んだ文字の右にある文字 c の中で最左のもの」 by brute force costs O(|S|), and since the final string has K characters the total is O(|S|K) → TLE.
  - **Step 3 (precompute next occurrences in O(|S|)):** To get the blue part in O(1), precompute the array c[i][j] = the index (which character position) of the leftmost occurrence of character j at or after the i-th character. It is computed cumulatively from the back in O(|S|) (※). Worked table for S = "bacbcba", columns 1/b 2/a 3/c 4/b 5/c 6/b 7/a — row 文字 a: 2, 2, 7, 7, 7, 7, 7; row 文字 b: 1, 4, 4, 4, 6, 6, −; row 文字 c: 3, 3, 3, 5, 5, −, −. (Entry (i, j) is "at or after i", not strictly after, as row b column 1 = 1 shows.)
  - **Step 4 (the greedy loop):** For each of the K output positions, scan characters j from 'a' upward, take NexPos = c[CurrentPos][j], and accept the first j for which the maximum achievable length, (|S| − NexPos − 1) + i, is ≥ K; then advance CurrentPos = NexPos + 1. This is the reference code's Step #3.
- **Complexity:** Naive greedy O(|S|K) → TLE; with the precomputed table, O(|S|L) where L is the number of distinct characters — 「L = 26 程度なので高速に実行できます」. (Footnote alternative: writing a = 0, b = 1, …, z = 25 and using an indexed RMQ also solves it in O(|S| log |S|).) Memory not stated on the slide; the reference code uses nex[100009][26].
- **Author's takeaway / typical pattern (典型):** When you want the lexicographically smallest object, very often the answer is determined by deciding greedily from the front (「辞書順で最小のものを求めたい場合、前から貪欲に決めていくことで答えが分かる場合が非常に多いです」); the recurring companion technique is the O(1) feasibility test supplied by precomputation.
- **Related problems (類題):** ABC076-C Dubious Document 2, ABC009-C 辞書式順序ふたたび, JOI2021-春合宿 Event Hopping 2
- **Flags:** The optimality argument stops at the 1st-character observation plus 「[以下略]」; the induction/exchange step — that fixing the earliest *feasible* character never makes later positions worse — is skipped, and the feasibility test is exactly where an off-by-one would break it (the count must include ch itself and the characters already fixed). The slide's own example is compressed: 「'b' を選ぶと合計文字数 5 文字」 counts the 2 already-fixed characters plus the 3 characters after the chosen 'b' at position 4, not a contiguous block of the original S.

## Author's Reference Solution
`006.cpp` — Precomputes `nex[i][c]`, the first position of character `c` at or after `i`, then builds the answer character by character, choosing the smallest `c` for which enough characters remain to reach length K.

```cpp
#include <iostream>
using namespace std;

string S;
int N,K;
int nex[100009][26];

int main() {
	// Step #1. 入力
	cin >> N >> K;
	cin >> S;

	// Step #2. 前計算
	for (int i = 0; i < 26; i++) nex[S.size()][i] = S.size();
	for (int i = (int)S.size() - 1; i >= 0; i--) {
		for (int j = 0; j < 26; j++) {
			if ((int)(S[i] - 'a') == j) {
				nex[i][j] = i;
			}
			else {
				nex[i][j] = nex[i + 1][j];
			}
		}
	}

	// Step #3. 一文字ずつ貪欲に決める
	string Answer = "";
	int CurrentPos = 0;
	for (int i = 1; i <= K; i++) {
		for (int j = 0; j < 26; j++) {
			int NexPos = nex[CurrentPos][j];
			int MaxPossibleLength = (int)(S.size() - NexPos - 1) + i;
			if (MaxPossibleLength >= K) {
				Answer += (char)('a' + j);
				CurrentPos = NexPos + 1;
				break;
			}
		}
	}

	// Step #4. 出力
	cout << Answer << endl;
	return 0;
}
```

> DATA NOTE: The reference code reads an extra `N` before `S` (`cin >> N >> K`), while the stated input is `S` then `K`; the code is kept verbatim and the statement is authoritative.
