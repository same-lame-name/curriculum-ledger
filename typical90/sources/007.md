# 007 — CP Classes (Binary Search on Sorted Ratings)

**Difficulty:** ★×3 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_g
**Source:** AtCoder Typical90 #007 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
ABC 競技プログラミング塾には N 個のクラスがあり、番号 i のクラスはレーティング A[i] の生徒を対象としています。
今、Q 人の生徒が入塾しようとしています。番号 j の生徒のレーティングは B[j] です。各生徒は自分に合わないレベルのクラスに行くと不満なので、不満度は次のように定義されます。
・対象レーティング X と自分のレーティング Y の差の絶対値、すなわち |X-Y|
j = 1, 2, 3,..., Q それぞれについて、番号 j の生徒の不満度として考えられる最小値を求めてください。
ただし 1 人もいないクラス、複数人から成るクラスがあっても良いものとします。
```

## Statement (English translation)
The ABC Competitive Programming School has N classes, and the class numbered i targets students with rating A[i].
Now, Q students are about to join the school. The rating of the student numbered j is B[j]. Each student is dissatisfied when they go to a class at a level that does not suit them, so the dissatisfaction is defined as follows.
・The absolute value of the difference between the target rating X and their own rating Y, that is, |X−Y|
For each j = 1, 2, 3, ..., Q, find the minimum possible dissatisfaction of the student numbered j.
However, there may be a class with no students, or a class consisting of multiple students.

## Constraints
```
【制約】
・1 ≦ N ≦ 10^5
・1 ≦ Q ≦ 10^5
・0 ≦ A[i] ≦ 10^9
・0 ≦ B[j] ≦ 10^9
・入力はすべて整数
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 要素の検索はソートして二分探索 (to look up an element, sort first and then binary-search)
- **Core idea:** Sort the class ratings once, then for a student of rating B[j] the closest target rating is either the smallest rating ≥ B[j] (found by binary search) or the entry immediately before it — because after sorting, |A[i] − B[j]| decreases up to the insertion point and increases after it. One sort plus Q binary searches gives O((N+Q) log N).
- **Editorial steps:**
  - **Step 1 (sort so the data is easy to handle):** sort the classes in ascending order of rating. In C++ this is `std::sort`, 計算量 O(N log N); the slide says this is important and that anyone who does not know it should look it up. The figure sorts 32 13 26 69 42 15 90 58 into 13 15 26 32 42 58 69 90.
  - **Step 2 (the optimum is one of two classes):** for a given student, the optimal class is always one of the following two: (1) the class with the minimum target rating among those ≥ the student's own rating; (2) the class exactly one position below that one. So finding the position of (1) is enough to answer.
  - **Step 3 (find (1) by binary search):** the position satisfying (1) is found with a 二分探索 that halves the search range at each step, in O(log N). The slide's example is B_i = 50 on 13 15 26 32 42 58 69 90: it examines 42 (labelled 「42以上」), then 69 (labelled 「69未満」), then 58 (in red), and concludes that the required position is 「58」.
  - **Step 4 (total):** sorting the array plus Q binary searches gives O((N+Q) log N).
- **Complexity:** O((N+Q) log N) — the sort is O(N log N) and each of the Q searches is O(log N); 「十分高速に動作します」.
- **Author's takeaway / typical pattern (典型):** searching for an exactly matching element or the nearest element is often fast with 二分探索; the slide used `std::sort` and `std::lower_bound` and invites the reader to look them up.
- **Related problems (類題):** AOJ ALDS1-4-B 「二分探索」, ABC077-C 「Snuke Festival」
- **Flags:** The claim that the optimum is one of exactly two classes is asserted without proof (it needs |A[i] − B[j]| to be V-shaped over the sorted array, which the slide never argues). The figure's step captions are garbled: after examining 42 and 69 the final caption reads 「58未満なので求める場所は「58」」, which does not literally identify 58, and the yellow/grey shading does not track the current candidate interval — only the examined values 42 → 69 → 58 are a reliable trace (they match a halving search on 8 elements). Boundaries to test: B[j] smaller than every A[i] (the predecessor does not exist), B[j] larger than every A[i] (`lower_bound` returns `end`), duplicate ratings (the constraints do not require A to be distinct), and B[j] = 0.

## Author's Reference Solution
`007.cpp` — Sorts A, then for each B[j] finds with `lower_bound` the first class rating ≥ B[j] and answers the smaller of the differences to that rating and to its predecessor.

```cpp
#include <iostream>
#include <algorithm>
#include <cmath>
using namespace std;

const int INF = 2000000000;
int N;
int A[300009];
int Q;
int B[300009];

int main() {
	// Step #1. Input
	cin >> N;
	for (int i = 1; i <= N; i++) cin >> A[i];
	cin >> Q;
	for (int i = 1; i <= Q; i++) cin >> B[i];

	// Step #2. Sorting
	sort(A + 1, A + N + 1);

	// Step #3. Binary Search
	for (int i = 1; i <= Q; i++) {
		int pos1 = lower_bound(A + 1, A + N + 1, B[i]) - A;
		int Diff1 = INF, Diff2 = INF;
		if (pos1 <= N) Diff1 = abs(B[i] - A[pos1]);
		if (pos1 >= 2) Diff2 = abs(B[i] - A[pos1 - 1]);
		cout << min(Diff1, Diff2) << endl;
	}
	return 0;
}
```
