## Statement (original Japanese)
```
長さが N の整数列 A があります。次の Q 個のクエリを順に処理してください。
・T[i] = 1 のとき: 数列 A の x[i] 番目の値と y[i] 番目の値を入れ替える
・T[i] = 2 のとき: 数列 A を右方向にひとつシフトする
・T[i] = 3 のとき: 数列 A の x[i] 番目の値を出力する

【制約】
・2 ≦ N ≦ 200000
・1 ≦ Q ≦ 200000
・1 ≦ A_i ≦ 10^9
・1 ≦ T[i] ≦ 3
・T[i] = 1 のとき 1 ≦ x[i], y[i] ≦ N, x[i] ≠ y[i]
・T[i] = 2 のとき x[i] = y[i] = 0
・T[i] = 3 のとき 1 ≦ x[i] ≦ N, y[i] = 0
```

## Statement (English translation)
There is an integer sequence A of length N. Process the following Q queries in order.
- When T[i] = 1: swap the x[i]-th and y[i]-th values of the sequence A.
- When T[i] = 2: shift the sequence A one position to the right.
- When T[i] = 3: output the x[i]-th value of the sequence A.

## Constraints

```
・T[i] = 2 のとき x[i] = y[i] = 0
・T[i] = 3 のとき 1 ≦ x[i] ≦ N, y[i] = 0
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 見かけ上の変化をメモ (memoize the *apparent* change — keep one number saying "how far is it shifted/rotated" instead of actually performing the shift)
- **Core idea:** Writing the statement literally makes the T = 2 query an O(N) loop, so Q queries cost O(NQ) and TLE. But a right shift never changes the *relative* order of the elements: the array is merely rotating, and the only thing that changes is the offset. So store one integer 「何回シフトしたか（＝どれくらい回転しているか）」 and translate every T = 1 / T = 3 index through that offset, touching only the original array — O(1) per query, O(N + Q) overall.
- **Editorial steps:**
  - **Step 1 (the literal implementation is too slow):** The slide first writes the statement's program verbatim: `if (T == 1) swap(A[x], A[y]);`, `if (T == 2) { int g = A[N]; for (int i = N - 1; i >= 1; --i) A[i + 1] = A[i]; A[1] = g; }`, `if (T == 3) cout << A[x] << endl;`. The T = 2 branch is O(N) per query, so 「各クエリの処理を上のプログラムのように書くと、T = 2 の処理に時間がかかり、実行時間制限オーバー（TLE）となります。残念ながら、パソコンは 1 秒に数億回の計算しかできません」.
  - **Step 2 (a shift is a rotation):** Look at what T = 2 really does: 「変化しているように見えますが、下図のように何回シフトしても、それに応じて "回転" しているだけで位置関係自体は変わりません」. The figure uses the digits of π, `3 1 4 1 5 9 2 6 5 3` (N = 10), with the `6` highlighted: 0 shifts `3 1 4 1 5 9 2 [6] 5 3` (the 6 at position 8), 1 shift `3 3 1 4 1 5 9 2 [6] 5`, 17 shifts `1 5 9 2 [6] 5 3 3 1 4` (the 6 at position 5).
  - **Step 3 (memorize the shift count, remap the queries):** Hold only the shift count and answer both T = 1 and T = 3 on the original array: 「「何回シフトしたか（＝どれくらい回転しているか）」の値を持つことで、元々の配列のままで T = 1 の交換クエリ、T = 3 の値の出力クエリに答えられます」. The slide's numeric example: at the moment 17 shifts have happened, swapping A[5] and A[7] 「元々の配列で A[8] と A[10] を交換することを指している」 — because 17 ≡ 7 (mod 10) and apparent index i sits at original index i − 7 (mod 10), so 5 − 7 ≡ −2 ≡ 8 and 7 − 7 ≡ 0 ≡ 10. T = 3 uses the same remap to fetch a value.
  - **Step 4 (why the accounting is right):** 「このように、見かけ上の変化に注目することで、全体計算量を O(N+Q) で問題が解けました」 — O(N) to read the array plus O(1) per query.
- **Complexity:** O(N + Q) — stated on the slide (「全体計算量を O(N+Q) で問題が解けました」). Memory: not stated on the slides (the array itself, O(N)).
- **Author's takeaway / typical pattern (典型):** For シフトや反転 (shifts and reversals), memoize 「今どんな変化になっているか」 as a single value rather than actually performing the appearance-changing operation; that deletes the expensive operation and can shrink the complexity dramatically. 「このテクニックは、競技プログラミングでもよく出題されます」.
- **Related problems (類題):** ABC 199-C「IPFL」, ABC 189-E「Rotate and Flip」
- **Flags:** (1) The slide never says to reduce the shift counter mod N — the 17-shift example silently uses 17 ≡ 7 (mod 10). Boundary: keep the counter mod N (the reference `044.cpp` does `shifts = (shifts + N - 1) % N`) or it grows unbounded and the index arithmetic becomes fragile. (2) The sign/direction of the remap is the entire difficulty, and the slide only demonstrates it: apparent index i ↔ original i − s (mod N) after s right shifts (hence its A[5] → A[8] with s = 7), whereas `044.cpp` keeps the *negated* offset (`shifts = (shifts + N - 1) % N` per shift, query `A[(x + shifts) % N]`). Both are correct, but mixing the two conventions is the off-by-one trap. (3) The slide asserts without proof that a swap performed on the original array keeps meaning the right thing after further shifts (true because a rotation is a fixed permutation of positions and the swap is a permutation of the original positions), and it never says that the swap is *permanent* — the invariant being tracked is about positions only, never about values. (4) It also does not mention the statement's convention that T = 2 sends x = y = 0 and T = 3 sends y = 0, which is what makes reading three integers per query safe.

## Author's Reference Solution
`044.cpp`

```cpp
#include <vector>
#include <iostream>
using namespace std;
int main() {
	int N, Q;
	cin >> N >> Q;
	vector<int> A(N);
	for (int i = 0; i < N; ++i) {
		cin >> A[i];
	}
	int shifts = 0;
	for (int i = 0; i < Q; ++i) {
		int T, x, y;
		cin >> T >> x >> y;
		if (T == 1) {
			--x; --y;
			swap(A[(x + shifts) % N], A[(y + shifts) % N]);
		}
		if (T == 2) {
			shifts = (shifts + N - 1) % N;
		}
		if (T == 3) {
			--x;
			cout << A[(x + shifts) % N] << endl;
		}
	}
	return 0;
}
```
