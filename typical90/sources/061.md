# 061 — Deck (deque simulation)

**Difficulty:** ★×2 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_bi
**Source:** AtCoder Typical90 #061 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
あなたはカードを整理するために 1 つの山札を作ります。
最初、山札にカードは 1 枚もありません。

これから Q 個の操作を行います。i 番目 (1 ≦ i ≦ Q) の操作では以下を行います：

・t[i] = 1 のとき、整数 x[i] が書かれたカードを山札の一番上にいれる
・t[i] = 2 のとき、整数 x[i] が書かれたカードを山札の一番下にいれる
・t[i] = 3 のとき、山札の上から x[i] 番目のカードに書かれた数を紙に書き出す

t[i] = 3 の操作で書き出された整数を操作順に出力するプログラムを書いてください。
```

## Statement (English translation)
You make one deck in order to organize cards.
At first, there are no cards in the deck.

You will now perform Q operations. The i-th (1 ≦ i ≦ Q) operation does the following:

・When t[i] = 1, put the card with the integer x[i] written on it on the top of the deck
・When t[i] = 2, put the card with the integer x[i] written on it on the bottom of the deck
・When t[i] = 3, write on paper the number written on the x[i]-th card from the top of the deck

Write a program that outputs, in the order of the operations, the integers written out by the operations with t[i] = 3.

## Constraints
```
【制約】
・2 ≦ Q ≦ 10^5
・1 ≦ t[i] ≦ 3
・t[i] = 1, 2 のとき 1 ≦ x[i] ≦ 10^9
・t[i] = 3 のとき 1 ≦ x[i] ≦ k[i]（k[i] は 1 ≦ j ≦ i かつ t[j] = 1, 2 を満たす j の個数）
・t[i] = 1, 2 を満たす i が少なくとも 1 つ存在する
・t[i] = 3 を満たす i が少なくとも 1 つ存在する
・与えられる入力は全て整数
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** deque を知っていますか？ (「Do you know `deque`?」)
- **Core idea:** The three operations are precisely a deque's interface — push/pop at the front, push/pop at the back, look at the front and the back — and the type-3 query only asks for the x-th element from the top, so the deck can be simulated in O(1) per operation. The slide's own implementation avoids STL: keep one large array and represent the deck by the window (cl, cr) of indices it occupies, so pushing at the front writes A[cl − 1] and decrements cl, pushing at the back writes A[cr] and increments cr, and the x-th card from the top is just A[cl + x − 1].
- **Editorial steps:**
  - **Step 1 — what a deque is:** 「まず、以下のようなデータ構造を deque といいます」: デック A は以下の 3 種類のクエリを処理できる — ① A の先頭に x を追加（または 1 つ削除）する; ② A の末尾に x を追加（または 1 つ削除）する; ③ A の先頭を求めたり、末尾を求めたりする. 「実装方法はリンクバッファなど沢山ありますが、今回は std::deque などの STL 機能を用いずとも簡単に実装できる方法を紹介します」.
  - **Step 2 — array plus window:** 配列 A を用意する。配列内において「A を管理している部分」を区間 (cl, cr) で表し、「最初 cl = cr = 10^5 などにする（絶対に cl が負にならないように）」. Per operation: t = 1 (add x at the front) → 「A[cl − 1] = x とし、cl に 1 を引く」; t = 2 (add x at the end) → 「A[cr] = x とし、cr に 1 を足す」; deletion at the front → 「cl に 1 を足す」 (the slide adds 「末尾の場合も同様のやり方でできる」, i.e. cr に 1 を引く); t = 3 (query the x-th from the top) → 「A[cl + x − 1] を出力する」.
  - **Step 3 — the numeric trace (具体例):** a 10-cell window drawn as cells 95, 96, …, 104. ① 最初は、配列が以下のような状態になっています — cl = cr (empty deck), the labels `cl, cr` sitting at the join between cells 99 and 100; ② 次に、先頭に「31」を追加します → A[cl − 1] = 31 with cl−−, drawn as cell 99 = 31 with `cl` under it and `cr` under cell 100; ③ 次に、末尾に「41」を追加します → A[cr] = 41 with cr++, drawn as cell 99 = 31, cell 100 = 41; ④ 次に、先頭から 2 番目の要素を求めます — 「これは A[cl + 2 − 1] = A[100] = 41 であると分かります。1 番目についても同様です」 (1st gives A[99] = 31).
  - **Step 4 — alternatives and neighbours:** 「また、std::deque を用いた解法もあります。こちらの方が実装がシンプルです」 (push_front / push_back, and t = 3 reads deq[x − 1]); and 「deque の他にも、キュー・スタック・双方向連結リストなどのデータ構造も頻出するので、この機会に理解しておくようにしましょう」.
- **Complexity:** O(Q) overall, O(1) per operation (「deque を使うと全体計算量 O(Q) でこの問題を解くことができます」). Memory: not stated on the slides; the construction needs an array of about 2 × 10^5 cells when cl = cr = 10^5 and Q ≤ 10^5 (`061-01.cpp` uses `A[1 << 20]` and starts at 500000).
- **Author's takeaway / typical pattern (典型):** know `deque` — both the STL container and the 「配列 + 両端ポインタ」 implementation — and its neighbours queue / stack / doubly linked list, since these data structures recur constantly.
- **Related problems (類題):** 第 6 回アルゴリズム実技検定 E「前から3番目」, ABC 158-D「String Formation」, ZONE 2021-D「宇宙からのメッセージ」.
- **Flags:** (1) The sizing argument is one clause: 「最初 cl = cr = 10^5 などにする（絶対に cl が負にならないように）」. With Q ≤ 10^5 front pushes the worst case is exactly cl = 0, so the buffer must hold indices 0 … 2·10^5 — the boundaries cl = 0 and cr = 2·10^5 are the ones to test, and `061-01.cpp` buys margin by starting at 500000. (2) The delete operations (cl++ / cr−−) are stated in one parenthetical line and never exercised — the problem has no deletion at all, so half of the deque specification is unused here. (3) The trace never prints cl and cr numerically: cl = 99 has to be recovered from 「A[cl + 2 − 1] = A[100]」, and in step ③ the `cr` label can be misread as 100 although the invariant (A[cr] = 41, then cr++) forces cr = 101 — from which the deck is A[99..100] = (31, 41). (4) The off-by-one boundaries of the query: x = 1 must give A[cl] (the top) and x = k must give A[cl + k − 1] = A[cr − 1] (the bottom); the slide checks only x = 2 on a two-card deck, so the k-th (bottom) case is untested. (5) The slide gives no bound check for t = 3 — the statement guarantees 1 ≤ x ≤ (number of cards), which is what makes A[cl + x − 1] safe, but the slide never says so.

## Author's Reference Solution
`061-01.cpp` — Simulates the deck on a fixed array whose top and bottom indices `cl` (decreasing) and `cr` (increasing) start in the middle, answering type-3 queries by direct indexing.

```cpp
#include <iostream>
using namespace std;

int Q, T[1 << 20], X[1 << 20];
int A[1 << 20];
int cl = 500000, cr = 500000;

int main() {
	// Step #1. 入力
	cin >> Q;
	for (int i = 1; i <= Q; i++) cin >> T[i] >> X[i];

	// Step #2. シミュレーション
	for (int i = 1; i <= Q; i++) {
		if (T[i] == 1) {
			cl--;
			A[cl] = X[i];
		}
		if (T[i] == 2) {
			A[cr] = X[i];
			cr++;
		}
		if (T[i] == 3) {
			cout << A[cl + X[i] - 1] << endl;
		}
	}
	return 0;
}
```

`061-02.cpp` — The same simulation using `std::deque`, with `push_front` / `push_back` and index access for type-3 queries.

```cpp
#include <iostream>
#include <deque>
using namespace std;

int Q, T[1 << 20], X[1 << 20];

int main() {
	// Step #1. 入力
	cin >> Q;
	for (int i = 1; i <= Q; i++) cin >> T[i] >> X[i];

	// Step #2. シミュレーション
	deque<int> deq;
	for (int i = 1; i <= Q; i++) {
		if (T[i] == 1) deq.push_front(X[i]);
		if (T[i] == 2) deq.push_back(X[i]);
		if (T[i] == 3) cout << deq[X[i] - 1] << endl;
	}
	return 0;
}
```
