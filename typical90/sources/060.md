# 060 — Chimera (bitonic subsequence via LIS from both ends)

**Difficulty:** ★×5 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_bh
**Source:** AtCoder Typical90 #060 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
長さ N の数列 A = (A[1], A[2], ..., A[N]) が与えられます。
A の（連続とは限らない）部分列 B = (B[1], B[2], ..., B[M]) であって次の条件を満たすようなものを考えます。

条件：ある整数 K (1 ≦ K ≦ M) が存在して、以下の条件をともに満たす
・1 ≦ j ＜ K を満たすjに対し、 B[j] < B[j+1] が成立する
・K ≦ j ＜ M を満たすjに対し、 B[j] > B[j+1] が成立する

B の要素数 M として考えられる最大値を求めてください。
```

## Statement (English translation)
A sequence A = (A[1], A[2], ..., A[N]) of length N is given.
Consider a (not necessarily contiguous) subsequence B = (B[1], B[2], ..., B[M]) of A that satisfies the following condition.

Condition: there exists an integer K (1 ≦ K ≦ M) such that both of the following hold
・For j satisfying 1 ≦ j ＜ K, B[j] < B[j+1] holds
・For j satisfying K ≦ j ＜ M, B[j] > B[j+1] holds

Find the maximum possible value of M, the number of elements of B.

## Constraints
```
【制約】
・1 ≦ N ≦ 300000
・1 ≦ A[i] ≦ N
・入力はすべて整数
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 両側から考える／最長増加部分列 (think from both sides / longest increasing subsequence, LIS)
- **Core idea:** In a valid B the values strictly increase up to the peak position K and strictly decrease afterwards, so once the peak index L is fixed the best possible B is the longest increasing subsequence ending at A_L followed by the longest decreasing run starting at A_L — the two parts share only the element A_L, giving M = P_L + Q_L − 1. P is precomputed left-to-right and Q right-to-left with the O(N log N) LIS algorithm, and the answer is max over all L → O(N log N).
- **Editorial steps:**
  - **Step 1 — the simplified sub-problem (LIS):** 「まず、今回の問題をさらに簡単にした、次の問題を考えてみましょう」: given A = (A_1, …, A_N), for each i = 1, 2, …, N find 「数列 A = (A_1, …, A_i) の（連続しなくてもよい）部分列であって、単調増加なものの長さの最大値 P_i」. Worked example on the slide: (A_1, …, A_7) = (3, 1, 4, 1, 5, 9, 2, 6) → the subsequence ⟨1, 4, 5, 9⟩ (the four chosen positions highlighted, the others greyed out) gives 「長さ最大 4」.
  - **Step 2 — the O(N log N) LIS algorithm used for it:** (1) 列 B を用意する。最初 B は空である; (2) i = 1, 2, …, N の順に、現在 B = (B_1, B_2, …, B_K) であるとして、 「B_j < A_i (1 ≦ j ≦ K) である個数 cnt を二分探索により数える」; if cnt = K then 「B の末尾に A_i を追加する」, otherwise 「B_{cnt+1} の値を A_i に修正する」; then 「そのとき、(A_1, …, A_i) の LIS の長さ P_i は cnt + 1 である」. The slide explicitly refuses to justify it: 「LIS を求めるアルゴリズムの詳細な解説をするには 1 ページは短すぎるので、本解説では割愛します」, pointing to https://qiita.com/python_walker/items/d1e2be789f6e7a0851e5.
  - **Step 3 — precompute both directions:** 「次に、(A_1, A_2, …, A_i) の最長増加部分列の長さ P_i と、(A_N, A_{N-1}, …, A_i) の最長増加部分列の長さ Q_i を前計算しましょう」. The slide's table for A = (3, 1, 4, 1, 5, 9, 2, 6):
    ```
    i   : 1  2  3  4  5  6  7  8
    P_i : 1  1  2  1  3  4  2  4
    Q_i : 2  1  2  1  2  2  1  1
    ```
    with a blue arrow drawn left→right across the P row and right→left across the Q row (the two directions of computation), and P_8 = 4 printed in orange as the running maximum.
  - **Step 4 — the formula and the enumeration over the peak:** 「そして、B_1 < … < B_K > … > B_M となる位置 B_K = A_L が決まった場合、M の最大値は (A_1, A_2, …, A_L) の最長増加部分列の長さ + (A_N, A_{N-1}, …, A_L) の最長増加部分列の長さ − 1、つまり P_L + Q_L − 1 となります。したがって、L の値を全探索することで解けます」. On the slide's own example the maximum sits at L = 6: 4 + 2 − 1 = 5, realized by 1, 4, 5, 9 followed by 2 — the slide itself never prints that 5.
  - **Step 5 — closing box:** 「このように、左右両側から考えた上で、最長増加部分列（LIS）を求めるアルゴリズムを使うと、この問題を計算量 O(N log N) で解くことができました」, plus the related idea 「「左右両側から考える」と関連したテクニックとして、「3 個のものを扱う時は中央の 2 個を考える」などの手法もあります」.
- **Complexity:** O(N log N) (「計算量 O(N log N) で解くことができました」), coming from two LIS passes over N ≤ 3·10^5 elements. Memory: not stated on the slides (the reference code keeps `A`, `P`, `Q` and the LIS array `dp` of size N).
- **Author's takeaway / typical pattern (典型):** 両側から考える — precompute the same quantity from the left and from the right and glue the two answers at a shared pivot (here the peak, minus 1 for the double-counted A_L); the LIS machinery is the standard O(N log N) tool for the one-sided half. Related pattern named on the slide: fix the middle two when a triple is involved.
- **Related problems (類題):** JOI 春合宿 2007「Building」, ABC 006-D「トランプ挿入ソート」, ABC 038-D「プレゼント」, ABC 134-E「Sequence Decomposing」, ABC 077-C「Snuke Festival」(両側から考える), ARC 070-D「No Need」(両側から考える).
- **Flags:** (1) The slide's definition and its table disagree: Step 1 defines P_i as the LIS length of the prefix (A_1, …, A_i), but the Step 3 values are the LIS length *ending at* A_i — P_4 = 1 while the prefix (3, 1, 4, 1) has LIS 2. Likewise Q_4 = 1, although (A_8, …, A_4) = (6, 2, 9, 5, 1) contains the increasing ⟨2, 5⟩ of length 2, so Q_i must be read as the longest decreasing run *starting at* A_i. The formula P_L + Q_L − 1 is only valid for that anchored reading, since both chains must own A_L as the peak; the slide never writes 「A_i で終わる／A_i から始まる」. Boundary to test: any array where anchored ≠ prefix, e.g. A = (3, 1, 4, 1). (2) 「したがって、L の値を全探索することで解けます」 asserts max_L (P_L + Q_L − 1) = answer with no proof; the two halves needed are an upper bound (a chimera whose peak is A_L has increasing part ≤ P_L and decreasing part ≤ Q_L) and a construction (the two optimal chains live on indices ≤ L and ≥ L, so they intersect only at A_L and can be concatenated). Boundaries: L = 1 and L = N (one side empty), and K = 1 / K = M (purely decreasing or purely increasing B). (3) Strictness is never pinned down: the statement demands strict < and >, so the LIS must be strict and the patience algorithm must use the first position ≥ A_i (lower_bound), not upper_bound; the boundary that exposes it is a constant array, e.g. A = (1, 1, 1), whose answer is 1. (4) The example's own typo: it writes 「(A_1, …, A_7) = (3, 1, 4, 1, 5, 9, 2, 6)」 — eight values, and the Step 3 table has eight columns, so the range should be A_1…A_8. (5) The LIS algorithm is quoted without proof and its O(N log N) cost is not derived (the binary search is mentioned, the fact that |B| = current LIS length is not); only the length is computed, and the slide never says a subsequence has to be reconstructed (it does not, for this answer).

## Author's Reference Solution
`060.cpp` — Computes, with a `lower_bound`-based LIS table, the length `P[i]` of the increasing subsequence ending at i and the length `Q[i]` of the increasing subsequence starting at i (scanning right to left), then prints the maximum of `P[i] + Q[i] - 1`.

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

int N, A[1 << 19];
int P[1 << 19], Q[1 << 19];
int dp[1 << 19], cnt = 0;

int main() {
	// Step #1. 入力
	cin >> N;
	for (int i = 1; i <= N; i++) cin >> A[i];

	// Step #2. 左側の LIS を求める
	for (int i = 1; i <= N; i++) {
		int pos1 = lower_bound(dp, dp + cnt, A[i]) - dp;
		dp[pos1] = A[i];
		P[i] = pos1 + 1;
		if (pos1 == cnt) cnt++;
	}

	// Step #3. 右側の LIS を求める
	cnt = 0;
	for (int i = N; i >= 1; i--) {
		int pos1 = lower_bound(dp, dp + cnt, A[i]) - dp;
		dp[pos1] = A[i];
		Q[i] = pos1 + 1;
		if (pos1 == cnt) cnt++;
	}

	// Step #4. 答えを求める
	int Answer = 0;
	for (int i = 1; i <= N; i++) {
		Answer = max(Answer, P[i] + Q[i] - 1);
	}
	cout << Answer << endl;
	return 0;
}
```
