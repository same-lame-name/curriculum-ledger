# 038 — Large LCM (LCM with Overflow Guard)

**Difficulty:** ★×3 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_al
**Source:** AtCoder Typical90 #038 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
正整数 A, B が与えられます。
A と B の最小公倍数を求めてください。
ただし、答えが 10^18 を超える場合は「Large」と出力してください。

## Statement (English translation)
Positive integers A, B are given.
Find the least common multiple of A and B.
However, if the answer exceeds 10^18, output "Large".

## Constraints
【制約】
・1 ≦ A ≦ 10^18
・1 ≦ B ≦ 10^18
・入力はすべて整数

## Samples
```
# 入力形式
A B

----------

# 入力例 1
4 6

# 出力例 1
12

----------

# 入力例 2
1000000000000000000 3

# 出力例 2
Large

----------

# 入力例 3
1000000000000000000 1

# 出力例 3
1000000000000000000
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** オーバーフローに注意 (beware of overflow).
- **Core idea:** lcm(a,b) = a × b ÷ gcd(a,b), but evaluating the product a × b first overflows 64-bit as soon as the answer is large, and then the "compare the result with 10^18" test reads a wrapped (garbage) value. Divide first instead: r = b ÷ gcd(a,b), and decide with the test r ≦ ⌊10^18 ÷ a⌋, which is equivalent to a × r ≦ 10^18 and never overflows.
- **Editorial steps:**
  - **Step 1 (the formula and the gcd):** lcm(a,b) = a × b ÷ gcd(a,b). The gcd gcd(a,b) is computed by the Euclidean algorithm (ユークリッドの互除法) in O(log(a + b)); the slide calls it a frequent algorithm and tells the reader to look it up if unknown. From C++17 on there is also the convenient function gcd(a, b), so that can be used instead.
  - **Step 2 (the natural implementation is WA):** Written naturally the program looks like `long long s = a * b / gcd(a, b); if (s > 10^18) "Large" else s`. In a language with arbitrary-precision integers such as Python this ACs, but in C++ it is WA. Example: `1000000000000000000 9000000000000000000` — the correct answer is "Large", but the program prints −86. The reason: while computing a × b the value exceeds the long long (64-bit integer) limit 2^63 − 1, so overflow turns the intermediate result into a garbage value.
  - **Step 3 (overflow-free rewrite):** Let r = b ÷ gcd(a,b). Then "r ≦ ⌊10^18 ÷ a⌋" is a necessary and sufficient condition for "a × r ≦ 10^18", and using that property avoids the overflow. The slide's implementation: `long long a, b, POW18 = 1000000000000000000LL; cin >> a >> b; long long r = b / gcd(a, b); if (r > POW18 / a) cout << "Large"; else cout << r * a;` — the comparison is done by division, and the multiplication only happens when its result is known to fit.
- **Complexity:** gcd is O(log(a + b)) by the Euclidean algorithm; everything else is O(1). The slide states no overall bound explicitly. Memory not stated on the slide.
- **Author's takeaway / typical pattern (典型):** 計算順序や計算方法の工夫 — changing the order and the form of the computation avoids overflow. The slide also warns, by analogy, about 典型 020 (★3, Log Inequality), where the influence of floating-point error similarly leads to WA.
- **Related problems (類題):** ABC 169-B「Multiplication 2」, ABC 185-C「Duodecim Ferra」.
- **Flags:** (1) The demonstrating input `1000000000000000000 9000000000000000000` has b = 9 × 10^18 and violates the statement's constraint B ≦ 10^18, so it can never appear in the judge data; the slide's own counterexample is outside the constraints (10^18 × 10^18 overflows just as well, so the point survives, but the number cannot be tested as given). (2) "r ≦ ⌊10^18 ÷ a⌋ is necessary and sufficient for a × r ≦ 10^18" is called 必要十分 with no proof; it depends on a ≧ 1 and on integer (floor) division. (3) The boundary of equality: an LCM of exactly 10^18 must be printed, not "Large" — sample 3 is that boundary, and the naive test `s > 10^18` gets it right only in the cases where no overflow happened first. (4) The slide compares `s` after the overflowing multiplication, so in the failing case the test itself is meaningless — that is precisely the point, but the write-up shows the test before explaining why it is broken.

## Author's Reference Solution
`038.cpp` — Divides by the gcd first, then prints the product when it does not exceed 10^18 (as decided by division) and Large otherwise.

```cpp
#include <iostream>
using namespace std;

long long gcd(long long a, long long b) {
	if (b == 0) return a;
	return gcd(b, a % b);
}

int main() {
	long long A, B, THRESHOLD = 1000000000000000000LL;
	cin >> A >> B;

	long long C = A / gcd(A, B);
	if (B <= THRESHOLD / C) cout << C * B << endl;
	else cout << "Large" << endl;
	return 0;
}
```
