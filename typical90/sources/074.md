# 074 — ABC String 2 (Operations on a String of a, b, c)

**Difficulty:** ★×6 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_bv
**Source:** AtCoder Typical90 #074 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
いま、電光掲示板に `a`, `b`, `c` からなる長さ N の文字列 S が表示されています。

あなたは以下の 2 種類の操作を好きな順番で何回でも行うことができます。ただし 変化させる とは、元々 `a` だったものを `b` に、`b` だったものを `c` に、`c` だったものを `a` に変えることを指します。
・S[i] = `b` である i (1 ≦ i ≦ N) を 1 つ選び、S[i] を `a` に変更した後、S[1], S[2], ..., S[i - 1] を変化させる。
・S[i] = `c` である i (1 ≦ i ≦ N) を 1 つ選び、S[i] を `b` に変更した後、S[1], S[2], ..., S[i - 1] を変化させる。

最大で何回の操作が行えるか、求めてください。
```

## Statement (English translation)
Right now, a string S of length N consisting of `a`, `b`, `c` is displayed on an electric bulletin board.

You may perform the following two kinds of operations any number of times, in any order. Here, to change means to turn what was `a` into `b`, what was `b` into `c`, and what was `c` into `a`.
・Choose one i (1 ≦ i ≦ N) with S[i] = `b`, change S[i] to `a`, and then change S[1], S[2], ..., S[i - 1].
・Choose one i (1 ≦ i ≦ N) with S[i] = `c`, change S[i] to `b`, and then change S[1], S[2], ..., S[i - 1].

Find the maximum number of operations that can be performed.

## Constraints
```
【制約】
・1 ≦ N ≦ 60
・S は `a`, `b`, `c` からなる長さ N の文字列である
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 特殊ケースを考える／不変量を考える (think about special cases / think about invariants)
- **Core idea:** Give each letter a digit `d[i] = 0, 1, 2` for `a, b, c` and define the potential `Potential = 2^0·d[1] + 2^1·d[2] + … + 2^(N−1)·d[N]`. Hand experiments on strings with a single non-`a` character predict that the answer is exactly this potential (a lone `b` at position i gives `2^(i−1)` operations, a lone `c` gives `2·2^(i−1)`), and `N ≦ 60` with `2^60 ≒ 10^18` makes the guess look right. Two facts then prove it: every operation decreases the potential by at least 1, and an operation that decreases it by exactly 1 always exists — so the maximum number of operations equals `Potential`.
- **Editorial steps:**
  - **Step 1 (guess from special cases):** consider `d = (d_1, d_2, …, d_N)` with `d_i = 0, 1, 2` when `S[i] = 'a', 'b', 'c'`. The claim is `Answer = Σ_{i=1}^{N} 2^(i−1)·d_i = 2^0·d_1 + 2^1·d_2 + … + 2^(N−1)·d_N`. Where does it come from? For `S = "aaa…aaa"` the number of operations is 0, so look at strings with exactly one `b`: `S = "baaaa…aaa"` → 1, `S = "abaaaa…aaa"` → 2, `S = "aabaaa…aaa"` → 4, `S = "aaabaa…aaa"` → 8. So a lone `b` at position i appears to give `2^(i−1)` operations. Since the constraint is `N ≦ 60` and `2^60 ≒ 10^18` (fits a 64-bit integer), this "looks correct" (制約に注目 → 典型 063). By the same reasoning a lone `c` at position i is predicted to give `2·2^(i−1)`, which is exactly what the digit weights produce.
  - **Step 2 (upper bound: the potential drops by at least 1):** introduce `Potential = 2^0·d_1 + 2^1·d_2 + … + 2^(N−1)·d_N`. Take an operation performed at position i. Position i drops by 1 (`b→a` or `c→b`), losing `2^(i−1)`; positions 1…i−1 are each rotated (`a→b→c→a`, i.e. `d → d+1 mod 3`), so each contributes at most `+1`, i.e. at most `2^0 + 2^1 + … + 2^(i−2) = 2^(i−1) − 1` in total. Hence the potential always loses at least 1 per operation (「ポテンシャルは必ず 1 以上減る」).
  - **Step 3 (lower bound: exactly 1 is attainable):** performing the operation at the position of the first character that is not `a` (「初めて 'a' 以外が来る位置」) decreases the potential by exactly 1 — the prefix is all `a`, so the Step 2 upper bound on the gain is met with equality, and the loss at position i cancels it down to a net −1. Combining Step 2 (≤ `Potential` operations) with Step 3, the maximum number of operations is `Potential`.
- **Complexity:** Not stated on the slides (the reference solution is a single O(N) pass over S).
- **Author's takeaway / typical pattern (典型):** This is, by the author's own estimate, the most ad-hoc problem of the 90 (「全 90 問の中で最も ad-hoc な部分の比率が高い」). The transferable techniques shown: notice a peculiar constraint (`N ≦ 60`), examine special cases (`N = 1`), experiment by hand (or on a PC), look for invariants such as "every operation decreases by 1" / "the value does not change", and replace characters by numbers (`{a,b,c} → {0,1,2}`). Knowing such techniques is what lets you win ARC/AGC problems without demanding a genius idea.
- **Related problems (類題):** ARC120-C「Swaps 2」, DDCC2020予選-D「Digit Sum Replace」, AGC018-A「Getting Difference」, ARC117-C「Tricolor Pyramid」
- **Flags:** (1) The formula is only a *guess* after two special families; the slide itself says 「予測できます」 and 「正しそうに見えますね」. The step that independent positions simply add (superposition) is not justified until the potential argument, so a reader should not take the experiment as a proof. (2) Attainability is one sentence plus one example: the slide never says that the "first non-`a`" move stays legal at every step until the potential reaches 0 (if `Potential > 0` some character is not `a`, and the first such character is `b` or `c`, so that operation is available) — that is precisely what upgrades "≤ Potential" to "= Potential". (3) Boundaries to test: all-`a` strings (answer 0), `N = 1` with `S = "b"` (1) and `S = "c"` (2), and the 64-bit bound — the maximum potential is `2·(2^60 − 1) < 2^63`, which the slide only argues indirectly through `2^60 ≒ 10^18`. (4) The slide's four-item example list stops at the 4th position and never shows a mixed string (e.g. `baaca`), where the additive prediction is the interesting part.

## Author's Reference Solution
`074.cpp` — Reads the string and accumulates a value in base 2, adding 1 for every 'b' and 2 for every 'c' at position i, weighted by 2^i.

```cpp
#include <iostream>
using namespace std;

long long N, Answer = 0;
string S;

int main() {
	cin >> N >> S;
	for (int i = 0; i < N; i++) {
		if (S[i] == 'b') Answer += 1LL * (1LL << i);
		if (S[i] == 'c') Answer += 2LL * (1LL << i);
	}
	cout << Answer << endl;
	return 0;
}
```
