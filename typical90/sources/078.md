# 078 — Easy Graph Problem (Counting Vertices by Smaller Neighbours)

**Difficulty:** ★×2 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_bz
**Source:** AtCoder Typical90 #078 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
N 頂点 M 辺の連結な単純無向グラフが与えられます。グラフの頂点には、それぞれ 1 から N までの番号が振られています。i 番目の辺は、頂点 a[i] と b[i] を双方向に結んでいます。

以下の条件を満たす頂点の個数はいくつあるか出力してください。
・自分自身より頂点番号が小さい隣接頂点がちょうど 1 つ存在する
```

## Statement (English translation)
You are given a connected simple undirected graph with N vertices and M edges. The vertices of the graph are numbered 1 through N. The i-th edge connects vertex a[i] and vertex b[i] in both directions.

Output the number of vertices satisfying the following condition.
・Exactly one adjacent vertex has a vertex number smaller than itself.

## Constraints
```
【制約】
・2 ≦ N ≦ 10^5
・N-1 ≦ M ≦ min(N(N-1)/2, 10^5)
・1 ≦ a[i], b[i] ≦ N
・与えられるグラフは単純
・与えられるグラフは連結
・入力はすべて整数
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** グラフの基本を知ろう (know the basics of graphs)
- **Core idea:** Read the graph into **隣接リスト** (adjacency lists) rather than an N×N **隣接行列** (adjacency matrix), then for each vertex count its neighbours with a smaller index; the answer is the number of vertices whose count is exactly 1. The slide spends most of its space on graph representation: an adjacency matrix needs `O(N²)` memory, which for `N ≦ 100000` is `10^10` entries and exceeds the limit (MLE), while adjacency lists need `O(M)` and give direct access to a vertex's neighbours, so the whole scan is `O(N + M)`.
- **Editorial steps:**
  - **Step 1 (what a graph is / adjacency matrix):** a graph is a structure expressing how things are connected: the circles are 頂点 (vertices) and the segments are 辺 (edges) — in a railway-map analogy, stations are vertices and the rails between them are edges. There are two representations. The first, 隣接行列, is an N×N table of "is there an edge between these vertices". For the sample graph (`1–2, 2–3, 3–1, 2–4`) the table is: row 1: `-, O, O, ×`; row 2: `O, -, O, O`; row 3: `O, O, -, ×`; row 4: `×, O, ×, -`. It needs `O(N²)` memory.
  - **Step 2 (adjacency lists):** the second representation, 隣接リスト, collects the neighbours of each vertex. For the same graph: 頂点1: `{2, 3}`, 頂点2: `{1, 3, 4}`, 頂点3: `{1, 2}`, 頂点4: `{2}`; it is implemented with variable-length arrays such as `std::vector`. Advantages: `O(M)` memory even when the number of vertices is huge, and direct retrieval of a vertex's neighbours.
  - **Step 3 (apply to the problem):** the constraint `N ≦ 100000` is large, and managing the graph as an adjacency matrix would require on the order of `10^10` entries, causing メモリ制限超過 (MLE), so use adjacency lists. For each `i (1 ≦ i ≦ N)`, once the set of neighbours `{G[i][1], …, G[i][D_i]}` of vertex i is known, it is enough to count, in `O(D_i)`, the j with `G[i][j] < i`. Each edge contributes `+2` to `D_1 + … + D_N`, so `D_1 + … + D_N = 2M` and the whole answer is obtained in `O(D_1 + … + D_N) = O(M)`.
- **Complexity:** `O(N + M)` overall (right column). Memory not stated explicitly; adjacency lists take `O(N + M)`.
- **Author's takeaway / typical pattern (典型):** the adjacency-list representation (隣接リスト形式) is the default way to hold a graph; graphs appear in a great variety of competitive-programming problems, being set broadly across ABC C–F, so a reader who does not know them should learn them.
- **Related problems (類題):** 第三回アルゴリズム実技検定 E「スプリンクラー」, 第一回アルゴリズム実技検定 E「SNSのログ」, ABC166-C「Peaks」, ABC163-C「management」
- **Flags:** (1) 「`10^10` パターン程度のメモリが必要となり MLE してしまいます」 assumes 4-byte integers (≈40 GB); the slide never quotes the memory limit or the element size, so the threshold is asserted rather than computed. (2) The counting rule is valid only because the graph is simple: with parallel edges a vertex could have the same smaller neighbour twice, and the slide never says so. (3) Boundaries to test: vertex 1 always has 0 smaller neighbours; a leaf hanging off a smaller vertex contributes exactly 1; the graph is guaranteed connected, but neither the algorithm nor its complexity uses connectivity, so a disconnected input must also work. (4) The slide never states the answer for the trivial `N = 2` case (sample 2 gives 1), where an adjacency matrix would already be harmless.

## Author's Reference Solution
`078.cpp` — Counts for each vertex how many of its neighbours have a smaller index, and prints how many vertices have exactly one such neighbour.

```cpp
#include <vector>
#include <iostream>
using namespace std;
int main() {
	int N, M;
	cin >> N >> M;
	vector<vector<int> > G(N);
	for (int i = 0; i < M; ++i) {
		int a, b;
		cin >> a >> b; --a, --b;
		G[a].push_back(b);
		G[b].push_back(a);
	}
	int answer = 0;
	for (int i = 0; i < N; ++i) {
		int cnt = 0;
		for (int j : G[i]) {
			if (j < i) {
				++cnt;
			}
		}
		if (cnt == 1) {
			++answer;
		}
	}
	cout << answer << endl;
	return 0;
}
```
