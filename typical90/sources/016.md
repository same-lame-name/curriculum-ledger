# 016 — Minimum Coins (Clever Brute Force)

**Difficulty:** ★×3 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_p
**Source:** AtCoder Typical90 #016 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
A 円硬貨、B 円硬貨、C 円硬貨のみを使ってピッタリ N 円を支払いたいです。
最小で合計何枚の硬貨を使う必要があるでしょうか。
ただし、各種類の硬貨は無数にあるものとします。

## Statement (English translation)
We want to pay exactly N yen using only A-yen coins, B-yen coins, and C-yen coins.
What is the minimum total number of coins needed?
However, assume there are infinitely many coins of each type.

## Constraints
【制約】
・1 ≦ A, B, C, N ≦ 10^9
・A, B, C はすべて異なる
・合計 9999 枚以内の硬貨でピッタリ N 円を支払うことができる
・入力はすべて整数

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 工夫した全探索 (A cleverly optimized brute force)
- **Core idea:** The number of coins of each type is at most 9999 (the constraint guarantees a solution within 9999 coins), so a triple loop over (x, y, z) is O(L^3) with L = 9999 ≈ 10^12 and TLEs. But once x and y are fixed, z is forced to be (N - Ax - By) / C, so only x and y need to be enumerated: O(L^2). The trick is to spot the wasted dimension in the brute force and eliminate it.
- **Editorial steps:**
  - **Step 1:** Consider trying all combinations of the counts of A-yen, B-yen and C-yen coins. Using the constraint that the total number of coins is ≤ 9999, a full search can be written as a triple loop `for x, for y, for z` up to L = 9999, checking `A*x + B*y + C*z == N` and taking the minimum `x+y+z`. However, this triple loop runs about L^3 ≈ 6 × 10^11 times, which cannot meet the time limit and TLEs.
  - **Step 2:** Look at the left program and find a place that seems impossible to optimize. In fact you do not need to enumerate z, because once the values of x and y are determined, z = (N - Ax - By) / C is determined. Example: making 227 yen with 21-, 47-, 56-yen coins — 21 + 47 + 47 = 115, remaining 112 yen, so the number of 56-yen coins is 2. Using this, only the combination of x and y needs to be searched, reducing the complexity from O(L^3) to O(L^2).
- **Complexity:** O(L^2) where L = 9999 (i.e. ~10^8)
- **Author's takeaway / typical pattern (典型):** Find where the brute force is being wasteful and eliminate it to improve the complexity. "A cleverly optimized brute force" (工夫した全探索) is one of the topics frequently tested in contests.
- **Related problems (類題):** ABC051-B「Sum of Three Integers」, ABC085-C「Otoshidama」, ABC095-C「Half and Half」, ABC112-C「Pyramid」
- **Flags:** none

## Author's Reference Solution
- **016.cpp** — Enumerates the counts i of A-coins and j of B-coins (with i + j ≤ 9999); derives the C-coin count, checks divisibility/nonnegativity/total ≤ 9999, and minimizes the total.

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

long long N;
long long A, B, C;

int main() {
	cin >> N;
	cin >> A >> B >> C;

	long long Answer = (1LL << 30);
	for (int i = 0; i <= 9999; i++) {
		for (int j = 0; j <= 9999 - i; j++) {
			long long V = N - 1LL * i * A - 1LL * j * B;
			long long R = 1LL * i + 1LL * j + V / C;
			if (V% C != 0LL || V < 0 || R > 9999LL) continue;
			Answer = min(Answer, R);
		}
	}
	cout << Answer << endl;
	return 0;
}
```
