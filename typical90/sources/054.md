## Statement (English translation)
The researcher Takahashi has written many co-authored papers, so the people involved created the concept of the Takahashi number out of respect and humor.
The Takahashi number is defined for each researcher as follows.

1. Takahashi's Takahashi number is 0.
2. A researcher who has co-authored with a researcher whose Takahashi number is n, and who has no co-authorship with any researcher whose Takahashi number is less than n, has Takahashi number n+1.
3. A researcher whose Takahashi number is not determined by the above has no defined Takahashi number.

Currently, there are N researchers in this world, including Takahashi, and there are M co-authored papers. The i-th co-authored paper is by K[i] researchers R[i][1], ..., R[i][K[i]].
Here, Takahashi is researcher 1. For each of the N researchers, is the Takahashi number defined? If it is defined, what is its value?

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** グラフの辺数を削減 (reduce the number of edges of the graph)
- **Core idea:** Model the researchers as N vertices and join i–j whenever researchers i and j have co-authored a paper; then the Takahashi number is exactly the shortest-path distance from vertex 1, because it counts how few co-authored papers you must follow from researcher 1. Plain BFS then dies on the edge count (up to ~N²/2 pairs inside the papers) with TLE/MLE, so insert one new vertex per paper and join it to that paper's K_i authors — with weight 0.5 per author–paper edge every author-to-author distance is unchanged (0.5 + 0.5 = 1), and the graph shrinks to N + M vertices and K₁ + ⋯ + K_M edges, on which BFS runs in O(N + M + (K₁ + ⋯ + K_M)).
- **Editorial steps:**
  - **Step 1 (reduce to shortest paths):** Put one vertex per researcher; put an edge between vertices i and j whenever researchers i and j have co-authored. Then 「高橋数」は頂点 1 から各頂点までの最短距離として求められます — the Takahashi number is precisely 「研究者 1 から最小何個の共著論文をたどり着けるか」, which is what a shortest path counts. So the problem is a single-source shortest-path problem, and since every edge costs 1 it can be solved by 幅優先探索 (breadth-first search, BFS).
  - **Step 2 (why the direct graph fails):** The number of edges is at most about N²/2 (every pair of authors on a paper becomes an edge), so the BFS becomes 実行時間制限超過 (TLE) and the adjacency structure becomes メモリ制限超過 (MLE). The slide poses the question 辺の数をなんとかして削減できないか — can the edge count be cut?
  - **Step 3 (one vertex per paper — the reduction):** 「以下のように新たに頂点を作って辺を張ると、2 点間の距離を 1 に保ったまま辺数を大幅に削減」: for paper i create one new vertex and join it to all of R[i][1], …, R[i][K_i], giving each of those edges weight 0.5. Two co-authors are then at distance 0.5 + 0.5 = 1, exactly as in the pairwise graph, and any longer route is unchanged. The new graph has 「頂点数 N + M」 and 「辺数 K₁ + ⋯ + K_M」, so BFS gives the whole answer in O(N + M + (K₁ + ⋯ + K_M)). The figure shows researchers A, B, C, D, E with red paper-vertices between them and 0.5 printed on every author–paper edge, and the concrete small example with authors 1–8: authors 1, 2, 4, 5 hang off one paper vertex, authors 3, 4, 6 off a second (author 4 is on both papers), and authors 7, 8 off a third, every edge labelled 0.5 (「左図の例の場合、次のように改善できます」).
  - **Step 4 (the Erdős-number aside):** The same notion exists with Erdős in place of Takahashi (エルデシュ数): how many co-authored papers you must trace from Erdős. The slide shows Erdős's photograph and dates (1913–1996) and remarks that he was a world-class graph theorist, so the number was presumably coined with affection for him.
- **Complexity:** O(N + M + (K₁ + ⋯ + K_M)) for the BFS on the reduced graph (stated on the slide); memory not stated on the slides, though the whole point is that it drops from an N²-order adjacency structure to O(N + M + ΣK_i).
- **Author's takeaway / typical pattern (典型):** 「グラフの最短経路問題に落とし込むと、辺の数が n² オーダーなど扱いづらい量になることがあります。このとき、グラフの構造にひと工夫を加えることで辺数を削減できることがよくあります」 — when the shortest-path reduction produces an n²-order edge set, add structural vertices; this problem's split-vertex trick is one instance and 「区間に辺を張るクエリ」 is another known one. The footnote adds that Erdős's research is usable in contests — the Erdős–Szekeres theorem and the Erdős–Gallai theorem have both been posed.
- **Related problems (類題):** ARC 061-E 「すぬけ君の地下鉄旅行」, 第二回全国統一プログラミング王決定戦 問題 D 「Shortest Path on a Line」, 第四回アルゴリズム実技検定 問題 J 「ワープ」.
- **Flags:** (1) The 0.5 edge weights are a conceptual device, not something BFS can consume: the slide never says how to implement them, and its own O(N + M + ΣK_i) bound presumes unit weights. You must either double every weight or BFS the unweighted bipartite author–paper graph and halve the resulting distances; 「2 点間の距離を 1 に保ったまま」 is true only under the 0.5 weighting. (2) The statement's definition of the Takahashi number carries the extra clause 「高橋数が n 未満の研究者との共著経験がない」; the slide asserts 高橋数 = BFS distance without deriving that BFS layers automatically satisfy that clause — the boundary is a researcher who co-authors both with an n-researcher and with an (n−1)-researcher, where the definition and the plain distance could disagree. (3) The slide never mentions the researchers whose Takahashi number is undefined; the required output for them is −1, which is exactly where the "unvisited" sentinel matters (the reference uses −2, since dist/2 must land on −1). (4) Edge bookkeeping: K₁ + ⋯ + K_M is the correct total only because each paper contributes exactly one new vertex and K_i incident edges; the naive pairwise graph has Σ C(K_i, 2) ≈ N²/2 edges, which is the number quoted in Step 2.

## Author's Reference Solution
`054.cpp`

```cpp
#include <queue>
#include <vector>
#include <iostream>
using namespace std;
int main() {
	int N, M;
	cin >> N >> M;
	vector<vector<int> > G(N + M);
	for (int i = 0; i < M; ++i) {
		int k, v;
		cin >> k;
		for (int j = 0; j < k; ++j) {
			cin >> v; --v;
			G[v].push_back(N + i);
			G[N + i].push_back(v);
		}
	}
	queue<int> que;
	que.push(0);
	vector<int> dist(N + M, -2);
	dist[0] = 0;
	while (!que.empty()) {
		int u = que.front(); que.pop();
		for (int i : G[u]) {
			if (dist[i] == -2) {
				dist[i] = dist[u] + 1;
				que.push(i);
			}
		}
	}
	for (int i = 0; i < N; ++i) {
		cout << dist[i] / 2 << '\n';
	}
	return 0;
}
```
