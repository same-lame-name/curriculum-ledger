# 064 — Uplift (difference array with absolute-value sum)

**Difficulty:** ★×3 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_bl
**Source:** AtCoder Typical90 #064 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
日本を N 個の区画に分けます。西から i 個目の区画（以下、区画 i とする）の標高は A[i] です。
これから Q 回の地殻変動が起こります。i 回目の地殻変動では、区画 L[i], L[i]+1, ..., R[i] の標高が V[i] ずつ変化します。（V[i]≧0 のとき標高が |V_i| 上がり、V_i<0 のとき標高が |V[i]| 下がることを意味します）

さて、区画 1 から N へ行く際の不便さは次のように定義されます。
> 区画 i の標高を E[i] とするとき、不便さは |E[1] - E[2]| + |E[2] - E[3]| + ... + |E[N-1] - E[N]|

各地殻変動後の不便さをそれぞれ求めてください。
```

## Statement (English translation)
We divide Japan into N sections. The elevation of the i-th section from the west (hereafter, section i) is A[i].
From now on, Q crustal movements occur. In the i-th crustal movement, the elevations of sections L[i], L[i]+1, ..., R[i] change by V[i] each. (When V[i] ≧ 0 the elevation rises by |V_i|, and when V_i < 0 it means the elevation falls by |V[i]|.)

Now, the inconvenience of traveling from section 1 to N is defined as follows.
> When the elevation of section i is E[i], the inconvenience is |E[1] - E[2]| + |E[2] - E[3]| + ... + |E[N-1] - E[N]|

Find the inconvenience after each crustal movement.

## Constraints
```
【制約】
・1 ≦ N,Q ≦ 10^5
・-10^9 ≦ A[i], V[i] ≦ 10^9
・1 ≦ L ≦ R ≦ N
・入力は全て整数
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 階差を考えよう (think in terms of the successive differences)
- **Core idea:** The inconvenience only ever looks at adjacent pairs, so store B_i = (標高 of section i+1) − (標高 of section i) = A_{i+1} − A_i for i = 1, …, N−1; then inconvenience = |B_1| + |B_2| + … + |B_{N−1}|. Adding V to a whole range [L, R] moves both members of every *interior* adjacent pair by V, so their differences do not change at all; only the two boundary differences move: B_{L−1} gains +V and B_R gains −V. Hence each movement costs O(1) work on the running sum of |B| → O(N + Q) in total.
- **Editorial steps:**
  - **Step 1 — replace elevations by differences:** 「この問題で重要なのは「隣接区画の標高差」なので、i = 1, 2, …, N−1 について「（区画 i+1 の標高）−（区画 i の標高）B_i」を考えてみましょう。（そのとき、不便さは |B_1| + |B_2| + … + |B_{N−1}| となります）」.
  - **Step 2 — the effect of one crustal movement:** 「地殻変動によって区画 L, L+1, …, R の標高が V 増えたとき、B_i の値は次のように変化します」: ① B_{L−1} の値が +V 変化する; ② B_R の値が −V 変化する. (Everything strictly inside L … R−1 is unchanged — that is the whole point, and it is what the two bullets encode.)
  - **Step 3 — the numeric trace:** 「例えば A = (3, 1, 4, 1, 5) で区間 [3, 4] の標高が 5 増えた場合」: A becomes (3, 1, 9, 6, 5) (cells 3 and 4 drawn in orange), and the difference row goes from B = (−2, 3, −3, 4) to B = (−2, 8, −3, −1) (the changed entries 8 and −1 highlighted) — i.e. B_2: 3 → 3 + 5 = 8 and B_4: 4 → 4 − 5 = −1, while B_1 and B_3 are untouched. The inconvenience itself goes 12 → 14 (the slide shows the two rows but does not print the sums).
  - **Step 4 — the O(1) update:** 「すると、「地殻変動によってどの程度不便さが増減したか」を計算量 O(1) で求めることができます。つまり以下の実装の通り、答え Answer を変化させていくと、全体計算量 O(N + Q) で解けます」. The snippet: build `B[i] = A[i + 1] - A[i]` and `Answer += abs(B[i])`; per query take `mae = abs(B[L[i] - 1]) + abs(B[R[i]])`, apply `if (L[i] >= 2) B[L[i] - 1] += V[i];` and `if (R[i] <= N - 1) B[R[i]] -= V[i];`, take `ato = abs(B[L[i] - 1]) + abs(B[R[i]])`, then `Answer += (ato - mae)` and print. `B[0]` and `B[N]` stay 0 (the guards prevent writing them), which is why the two out-of-range `abs` terms are harmless.
- **Complexity:** O(N + Q) (「全体計算量 O(N + Q) で解くことができます」). Memory: not stated on the slides (the reference code allocates `A`, `B`, `L`, `R`, `V` as `long long [1 << 18]`).
- **Author's takeaway / typical pattern (典型):** look at the differences of two neighbouring elements (階差) — a range add turns into two point updates on the difference array, so a quantity built from adjacent differences can be maintained in O(1) per range add. 「隣り合う 2 つの要素の差（階差）を見る考察テクニックは、AtCoder だけでなく JOI などでも頻出なので、理解しておきましょう」.
- **Related problems (類題):** JOI 2017 本選 1「フェーン現象」, JOI 2019 予選 4「日本沈没」, yukicoder No. 1209「XOR into You」, AGC 006-C「Rabbit Exercise」.
- **Flags:** (1) The prose states the update as 「B_{L−1} の値が +V 変化する」 / 「B_R の値が −V 変化する」 with no L = 1 / R = N caveat; the guards are load-bearing, because `mae` and `ato` both include |B[L−1]| and |B[R]| — an unguarded `B[0] += V` would change |B[0]| and silently corrupt the delta (the interior of the array would be fine, the answer would not). Boundaries to test: L = 1, R = N, and N = 1 (empty difference array, every answer 0). (2) Range: |A|, |V| ≤ 10^9 and N, Q ≤ 10^5, so Answer reaches ~2·10^14 — `long long` is mandatory and `abs` must be the `long long` overload; the slide never mentions the magnitudes, only that it declares `long long`. (3) The slide's snippet is not compilable as printed: `V[i]` is used but `V` never appears in the declaration lines (`long long N, Q, A[...], L[...], R[...]; long long B[...], Answer = 0;`), so `V[1 << 18]` must be added. (4) The sign convention is fixed by the slide (B_i = A_{i+1} − A_i, matching the trace B = (−2, 3, −3, 4) and both update rules); a reader who defines B_i = A_i − A_{i+1} must flip both signs. The inconvenience is only ever written as |B_1| + … + |B_{N−1}|, which silently relies on the absolute values making the convention irrelevant. (5) The surrounding prose says only 「答え Answer を変化させていくと」, which reads as if the final value were what matters; the statement instead wants Q lines, one per movement (the snippet does print inside the loop, so this is a prose gap, not a code gap). Boundary: a movement that *decreases* the inconvenience, e.g. N = 3, A = (1, 10, 1) with L = R = 2, V = −10 → 18 drops to 2, so a solution that re-sums only at the end, or prints only once, is caught.

## Author's Reference Solution
`064.cpp` — Stores the adjacent differences `B[i] = A[i+1] - A[i]` and the running sum of their absolute values, and for each movement replaces only the two differences at the boundaries of the range, printing the updated sum.

```cpp
#include <iostream>
using namespace std;

long long N, A[1 << 18], B[1 << 18];
long long Q, L[1 << 18], R[1 << 18], V[1 << 18];

int main() {
	// Step #1. 入力
	cin >> N >> Q;
	for (int i = 1; i <= N; i++) cin >> A[i];
	for (int i = 1; i <= Q; i++) cin >> L[i] >> R[i] >> V[i];

	// Step #2. 最初の答え
	long long Answer = 0;
	for (int i = 1; i <= N - 1; i++) {
		B[i] = A[i + 1] - A[i];
		Answer += abs(B[i]);
	}
	
	// Step #3. シミュレーション
	for (int i = 1; i <= Q; i++) {
		long long mae = abs(B[L[i] - 1]) + abs(B[R[i]]);
		if (L[i] >= 2) B[L[i] - 1] += V[i];
		if (R[i] <= N - 1) B[R[i]] -= V[i];
		long long ato = abs(B[L[i] - 1]) + abs(B[R[i]]);
		Answer += (ato - mae);
		cout << Answer << endl;
	}
	return 0;
}
```
