# 045 — Simple Grouping (Minimax K-Grouping of Points)

**Difficulty:** ★×6 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_as
**Source:** AtCoder Typical90 #045 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
ユークリッド平面上に、N 個の点 (X[1], Y[1]), (X[2], Y[2]), ..., (X[N], Y[N]) があります。

これらを、
 1) どのグループにも属さない点
 2) 複数のグループに入る点
 3) ひとつも点が属さないグループ
のないように K 個のグループに分けることを考えます。

同一グループ内での 2 点間距離の最大値を最小化し、その 2 乗の値を出力してください。


【制約】
・2 ≦ K ≦ N ≦ 15
・0 ≦ X[i], Y[i] ≦ 10^9
・(X[i], Y[i]) ≠ (X[j], Y[j])
・入力はすべて整数
```

## Statement (English translation)
There are N points (X[1], Y[1]), (X[2], Y[2]), ..., (X[N], Y[N]) on the Euclidean plane.

Consider dividing these points into K groups so that there is
1) no point that belongs to no group,
2) no point that belongs to more than one group, and
3) no group that contains no points.

Minimize the maximum distance between two points in the same group, and output the square of that value.

## Constraints
```
【制約】
・2 ≦ K ≦ N ≦ 15
・0 ≦ X[i], Y[i] ≦ 10^9
・(X[i], Y[i]) ≠ (X[j], Y[j])
・入力はすべて整数
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** bit DP ／ 部分集合の部分集合は 3^N 通り (bit DP / the number of (subset, sub-subset) pairs is 3^N, not 4^N)
- **Core idea:** N ≤ 15, so the state is "which points already belong to a group", recorded as a base-2 integer `bit` in 0 … 2^N−1 (bit DP). Let dp[bit][cnt] = the minimum score when the points of `bit` have been split into `cnt` groups, where the score is the maximum pairwise distance inside a group, and let d[bit] = that same maximum taken over the points of `bit`. The last group contributes some non-empty `bit − b`, hence dp[bit][cnt] = min over b ⊂ bit of max(dp[b][cnt−1], d[bit−b]). Enumerating every (b, bit) pair looks like 4^N, but each point is either in b, in bit−b, or in neither, so there are only 3^N pairs and the DP is feasible.
- **Editorial steps:**
  - **Step 1 (state design):** 「まず、以下の値を動的計画法で順々に計算することを考えます」: dp[既に選んだ点][現在のグループ数] = スコアの最小値, where 「ここでは「同一グループ内での二点間距離の最大値」をスコアとします」. The chosen set runs from 「何も選んでない」 to 「全て選んだ」, i.e. 2^N possibilities, recorded as an integer 0 … 2^N−1. The slide's table for N = 3: bit 0 → なし; bit 1 → {(X_1,Y_1)}; bit 2 → {(X_2,Y_2)}; bit 3 → {(X_1,Y_1),(X_2,Y_2)}; bit 4 → {(X_3,Y_3)}; bit 5 → {(X_1,Y_1),(X_3,Y_3)}; bit 6 → {(X_2,Y_2),(X_3,Y_3)}; bit 7 → {(X_1,Y_1),(X_2,Y_2),(X_3,Y_3)}. Recording 「現在までに選ばれているもの」 as such an integer is what is called bit DP.
  - **Step 2 (transition):** 「DP の式は、こんな感じになります」: dp[bit][cnt] = min over b ⊂ bit of max(dp[b][cnt − 1], d[bit − b]), where d[bit] = 「グループに含まれる点の集合が bit のときの二点間距離の最大値」 and 「この値はあらかじめ計算するものとします」. Here b ranges over the subsets of bit (which points were used before the last group) and bit − b is the group added last.
  - **Step 3 (why the submask enumeration is cheap):** The slide writes the point count as n (= N in the statement). Such (b, bit) pairs 「一見 4^n 通りくらいありそうに思えますが、実は 3^n 通りしかありません」 — because for each point there are exactly three cases: in b, in bit − b, or in neither. 「よって、適切に実装することで、全体計算量 O(3^n × N) での DP が動作します」.
  - **Step 4 (stated bound and the footnote alternative):** 「bit DP が計算量 3^n のオーダーになります」. Footnote: an alternative 解 exists that binary searches the answer and reduces the problem to 彩色数 (graph coloring), giving O(2^n × N log N); the known algorithm for the chromatic number of an n-vertex graph is O(2^n × N).
- **Complexity:** O(3^n × N) for the DP, as stated, with n = N the number of points (「全体計算量 O(3^n × N) での DP が動作します」; the slide also says 「bit DP が計算量 3^n のオーダーになります」). The precomputation of d[bit] is explicitly excluded from that bound. Memory: not stated on the slides (the DP table is 2^n × (K+1) entries, the d table 2^n).
- **Author's takeaway / typical pattern (典型):** bit DP is the standard upgrade from n!-permutation brute force and is used well beyond this problem; 「bit DP は、今回の問題に限らず、例えば n! 通り全探索からの高速化にも使われます。特に JOI では満点や部分点解法として頻出です」. And the reusable counting fact: 「「部分集合の部分集合」は（4^n 通りではなく）全部で 3^n 通りしかないため、集合を合わせていくと bit DP が計算量 3^n のオーダーになります」.
- **Related problems (類題):** AOJ DPL 2-A「巡回セールスマン問題」, JOI 2014 予選 4「部活のスケジュール表」, ABC 187-F「Close Group」, M-SOLUTIONS 2020 問題 E「M's Solution」
- **Flags:** (1) 「この値はあらかじめ計算するものとします」 hides a real cost: filling d[bit] for all 2^N sets by scanning every inner pair is O(2^N N^2) (that is literally what `045.cpp` does with its `j`/`k` double loop), so the quoted O(3^N × N) covers the DP only. Boundary to test: d of a one-point group must be 0 — the max over an *empty* set of pairs; the slide never says it and the code gets it for free. (2) The DP uses exactly `cnt` groups and is read at cnt = K, while the statement asks for K non-empty groups — the two agree, but only because splitting a group never increases the max intra-group distance; that argument is not on the slide. (3) `b ⊂ bit` is written without excluding b = bit (which would create an empty group) or b = 0 when cnt−1 groups are already accounted for; both must be excluded and the slide does not say so (the reference loops `for (k = j; k != 0; k = (k-1) & j)`). (4) No proof that "last group + rest" is a valid decomposition for a min-max DP: it counts each unordered partition many times (K! orders), harmless for a minimum but never discussed. (5) Initialisation is absent (dp[0][0] = 0, everything else = ∞ / 1LL<<62 in the code) — the boundary where infeasible (bit, cnt) pairs must not leak into the min.

## Author's Reference Solution
`045.cpp`

```cpp
#include <vector>
#include <iostream>
using namespace std;
int main() {
	cin.tie(0);
	ios_base::sync_with_stdio(false);
	int N, K;
	cin >> N >> K;
	vector<int> X(N), Y(N);
	for (int i = 0; i < N; ++i) {
		cin >> X[i] >> Y[i];
	}
	vector<vector<long long> > d(N, vector<long long>(N));
	for (int i = 0; i < N; ++i) {
		for (int j = 0; j < N; ++j) {
			d[i][j] = (long long)(X[i] - X[j]) * (X[i] - X[j]) + (long long)(Y[i] - Y[j]) * (Y[i] - Y[j]);
		}
	}
	vector<long long> cost(1 << N);
	for (int i = 1; i < 1 << N; ++i) {
		for (int j = 0; j < N; ++j) {
			for (int k = 0; k < j; ++k) {
				if (((i >> j) & 1) == 1 && ((i >> k) & 1) == 1) {
					cost[i] = max(cost[i], d[j][k]);
				}
			}
		}
	}
	vector<vector<long long> > dp(K + 1, vector<long long>(1 << N, 1LL << 62));
	dp[0][0] = 0;
	for (int i = 1; i <= K; ++i) {
		for (int j = 1; j < 1 << N; ++j) {
			for (int k = j; k != 0; k = (k - 1) & j) {
				dp[i][j] = min(dp[i][j], max(dp[i - 1][j - k], cost[k]));
			}
		}
	}
	cout << dp[K][(1 << N) - 1] << endl;
	return 0;
}
```
