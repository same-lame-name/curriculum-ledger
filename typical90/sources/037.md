# 037 — Don't Leave the Spice (Knapsack with Ranged Consumption)

**Difficulty:** ★×5 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_ak
**Source:** AtCoder Typical90 #037 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
香辛料を使う料理が N 個あり、1 から N までの番号が付いています。
料理 i (1 ≦ i ≦ N) の価値は V[i] で、作るときに香辛料を消費します。消費する香辛料の量は L[i] [mg] 以上 R[i] [mg] 以下の範囲で調節できます。

以下のことが実現可能かどうか判定し、可能な場合は作る料理の価値の合計としてあり得る最大の値を出力してください。
・N 種類の料理から何種類か選んで 1 つずつ作ることで、香辛料をちょうど W [mg] 消費する。
ただし、上で述べた手段以外で香辛料を使うことはできません。

## Statement (English translation)
There are N dishes that use spices, numbered 1 through N.
The value of dish i (1 ≦ i ≦ N) is V[i], and making it consumes spices. The amount of spice consumed can be adjusted within the range from L[i] [mg] or more to R[i] [mg] or less.

Determine whether the following is feasible, and if it is feasible, output the maximum possible value of the total value of the dishes made.
・By choosing some kinds from the N kinds of dishes and making one of each, consume exactly W [mg] of spice.
However, spices cannot be used by any means other than the means described above.

## Constraints
【制約】
・1 ≦ W ≦ 10^4
・1 ≦ N ≦ 500
・1 ≦ L[i] ≦ R[i] ≦W
・1 ≦ V[i] ≦ 10^9
・入力はすべて整数

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** DP をセグメント木で高速化 (speed the DP up with a segment tree).
- **Core idea:** Because dish i consumes between L_i and R_i spice, each transition reads a contiguous window of the previous DP row: dp[i][j] = max(dp[i−1][j−R_i], …, dp[i−1][j−L_i]) + V_i. Scanning that window is the bottleneck (O(W²N) in total). The window maximum is a range-max query over dp[i−1][·], so a segment tree answers every transition in O(log W), giving O(NW log W); the same window maximum maintained by a deque gives O(NW).
- **Editorial steps:**
  - **Step 1 (遅い解法 — the knapsack-shaped DP):** The problem looks very much like a knapsack, so consider dp[how many dishes have been considered][total spice] = maximum total value. This DP really does solve it, with transitions ① skip: dp[i][j] = dp[i−1][j]; ② take: dp[i][j] = max(dp[i−1][j−R_i], dp[i−1][j−R_i+1], …, dp[i−1][j−L_i]) + V_i. Unfortunately the cost is O(W²N), which TLEs. The slide's table for (L,R,V) = (1,2,3), (1,2,4), (3,3,5) with columns j = 0…6 reads: row 0 = 0, −∞, −∞, −∞, −∞, −∞, −∞; row 1 = 0, 3, 3, −∞, −∞, −∞, −∞; row 2 = 0, 4, 7, 7, 7, −∞, −∞; row 3 = 0, 4, 7, 7, 9, 12, 12. The arrows on the highlighted cells show that a cell of row 2 is read out of a contiguous run of row 1 (e.g. dp[2][2] = max(dp[1][0], dp[1][1]) + 4 = 3 + 4 = 7, and dp[3][4] = dp[2][1] + 5 = 4 + 5 = 9).
  - **Step 2 (速い解法 — reduce to RMQ):** Identify which part is the bottleneck: the max over the window j−R_i … j−L_i, scanned in O(W) for every (i,j), hence O(W²N). Can it be cut? Reduce it to Range Minimum Query: given the sequence A = (A_1, A_2, …, A_M), answer Q queries of the following two forms — type 1: x and y are given, set A_x to y; type 2: l and r are given, output max(A_l, A_{l+1}, …, A_r). A segment tree answers each query in O(log M) (the slide omits the data-structure explanation itself and tells the reader to look it up).
  - **Step 3 (the whole DP at O(W log W) per dish):** Once reduced to RMQ, the range maximum is fast, so each i (1 ≦ i ≦ N) is solved in O(W log W) and the whole DP becomes O(NW log W). (Footnote ※: all the other steps of the DP are O(WN).)
- **Complexity:** O(NW log W). The slide also names the alternative: with a deque (sliding-window minimum algorithm) the problem can be solved in O(NW), omitted there (「ここでは割愛しますが、是非調べてみてください」). Memory not stated on the slides (the reference code keeps dp[509][10009] and one segment tree of size ~W per row).
- **Author's takeaway / typical pattern (典型):** When a DP transition repeatedly asks for the minimum/maximum over a sliding window of the previous row, replace the scan by a segment tree, i.e. reduce the transition to the named problem Range Minimum Query. That is the named technique of the slide: 「DP をセグメント木で高速化」.
- **Related problems (類題):** ABC 170-E「Smart Infants」, JOI 2015 予選 6「財宝」, JOI 2011 春合宿「Bookshelf」.
- **Flags:** (1) The slide names the reduction Range Minimum Query but the operation actually used is range max — the name is being used for the range-query family, not for the minimum specifically. (2) The O(NW) deque alternative is asserted with no algorithm (「割愛します」) — an unproven claim to check. (3) The initialisation and the infeasible case are never discussed: dp[i][j] must be −∞ for j < L_i and for unreachable sums, and the statement requires printing −1 when exactly W cannot be consumed — the slide only ever discusses maximizing. (4) The window bounds are written as j−R_i … j−L_i without saying they are clipped at 0; in `037.cpp` that boundary lives in cl = max(0, j−R_i), cr = max(0, j−L_i+1) together with the `if (cl == cr) continue;` skip. (5) The slide's table uses −∞ as an unreachable marker but never explains what −∞ + V_i or a max over an all-−∞ window yields, which is exactly the trap the reference code guards with `if (val != −(1LL << 60))`.

## Author's Reference Solution
`037.cpp` — Runs a DP over the dishes and the consumed spice amount, reading each transition from a range-maximum segment tree over the previous row.

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

class RangeMax {
public:
	int size_ = 1;
	vector<long long> dat;

	void init(int sz) {
		while (size_ <= sz) size_ *= 2;
		dat.resize(size_ * 2, -(1LL << 60));
	}
	void update(int pos, long long x) {
		pos += size_;
		dat[pos] = x;
		while (pos >= 2) {
			pos >>= 1;
			dat[pos] = max(dat[pos * 2], dat[pos * 2 + 1]);
		}
	}
	long long query_(int l, int r, int a, int b, int u) {
		if (l <= a && b <= r) return dat[u];
		if (r <= a || b <= l) return -(1LL << 60);
		long long v1 = query_(l, r, a, (a + b) >> 1, u * 2);
		long long v2 = query_(l, r, (a + b) >> 1, b, u * 2 + 1);
		return max(v1, v2);
	}
	long long query(int l, int r) {
		return query_(l, r, 0, size_, 1);
	}
};

long long W, N;
long long L[1 << 18], R[1 << 18], V[1 << 18];
long long dp[509][10009];
RangeMax Z[509];

int main() {
	// Step #1. 入力
	cin >> W >> N;
	for (int i = 1; i <= N; i++) cin >> L[i] >> R[i] >> V[i];

	// Step #2. 初期化
	for (int i = 0; i <= N; i++) {
		for (int j = 0; j <= W; j++) dp[i][j] = -(1LL << 60);
		Z[i].init(W + 2);
	}
	dp[0][0] = 0;
	Z[0].update(0, 0);

	// Step #3. 動的計画法
	for (int i = 1; i <= N; i++) {
		for (int j = 0; j <= W; j++) dp[i][j] = dp[i - 1][j];
		for (int j = 0; j <= W; j++) {
			int cl = max(0, j - (int)R[i]), cr = max(0, j - (int)L[i] + 1);
			if (cl == cr) continue;
			long long val = Z[i - 1].query(cl, cr);
			if (val != -(1LL << 60)) {
				dp[i][j] = max(dp[i][j], val + V[i]);
			}
		}
		for (int j = 0; j <= W; j++) Z[i].update(j, dp[i][j]);
	}

	// Step #4. 出力
	if (dp[N][W] == -(1LL << 60)) cout << "-1" << endl;
	else cout << dp[N][W] << endl;
	return 0;
}
```
