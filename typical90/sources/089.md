# 089 — Partitions and Inversions (Bounded-Inversion Partitions)

**Difficulty:** ★×7 (author's star rating)

## Statement (original Japanese)
```
長さ N の正整数列 A = (A[1], A[2], ..., A[N]) が与えられます。
この数列を 1 つ以上の空でない連続した区間に分割する方法は 2^{N-1} 通りありますが、これらのうち次の条件を満たすものの個数を数えてください。

- すべての区間について、その区間内でのバブルソートの交換回数が K 以下である。

なお、答えは非常に大きくなる可能性があるため、10^9+7 で割った余りを出力してください。

《バブルソートの交換回数とは》
「A[i] > A[i+1] であればその 2 数を交換する、という操作を i = 1, 2, ..., N-1 の順に行う」ことを 1 回の走査とします。そこで走査を N-1 回繰り返すことで、数列を昇順にソートできることが知られています。
ここでは、このアルゴリズムを適用した時に整数の交換が行われる回数をバブルソートの交換回数と定義します。
例えば、A = (2, 4, 3, 1) の場合、バブルソートの交換回数は 4 です。


【制約】
・1 ≦ N ≦ 200000
・0 ≦ K ≦ N(N-1)/2
・1 ≦ A[i] ≦ 10^9
・入力はすべて整数


【小課題】
1. (1 点) K = 0
2. (1 点) N ≦ 15
3. (1 点) N ≦ 800
4. (2 点) N ≦ 10000
5. (2 点) 追加の制約はない
```

## Statement (English translation)
A sequence of positive integers A = (A[1], A[2], ..., A[N]) of length N is given.
There are 2^{N-1} ways to partition this sequence into one or more non-empty contiguous intervals. Among them, count the number of ways that satisfy the following condition.

- For every interval, the number of swaps performed by bubble sort within that interval is at most K.

Note that the answer can be very large, so output it modulo 10^9+7.

《What is the number of swaps of bubble sort?》
Let one pass be the operation: for i = 1, 2, ..., N-1 in this order, if A[i] > A[i+1], swap the two numbers. It is known that repeating the pass N-1 times sorts the sequence in ascending order.
Here, the number of swaps of bubble sort is defined as the number of times integers are swapped when this algorithm is applied.
For example, when A = (2, 4, 3, 1), the number of swaps of bubble sort is 4.

【Subtasks】
1. (1 point) K = 0
2. (1 point) N ≦ 15
3. (1 point) N ≦ 800
4. (2 points) N ≦ 10000
5. (2 points) No additional constraints

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** P1「累乗に帰着させよう」 (reduce to a power / exponentiation); P2「バブルソートの交換回数 = 転倒数」 (bubble-sort swap count = inversion count); P3「しゃくとり法・BIT を使って高速化」 (speed up with two pointers and a BIT); P4「累積和を用いた DP」 (DP with prefix sums).
- **Core idea:** Bubble sort's swap count is exactly the inversion count, so “every piece has ≤ K bubble-sort swaps” becomes “every piece has ≤ K inversions”. For each right end r let cl[r] be the smallest l with inv(A[l..r]) ≤ K; cl is non-decreasing, so one two-pointer sweep finds all cl[r], and a BIT with coordinate compression makes that O(N log N) instead of O(N³). Then dp[r] = dp[cl[r]−1] + … + dp[r−1] counts the partitions whose last piece is valid, and a prefix-sum array makes each transition O(1). Total O(N log N).
- **Editorial steps:**
  - **P1 (小課題 1, K = 0 → answer 2^cnt):** For K = 0 every piece must already be ascending, so a boundary with A_i > A_{i+1} must be cut. Example A = (2,4,1,3,6,5): the cuts between A_2|A_3 and A_5|A_6 are forced; the other three boundaries (A_1|A_2, A_3|A_4, A_4|A_5) are free, and the slide enumerates cuts at those free boundaries to show every piece stays ascending (「どの方法でも全ピースが昇順にソートされた状態になります」). With cnt = #{ i : A_i < A_{i+1} }, the number of partitions is 2 × 2 × 2 × … × 2 = 2^cnt [通り]. The slide's code sets `Answer = 1, mod = 1000000007`, counts cnt, then multiplies Answer by 2 exactly cnt times; “計算量は O(N) であり、十分高速です”. This is the named move 累乗に帰着させる (▶典型069): naive multiplication suffices here, but 繰り返し二乗法 computes a^b mod m in O(log b).
  - **P1 supplement (小課題 2, N ≤ 15):** small enough for bit 全探索 (▶典型002) over all 2^{N−1} cut patterns, O(2^N × N²).
  - **Step 1 — rewrite the condition as an inversion count (▶典型049):** バブルソートの交換回数 = #{ (i,j) : A_i > A_j, 1 ≤ i < j ≤ N } (転倒数). Example A = (2,3,1,4): only (i,j) = (1,3) and (2,3) have A_i > A_j, so 2 swaps, and the slide's drawn passes also give 2 ((2,3,1,4) → (2,1,3,4) 「1回目」 → (1,2,3,4) 「2回目」). The justification is via an invariant (▶典型076), in two bullets: (a) however two adjacent elements are swapped, the inversion count cannot drop by 2 or more; (b) unless A is sorted there is at least one i with A_i > A_{i+1}, and swapping that pair drops the inversion count by exactly 1 — hence the two quantities agree. Illustration: 3 7 1 5 6 4 2 has 12 inversions; swap(A_2,A_3) → 3 1 7 5 6 4 2 with 11 (only the pair (2,3) changes status), swap(A_5,A_6) → 3 1 7 5 4 6 2 with 10, swap(A_4,A_5) → 3 1 7 4 5 6 2 with 9.
  - **Step 2 — define cl[r]:** For each r = 1,2,…,N find cl[r] = 区間 [l,r] の転倒数が K 以下となる最小の l, i.e. the minimum l with inv(A[l..r]) ≤ K. A final piece [l,r] is usable iff l ≥ cl[r] (and l ≤ r).
  - **Step 2, naive O(N³):** For each r, shift l left one step at a time, measuring how much the inversion count changed, and stop at the first shift where it exceeds K. Slide example (K = 5, r = N, A = (3,5,2,4,1)): [5,5] = (1), inv 0; add A_4 = 4 (A_4 > A_5) → 1; add A_3 = 2 (A_3 < A_4, A_3 > A_5) → 2; add A_2 = 5 (A_2 > A_3, A_4, A_5) → 5; add A_1 = 3 (A_1 < A_2, A_1 > A_3, A_1 < A_4, A_1 > A_5) → 7 > 5, so cl[5] = 2. Verdict: 「しかし計算量は O(N³) と効率が悪いです」.
  - **Step 2, O(N²) via monotonicity + しゃくとり法 (▶典型034):** The slide asserts the key property 単調性: cl[1] ≤ cl[2] ≤ cl[3] ≤ … ≤ cl[N]. Hence two pointers: ① start with (l,r) = (N,N) and keep shifting l left 「ギリギリまで」 while inv(A[l..r]) ≤ K; ② once cl[r] is known, decrease r by 1. The per-shift change is: when l decreases by 1, the number of A_l,…,A_r smaller than A_l; when r decreases by 1, the number of A_l,…,A_r larger than A_r — recomputing that by brute force costs O(N) per shift, so O(N²) overall. Numeric trace (N = 5, K = 2, A = (3,5,4,2,1)): [5,5] inv 0 → add A_4 (A_4 > A_5) +1 → 1 → add A_3 (A_3 > A_4, A_5) +2 → 3 > 2 ⇒ cl[5] = 4 → drop A_5 (A_3, A_4 > A_5) −2 → 1 → add A_2 (A_2 > A_3, A_4) +2 → 3 > 2 ⇒ cl[4] = 3 → drop A_4 (A_2, A_3 > A_4) −2 → 1 → add A_1 (A_1 < A_2, A_3) +0 → 1 ≤ 2 ⇒ cl[3] = 1 → drop A_3 (A_1 < A_3, A_2 > A_3) −1 → 0 ⇒ cl[2] = 1 → drop A_2 (A_1 < A_2) ⇒ cl[1] = 1. Thus (cl[1],…,cl[5]) = (1,1,1,3,4).
  - **Step 2, O(N log N) via BIT + 座標圧縮 (▶典型017, ▶典型034):** A BIT over an array d supports add(x,y) (add y to d[x], y may be negative) and query(x) = d[1]+d[2]+…+d[x], each in O(log N). Add 1 to d[A_i] when A_i enters the window and −1 when it leaves; then “the number of integers ≤ x inside the window” is one query, so all of {cl[1],…,cl[N]} take O(N log N). Because the constraint is A_i ≤ 10⁹, 座標圧縮 must be done first.
  - **Step 3 — partition DP (▶典型050):** dp[r] = r 番目の要素までを考えたときの分割方法の総数. Because the last piece can be [cl[r],r], [cl[r]+1,r], …, [r−1,r], [r,r]: dp[r] = dp[cl[r]−1] + dp[cl[r]] + … + dp[r−2] + dp[r−1]. On the slide's own example (N = 5, K = 2, A = (3,5,4,2,1), cl = (1,1,1,3,4)) this yields dp[0..5] = 1, 1, 2, 4, 6, 10, so the answer is 10. But this recurrence is O(N²).
  - **Step 3 — prefix sums (▶典型010):** With dp2[i] = Σ_{j=0}^{i} dp[j] = dp2[i−1] + dp[i], every dp[i] is O(1): dp[i] = dp2[i−1] − dp2[cl[i]−2], with the convention dp2[−1] = 0 and dp2[0] = 1. Slide table: i = −1,0,1,2,3,4,5 gives dp2 = 0, 1, 2, 4, 8, 14, 24; 「元々は dp[5] = dp[3] + dp[4] でしたが、今回の場合は累積和を用いて dp[5] = (dp2[4] − dp2[2]) = (14 − 4) = 10 となります」.
- **Complexity:** P1: O(N). 小課題 2: O(2^N × N²). Step 2: O(N³) naive → O(N²) with the monotone two-pointer sweep → O(N log N) with BIT (coordinate compression included). Step 3: O(N²) → O(N) with prefix sums. Whole problem: O(N log N), which the slide states explicitly (“全体計算量 O(N log N) で解くことができました”).
- **Author's takeaway / typical pattern (典型):** The transferable pattern is the fusion of seven typicals: 「条件の言い換え」「不変量」「しゃくとり法」「BIT」「座標圧縮」「累積和」「動的計画法」. For K = 0 the pattern is the pure mathematical observation that reduces counting to a power (累乗に帰着); for the general case it is “rewrite the condition → find the monotone window boundary → speed it up with BIT → count with a partition DP accelerated by prefix sums”. The slide's meta-point: AtCoder has many problems not solvable by a single typical technique, but combining the 89 typicals covers ABC through ARC/AGC.
- **Related problems (類題):** Not listed for P1–P3; slide 1 instead points at the 典型069 commentary for related problems on 累乗への帰着 and 繰り返し二乗法. Slide 4 lists (limited to 累積和 + DP fusion problems): ABC179-D「Leaping Tak」, ABC209-F「Deforestation」, EDPC-M「Candies」, AGC009-C「Division into Two」.
- **Flags:** (1) Slide 1 defines cnt = #{ i : A_i < A_{i+1} } and its code tests `A[i] < A[i+1]`, strictly; but equal neighbours are allowed by the statement (A_i ≤ 10⁹, not distinct) and A_i = A_{i+1} is also a free boundary — `089-01.cpp` uses `<=`. Boundary to test: A = (1,1), K = 0 (expected 2). (2) The identity バブルソートの交換回数 = 転倒数 is only sketched by two bullets (“転倒数が 2 以上落ちない”, “ソートされていなければ必ず 1 落ちる”); the induction/potential argument is left to the reader. (3) Slide 3 calls the monotonicity cl[1] ≤ … ≤ cl[N] 「明らかに成り立ちます」 with no proof; this is the claim the O(N²)/O(N log N) steps rest on. (4) The O(N²) claim also needs that l only ever moves left (amortized O(N) shifts total), which the slide does not spell out. (5) 典型034 is cited twice on slide 3, once for しゃくとり法 and once for 座標圧縮 — one of the two citations is presumably a typo. (6) Boundaries worth testing: K = 0 (cl[r] = r, answer counts only already-sorted cuts), K = N(N−1)/2 (whole array valid, answer 2^{N−1}), and the dp2[−1] = 0 branch, which is taken exactly when cl[i] = 1 (e.g. i = 1).

## Author's Reference Solution
`089-01.cpp` — For K = 0, multiplies the answer by 2 for every adjacent non-decreasing pair.

```cpp
#include <iostream>
using namespace std;

long long mod = 1000000007;
long long N, K, Answer = 1;
long long A[1 << 18];

int main() {
	cin >> N >> K;
	for (int i = 1; i <= N; i++) cin >> A[i];
	for (int i = 1; i <= N - 1; i++) {
		if (A[i] <= A[i + 1]) {
			Answer *= 2LL;
			Answer %= mod;
		}
	}
	cout << Answer << endl;
	return 0;
}
```

`089-02.cpp` — Enumerates all 2^{N-1} partitions and directly counts inversions in every interval.

```cpp
#include <iostream>
#include <vector>
using namespace std;

long long N, K;
long long A[19];

long long count_inversions(vector<long long> vec) {
	long long cnt = 0;
	for (int i = 0; i < vec.size(); i++) {
		for (int j = i + 1; j < vec.size(); j++) {
			if (vec[i] > vec[j]) cnt++;
		}
	}
	return cnt;
}

int main() {
	// Step #1. Input
	cin >> N >> K;
	for (int i = 0; i < N; i++) cin >> A[i];
	
	// Step #2. Brute Force
	long long Answer = 0;
	for (int i = 0; i < (1 << (N - 1)); i++) {
		vector<long long> vec; bool flag = true;
		for (int j = 0; j < N; j++) {
			vec.push_back(A[j]);
			if (j == N - 1 || ((i & (1 << j)) != 0)) {
				long long val = count_inversions(vec);
				if (val > K) flag = false;
				vec.clear();
			}
		}
		if (flag == true) Answer += 1;
	}

	// Step #3. Output
	cout << Answer << endl;
	return 0;
}
```

`089-03.cpp` — Precomputes each right endpoint's leftmost valid block start by expanding leftward and counting inversions, then runs the partition DP.

```cpp
#include <iostream>
#include <vector>
using namespace std;

long long N, K, mod = 1000000007;
long long A[5009], cl[5009];
long long dp[5009];

int main() {
	// Step #1. Input
	cin >> N >> K;
	for (int i = 1; i <= N; i++) cin >> A[i];

	// Step #2. Maeshori
	for (int i = 1; i <= N; i++) {
		int cnt = 0;
		for (int j = i - 1; j >= 1; j--) {
			for (int k = j + 1; k <= i; k++) {
				if (A[j] > A[k]) cnt++;
				if (cnt > K) { cl[i] = j; break; }
			}
			if (cnt > K) break;
		}
	}

	// Step #3. DP
	dp[0] = 1;
	for (int i = 1; i <= N; i++) {
		for (int j = cl[i]; j < i; j++) {
			dp[i] += dp[j];
			dp[i] %= mod;
		}
	}
	cout << dp[N] << endl;
	return 0;
}
```

`089-04.cpp` — Precomputes valid block starts with a sliding window while maintaining inversion counts, then runs the partition DP.

```cpp
#include <iostream>
#include <vector>
using namespace std;

long long N, K, mod = 1000000007;
long long A[10009], cl[10009];
long long dp[10009];

int main() {
	// Step #1. Input
	cin >> N >> K;
	for (int i = 1; i <= N; i++) cin >> A[i];

	// Step #2. Maeshori
	long long l = N, cnt = 0;
	for (int r = N; r >= 1; r--) {
		while (l >= 1 && cnt <= K) {
			l--;
			for (int i = l + 1; i <= r; i++) { if (A[l] > A[i]) cnt++; }
		}
		cl[r] = l;
		for (int i = l; i <= r - 1; i++) { if (A[i] > A[r]) cnt--; }
	}

	// Step #3. DP
	dp[0] = 1;
	for (int i = 1; i <= N; i++) {
		for (int j = cl[i]; j < i; j++) {
			dp[i] += dp[j];
			dp[i] %= mod;
		}
	}
	cout << dp[N] << endl;
	return 0;
}
```

`089-05.cpp` — Coordinate-compresses the values, uses a BIT to precompute valid block starts, and runs a prefix-sum DP.

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

class BIT {
public:
	int size_ = 0;
	vector<long long> dat;
	
	void init(int sz) {
		size_ = sz + 2;
		dat.resize(size_ + 2, 0);
	}
	void add(int pos, long long x) {
		pos++;
		while (pos <= size_) {
			dat[pos] += x;
			pos += (pos & -pos);
		}
	}
	long long sum(int pos) {
		long long s = 0; pos++;
		while (pos >= 1) {
			s += dat[pos];
			pos -= (pos & -pos);
		}
		return s;
	}
};

long long N, K, mod = 1000000007;
long long A[1000009], cl[1000009];
long long dp[1000009], ru[1000009];
BIT Z;

int main() {
	// Step #1. Input
	cin >> N >> K;
	for (int i = 1; i <= N; i++) cin >> A[i];

	// Step #2. Coordinate Compression
	vector<long long> V;
	for (int i = 1; i <= N; i++) V.push_back(A[i]);
	sort(V.begin(), V.end());
	V.erase(unique(V.begin(), V.end()), V.end());
	for (int i = 1; i <= N; i++) A[i] = lower_bound(V.begin(), V.end(), A[i]) - V.begin();

	// Step #3. Maeshori
	long long l = N, cnt = 0;
	Z.init(V.size() + 2);
	Z.add(A[N], 1);
	for (int r = N; r >= 1; r--) {
		while (l >= 1 && cnt <= K) {
			l--;
			cnt += Z.sum(A[l] - 1);
			Z.add(A[l], 1);
		}
		Z.add(A[r], -1);
		cnt -= (Z.sum(V.size() + 1) - Z.sum(A[r]));
		cl[r] = l;
	}

	// Step #4. DP
	dp[0] = 1; ru[0] = 1;
	for (int i = 1; i <= N; i++) {
		if (cl[i] == 0) dp[i] = ru[i - 1];
		if (cl[i] >= 1) dp[i] = (ru[i - 1] - ru[cl[i] - 1] + mod) % mod;
		ru[i] = (ru[i - 1] + dp[i]) % mod;
	}
	cout << dp[N] << endl;
	return 0;
}
```
