# 047 — Monochromatic Diagonal (Monochromatic Down-Right Diagonals)

**Difficulty:** ★×7 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_au
**Source:** AtCoder Typical90 #047 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
{'R', 'G', 'B'} からなる長さ N の文字列 S, T が与えられます。
N×N マスの (i, j) 番目を次の規則で塗るとき、右下がりの斜めの列のうち、一色で塗られるものが何本あるか求めてください。
・S[i] と T[j] が同じ文字なら同じ色、違う文字ならどちらでもないほうの色で塗る


【制約】
・1 ≦ N ≦ 1000000
・S, T は {'R', 'G', 'B'} のみからなる長さ N の文字列

【小課題】
1. (2 点) N ≦ 2000
2. (5 点) 追加の制約はない
```

## Statement (English translation)
Strings S and T of length N consisting of {'R', 'G', 'B'} are given.
When the N×N cells (i, j) are painted according to the following rule, find how many of the down-right diagonals are painted in a single color.
- If S[i] and T[j] are the same character, paint the cell with that same color; if they are different, paint it with the color that is neither of the two.

## Constraints
```
【制約】
・1 ≦ N ≦ 1000000
・S, T は {'R', 'G', 'B'} のみからなる長さ N の文字列

【小課題】
1. (2 点) N ≦ 2000
2. (5 点) 追加の制約はない
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** P1 (subtask-1 slide): "3 種類" のものは 0・1・2 に置き換え (when there are only 3 kinds, relabel them 0/1/2). P2 (subtask-2 slide): 文字列一致判定はローリングハッシュ (testing string equality is a job for rolling hash).
- **Core idea:** Subtask 1 is the literal O(N²) grid: build F[i][j] exactly as the statement says and count the diagonals that use a single colour. For the full problem the key is that "diagonal k is entirely one colour" is a *string equality* statement: for red, cell (i, i+k) is red exactly in the three cases (s_i, t_{i+k}) = (R,R), (G,B), (B,G); relabelling t by swapping G and B turns this into s_i = t_{i+k} for every i. Doing that for each of the three colours and each of the 2N−1 diagonals leaves 3·(2N−1) substring-equality tests, each O(1) under rolling hash, so the whole thing is O(N).
- **Editorial steps:**
  - **Step 1 (P1 / subtask 1, O(N²)):** N ≤ 2000, so 「マス目 F[i][j] を問題文の通りに作ります」 and for every diagonal count how many of its cells are R, G, B; the diagonal is monochromatic iff two of the three counters are zero. Code: `for (int i = -(N-1); i <= (N-1); ++i) { int rcnt=0, gcnt=0, bcnt=0; for (int r = 0; r < N; ++r) { int c = r + i; if (0 <= c && c < N) { if (F[r][c]=='R') ++rcnt; if (F[r][c]=='G') ++gcnt; if (F[r][c]=='B') ++bcnt; } } if (rcnt==0 && gcnt==0) ++answer; if (gcnt==0 && bcnt==0) ++answer; if (bcnt==0 && rcnt==0) ++answer; }`, where i is the diagonal offset c − r. 「全体計算量は O(N²) です」.
  - **Step 2 (P1 / subtask 2 step 1 — turn "all red" into equality):** Fix an integer k with −N < k < N; the diagonal {(i, i+k)} is painted entirely red (R) iff for all i one of these holds: s_i = "R" and t_{i+k} = "R"; s_i = "G" and t_{i+k} = "B"; s_i = "B" and t_{i+k} = "G" (when the two letters differ the cell takes the third colour). Now replace G→B and B→G inside the string t; the three cases become s_i = "R" ∧ t_{i+k} = "R", s_i = "G" ∧ t_{i+k} = "G", s_i = "B" ∧ t_{i+k} = "B", so 「条件は「すべての i で s_i = t_{i+k}」と単純化されました！」. The same relabelling works for green and for blue: 「赤色だけでなく、緑色や青色に対しても、同様にできます」.
  - **Step 3 (P1 / subtask 2 step 1 — where the relabelling comes from):** The way to *find* it: 「R, G, B を 0, 1, 2 に置き換えるという典型的な発想」. Then 「斜め線が緑色（G）で塗られている条件が「すべて s_i + t_{i+k} = 2」と 1 つにまとめられ」 — because (G,G) = 1+1, (R,B) = 0+2, (B,R) = 2+0. This idea is also used in ARC 117-C「Tricolor Pyramid」.
  - **Step 4 (P1 / subtask 2 step 2 — which substrings to compare):** Collecting the tests: for k < 0 compare s_{−k+1} s_{−k+2} … s_n with t_1 t_2 … t_{n+k}; for k ≥ 0 compare s_1 s_2 … s_{n−k} with t_{k+1} t_{k+2} … t_n. 「つまり、文字列の一致判定をする必要があります。ここで、ローリングハッシュという方法を使います」.
  - **Step 5 (P2 — rolling hash definition):** For a length-L string X, hash(X) = (b^{L−1}·X_0 + b^{L−2}·X_1 + … + b^0·X_{L−1}) mod p, where b and p are free (p preferably prime) and the characters are read as integers such as ASCII codes; the useful property is that a substring hash is obtainable in constant time. Prefix hashes come out incrementally: h_0 = 0, h_k = (b·h_{k−1} + X_k) mod p. A substring hash then costs O(1) after precomputing powers: hash(s_i s_{i+1} … s_{r−1}) = (h_r − b^{r−i}·h_i) mod p.
  - **Step 6 (P2 — why that is enough, plus the warning):** With O(1) substring comparison 「各 k に対して定数時間で判定でき、全体計算量 O(N) で解けます」. Warning: 「ただし p = 2^64 とすると、どんな b を設定しても「ハッシュ衝突」を起こし WA するケースが作れるので、注意してください」. Alternative: 「他にも、Z-Algorithm を使った解法もあります」.
- **Complexity:** Subtask 1: O(N²). Subtask 2: O(N) — 3 colours × (2N−1) diagonals × O(1) hash comparisons, as stated. Memory: not stated on the slides.
- **Author's takeaway / typical pattern (典型):** Two transferable moves. (a) 「文字列 t を適切に置換することで、「斜め線がすべて赤色で塗られているか」の条件が単純化されました」 — permute/relabel one of the strings so a table of colour cases collapses into plain equality; the 0/1/2 relabelling compresses all three colours into one arithmetic condition. (b) 「文字列一致判定はローリングハッシュ」 — substring equality in O(1) after linear precomputation, which turns a per-diagonal O(N) scan into a constant-time test.
- **Related problems (類題):** AOJ 2444「Substring」, ABC 150-F「Xor Shift」, AOJ 2711「Nearly Cyclic String」 (listed on the rolling-hash slide); ARC 117-C「Tricolor Pyramid」 is named in the text of the first slide as the problem that uses the 0/1/2 relabelling.
- **Flags:** (1) Only the RED case is written out (and, in the 0/1/2 remark, only green's s_i + t_{i+k} = 2). The claims that must be re-derived: with R,G,B ↦ 0,1,2 the cell colour is determined by (s_i + t_{i+k}) mod 3 — red ≡ 0, blue ≡ 1, green ≡ 2 — so each colour class is one congruence. The two reference solutions use yet other encodings, so the convention must be pinned down in any re-derivation: `047-01.cpp` builds the third colour with `S[i]^T[j]^'R'^'G'^'B'` and counts two-counters-zero, while `047-02.cpp` never permutes t at all — it sets `seq2[j] = (i - seq3[j] + 3) % 3` for i = 0,1,2 and hashes `seq2` against reversed windows of `seq1`, i.e. it inverts the residue instead of relabelling. (2) The slide tests the three colours separately but never states that a monochromatic diagonal is counted exactly once — a diagonal of a single colour satisfies exactly one of the three per-colour conditions, which is why the subtask-1 code can increment `answer` three separate times; that uniqueness is worth checking. (3) The hash is only asserted to be safe with a prime p: no failure probability is given, only the warning that p = 2^64 is definitely breakable. With N ≤ 10^6 there are ≈6·10^6 comparisons, so a single modulus is a real (and adversarially attackable) risk; the reference uses the prime 699999953. Boundary: the base b must not be ≡ 0 or ≡ 1 (mod p), and the last character carries b^0. (4) Off-by-one: the diagonal index range is written 「−N < k < N」, i.e. −(N−1) … N−1 (2N−1 diagonals), and for k < 0 the comparison starts at s_{−k+1} (s treated as 1-indexed and extended to the left); a wrong clip silently drops or double-counts the corner diagonals. Boundary cases: N = 1 (a single cell) and the sample N = 3 with S = RRR, T = BBB → 5.

## Author's Reference Solution
`047-01.cpp`

```cpp
#include <string>
#include <vector>
#include <iostream>
using namespace std;
int main() {
	int N; string S, T;
	cin >> N >> S >> T;
	vector<string> F(N);
	for (int i = 0; i < N; ++i) {
		for (int j = 0; j < N; ++j) {
			if (S[i] == T[j]) {
				// color: same as S[i] and T[j]
				F[i] += S[i];
			}
			else {
				// color: different from S[i] and T[j]
				F[i] += (S[i] ^ T[j] ^ 'R' ^ 'G' ^ 'B');
			}
		}
	}
	int answer = 0;
	for (int i = -(N - 1); i <= (N - 1); ++i) {
		int rcnt = 0, gcnt = 0, bcnt = 0;
		for (int r = 0; r < N; ++r) {
			int c = r + i;
			if (0 <= c && c < N) {
				if (F[r][c] == 'R') ++rcnt;
				if (F[r][c] == 'G') ++gcnt;
				if (F[r][c] == 'B') ++bcnt;
			}
		}
		if (rcnt == 0 && gcnt == 0) ++answer;
		if (gcnt == 0 && bcnt == 0) ++answer;
		if (bcnt == 0 && rcnt == 0) ++answer;
	}
	cout << answer << endl;
	return 0;
}
```

`047-02.cpp`

```cpp
#include <string>
#include <vector>
#include <iostream>
using namespace std;
const int mod = 699999953; // large prime number
int main() {
	int N; string S, T;
	cin >> N >> S >> T;
	vector<int> seq1(N), seq3(N);
	for (int i = 0; i < N; ++i) {
		seq1[i] = (S[i] == 'R' ? 0 : (S[i] == 'G' ? 1 : 2));
		seq3[i] = (T[i] == 'R' ? 0 : (T[i] == 'G' ? 1 : 2));
	}
	int answer = 0;
	for (int i = 0; i < 3; ++i) {
		vector<int> seq2(N);
		for (int j = 0; j < N; ++j) {
			seq2[j] = (i - seq3[j] + 3) % 3;
		}
		int power3 = 1, hash1 = 0, hash2 = 0;
		for (int j = 0; j < N; ++j) {
			hash1 = (hash1 * 3 + seq1[j]) % mod;
			hash2 = (hash2 + power3 * seq2[N - j - 1]) % mod;
			if (hash1 == hash2) {
				++answer;
			}
			power3 = power3 * 3 % mod;
		}
		power3 = 1, hash1 = 0, hash2 = 0;
		for (int j = 0; j < N - 1; ++j) {
			hash1 = (hash1 + power3 * seq1[N - j - 1]) % mod;
			hash2 = (hash2 * 3 + seq2[j]) % mod;
			if (hash1 == hash2) {
				++answer;
			}
			power3 = power3 * 3 % mod;
		}
	}
	cout << answer << endl;
	return 0;
}
```
