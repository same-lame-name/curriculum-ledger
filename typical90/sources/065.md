# 065 — RGB Balls 2 (binomial counting with convolution)

## Statement (original Japanese)
```
赤色のボールが R 個、緑色のボールが G 個、青色のボールが B 個あります。それぞれのボールは、たとえ色が同じであっても互いに区別できます。
これらの R+G+B 個のボールから、以下の条件を全て満たしながら K 個のボールを選ぶことを考えます。

- 赤色・緑色のボールを合計 X 個以下選んでいる
- 緑色・青色のボールを合計 Y 個以下選んでいる
- 青色・赤色のボールを合計 Z 個以下選んでいる

このような K 個のボールの選び方は何通りあるでしょうか？
答えは非常に大きくなる可能性があるため、答えを 998244353 で割った余りを求めてください。
```

## Statement (English translation)
There are R red balls, G green balls, and B blue balls. Each ball is distinguishable from every other ball even if the colors are the same.
Consider choosing K balls from these R+G+B balls while satisfying all of the following conditions.

- You are choosing at most X red and green balls in total
- You are choosing at most Y green and blue balls in total
- You are choosing at most Z blue and red balls in total

How many ways are there to choose such K balls?
Since the answer can be very large, find the remainder of the answer divided by 998244353.

Subtasks
- Subtask 1 (3 points)
    - 1 ≦ R, G, B ≦ 5
    - 1 ≦ K ≦ min(5, R+G+B)
- Subtask 2 (2 points)
    - 1 ≦ R, G, B ≦ 3000
    - 1 ≦ K ≦ min(3000, R+G+B)
- Subtask 3 (2 points)
    - No additional constraints

【制約】
- 1 ≦ R, G, B ≦ 200000
- 1 ≦ K ≦ min(200000, R+G+B)
- 0 ≦ X ≦ min(K, R+G)
- 0 ≦ Y ≦ min(K, G+B)
- 0 ≦ Z ≦ min(K, B+R)

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** P1: 二項係数を使おう (use binomial coefficients). P2: 少ない方を考えると考察が進む場合がある (thinking about the smaller side can move the argument forward). P3: 畳み込みを知っていますか？ (do you know convolution?)
- **Core idea:** Fix how many balls of each colour are taken, (x, y, z) with x+y+z = K; for fixed counts the number of choices is the product of three binomial coefficients, so enumerating all such triples solves subtask 2 in O(K²). For the full score, use the fact that the total is exactly K to replace each "two colours ≤ limit" condition with a lower bound on the third colour; the answer then becomes a convolution of two arrays of binomial coefficients, evaluated with FFT (ACL `atcoder::convolution`) in O(K log K).
- **Editorial steps:**
  - **Step 1 (P1, 小課題 2 — count for fixed (x, y, z)):** If x red are chosen from A, y white from B and z blue from C, the number of ways is Answer = (A choose x) × (B choose y) × (C choose z), using (n choose r) = nCr = n!/(r!(n−r)!). Example on the slide: (A,B,C) = (5,4,4), (x,y,z) = (1,2,3) gives 5C1 × 4C2 × 4C3 = 5 × 6 × 4 = 120 (red 5C1 = 5, white 4C2 = 6, blue 4C3 = 4). With this sub-count known, "it is enough to brute-force all (x,y,z) with x+y+z = K" — O(K²) triples.
  - **Step 2 (P1 — nCr mod 998244353 in O(1) after precomputation):** (1) precompute fact[1..N] (the slide says: reduce 1,2,3,…,N modulo 998244353 and call them fact[1], fact[2], …, fact[N]); (2) compute 1/1!, 1/2!, …, 1/N! modulo 998244353 using modular inverses, stored as inv[1..N]; (3) nCr mod 998244353 = (fact[n] × inv[n−r] × inv[r]) % mod, with a warning about overflow. The inverse is justified by Fermat: for prime p, 1 ÷ a = a^(p−2) mod p (in general a ÷ b ≡ x when b·x ≡ 1 (mod p)), and a^(p−2) mod p is computed by repeated squaring (繰り返し二乗法). The slide states the total cost is O(K²), because the number of integer triples (x,y,z) with x+y+z = K is O(K²).
  - **Step 3 (P2, 満点解法 ステップ1 — turn a pair-sum bound into a one-colour bound):** A condition such as 赤・白の合計は lx 個以下 involves a sum of two variables and is awkward. Using that the total is K, it is equivalent to 青のボールは K − lx 個以上; likewise 白・青の合計は ly 個以下 ⇔ 赤のボールは K − ly 個以上, and 青・赤の合計は lz 個以下 ⇔ 白のボールは K − lz 個以上. The task becomes: each colour's count has a fixed lower bound (and upper bound = the stock), count the ways to take K balls in total. Worked instance on the slide: (A,B,C) = (5,5,6), K = 10, lx = 7, ly = 8, lz = 9 ⇒ blue ∈ [K−lx, C] = [3,6], red ∈ [K−ly, A] = [2,5], white ∈ [K−lz, B] = [1,5]. The named heuristic: look at the one colour that is NOT in the constrained pair rather than the pair (related notion: 余事象, the complement); when the number of objects violating a condition is far smaller than the number satisfying it, the former view is the productive one. The slide adds that this alone does not reach the full score.
  - **Step 4 (P3, 満点解法 ステップ2 — the answer as a convolution):** Define a_i = (A choose i) for K − ly ≤ i ≤ A and 0 otherwise; b_i = (B choose i) for K − lz ≤ i ≤ B and 0 otherwise; c_i = (C choose i) for K − lx ≤ i ≤ C and 0 otherwise. Then Answer = Σ_{i=0}^{A} Σ_{j=0}^{B} a_i b_j c_{K−i−j}. Put d_x = Σ_{i+j=x} a_i b_j (sum over all (i,j) with i+j = x); then Answer = Σ_{x=0}^{K} d_x c_{K−x}. d_0, …, d_2K are computed by the convolution on the next panel in O(K log K), so K ≤ 200000 is fast enough.
  - **Step 5 (P3 supplement — convolution and how to implement it):** Convolution problem: given A = (A_0,…,A_n) and B = (B_0,…,B_n), for every X form C_X = Σ_{i+j=X} A_i B_j over 0 ≤ i,j ≤ N, and output C_0,…,C_2N. Example on the slide: A = (8,6,9), B = (1,2,0) ⇒ (C_0,…,C_4) = (8×1, 8×2+6×1, 8×0+6×2+9×1, 6×0+9×2, 9×0) = (8, 22, 21, 18, 0). It is computable by the fast Fourier transform (FFT), and ACL's `atcoder::convolution` does it in O(N log N) without knowing FFT; the slide also recommends browsing the other ACL functions.
- **Complexity:** P1: O(K²) (subtask 2) — the number of triples (x,y,z) with x+y+z = K. P3: O(K log K) overall (「全体計算量 O(K log K)」), with the convolution O(K log K) and K ≤ 200000 fast enough. Memory not stated on the slides.
- **Author's takeaway / typical pattern (典型):** Three transferable moves: (i) when the objects chosen from each colour are independent given the counts, multiply binomial coefficients, and precompute factorials + inverses for O(1) nCr (the slide points to 「アルゴリズム・AtCoder のための数学 3-10. 節」); (ii) when a condition couples two variables, flip to the complementary single variable (余事象); (iii) when the answer is a nested sum indexed by i+j = const, recognise 畳み込み and hand it to FFT/ACL.
- **Related problems (類題):** P1: ABC034-C 「経路」, ABC145-D 「Knight」, ABC185-C 「Duodecim Ferra」, ABC021-D 「多重ループ」, ABC178-D 「Redistribution」. P2: ABC193-C 「Unexpressed」, ABC141-C 「Attack Survival」, ABC156-D 「Bouquet」, ARC119-B 「Electric Board」. P3: ATC001-C 「高速フーリエ変換」, ABC196-F 「Substring 2」, ABL F 「Heights and Pairs」, AOJ 2560 「Point Distance」.
- **Flags:** (1) The slides rename the problem data: the statement's colours are 赤/緑/青 with counts R, G, B, while the slides say 赤/白/青 with counts (A, B, C) and write the limits X, Y, Z as lx, ly, lz. (2) The double sum runs i = 0..A, j = 0..B although only i+j ≤ K can contribute; terms with K−i−j < 0 or > C need c zero-padded or skipped, which the slide's formula assumes silently (the reference code guards `if (0 <= K - i && K - i <= (int)p3.size())`). Likewise 「d_0, …, d_2K」 is loose: arrays of length A+1 and B+1 convolve to degree A+B, and only x ≤ K is ever used. (3) 「条件に当てはまらない方（1色）を考えると良い」 is offered as a heuristic; the ⇔ equivalences are valid only because the total is exactly K, which the slide states but does not prove step by step. (4) P1 is labelled 小課題 2 but the slide never says why O(K²) stops there: subtask 2 has K ≤ 3000, while subtask 3 allows K ≤ 200000 and needs P3. (5) Step 2's item 1 says to reduce 「1,2,3,…,N」 but calls the array fact[]; it means factorials, and the text is terse. (6) The stated O(K log K) omits the factorial precomputation (the reference's `init()` fills fact/inv up to 500000 unconditionally, although only binomials up to max(A,B,C) are used and only indices ≤ K are needed by the formulas).

## Author's Reference Solution
`065-01.cpp` — Subtask 1: enumerates all 2^(R+G+B) subsets of the distinguishable balls, counts each colour, and counts the subsets satisfying the three pair-sum limits and a total of K.

```cpp
#include <iostream>
#include <cassert>
using namespace std;

int R, G, B, K;
int X, Y, Z;

int main() {
	// Step #1. 入力・前処理
	cin >> R >> G >> B >> K;
	cin >> X >> Y >> Z;
	assert(R + G + B <= 15);

	// Step #2. bit 全探索
	int Answer = 0;
	for (int i = 0; i < (1 << (R + G + B)); i++) {
		int cntr = 0, cntg = 0, cntb = 0;
		for (int j = 0; j < R + G + B; j++) {
			if ((i & (1 << j)) == 0) continue;
			if (j < R) cntr += 1;
			else if (j < R + G) cntg += 1;
			else cntb += 1;
		}
		if (cntr + cntg <= X && cntg + cntb <= Y && cntb + cntr <= Z && cntr + cntg + cntb == K) {
			Answer += 1;
		}
	}

	// Srep #3. 出力
	cout << Answer << endl;
	return 0;
}
```

`065-02.cpp` — Subtask 2: precomputes factorials, modular inverses and binomial coefficients, then double-loops over the numbers of red and green balls, deriving the blue count from K and testing the three limits.

```cpp
#include <iostream>
using namespace std;

long long mod = 998244353;
long long fact[1 << 19], inv[1 << 19];

long long modpow(long long a, long long b, long long m) {
	long long p = 1, q = a;
	for (int i = 0; i < 32; i++) {
		if ((b & (1LL << i)) != 0LL) {
			p *= q; p %= m;
		}
		q *= q; q %= m;
	}
	return p;
}

long long Div(long long a, long long b, long long m) {
	return (a * modpow(b, m - 2, m)) % m;
}

long long ncr(long long n, long long r) {
	if (n < r || r < 0) return 0;
	return (fact[n] * inv[r] % mod) * inv[n - r] % mod;
}

void init() {
	fact[0] = 1LL;
	for (int i = 1; i <= 500000; i++) fact[i] = (1LL * i * fact[i - 1]) % mod;
	for (int i = 0; i <= 500000; i++) inv[i] = Div(1, fact[i], mod);
}

long long R, G, B, K;
long long X, Y, Z;
long long ar[1 << 19], ag[1 << 19], ab[1 << 19];

int main() {
	init();

	// Step #1. 入力
	cin >> R >> G >> B >> K;
	cin >> X >> Y >> Z;

	// Step #2. 前処理
	for (int i = 0; i <= R; i++) ar[i] = ncr(R, i);
	for (int i = 0; i <= G; i++) ag[i] = ncr(G, i);
	for (int i = 0; i <= B; i++) ab[i] = ncr(B, i);

	// Step #3. 全探索
	long long Answer = 0;
	for (int i = 0; i <= R; i++) {
		for (int j = 0; j <= G; j++) {
			int rem = K - i - j;
			if (rem < 0 || rem > B) continue;
			if (i + j > X || j + rem > Y || rem + i > Z) continue;
			Answer += (ar[i] * ag[j] % mod) * ab[rem] % mod;
			Answer %= mod;
		}
	}
	cout << Answer << endl;
	return 0;
}
```

`065-03.cpp` — Subtask 3: narrows each colour's count range using the limits, forms the binomial-coefficient arrays, multiplies two of them with `atcoder::convolution`, and sums over the blue count.

```cpp
#include <atcoder/all>
#include <iostream>
#include <vector>
using namespace std;

long long mod = 998244353;
long long fact[1 << 19], inv[1 << 19];

long long modpow(long long a, long long b, long long m) {
	long long p = 1, q = a;
	for (int i = 0; i < 32; i++) {
		if ((b & (1LL << i)) != 0LL) {
			p *= q; p %= m;
		}
		q *= q; q %= m;
	}
	return p;
}

long long Div(long long a, long long b, long long m) {
	return (a * modpow(b, m - 2, m)) % m;
}

long long ncr(long long n, long long r) {
	if (n < r || r < 0) return 0;
	return (fact[n] * inv[r] % mod) * inv[n - r] % mod;
}

void init() {
	fact[0] = 1LL;
	for (int i = 1; i <= 500000; i++) fact[i] = (1LL * i * fact[i - 1]) % mod;
	for (int i = 0; i <= 500000; i++) inv[i] = Div(1, fact[i], mod);
}

long long R, G, B, K;
long long X, Y, Z;
long long ar[1 << 19], ag[1 << 19], ab[1 << 19];

int main() {
	init();

	// Step #1. 入力
	cin >> R >> G >> B >> K;
	cin >> X >> Y >> Z;

	// Step #2. 前処理
	long long R_left = K - Y, R_right = R;
	long long G_left = K - Z, G_right = G;
	long long B_left = K - X, B_right = B;
	for (int i = 0; i <= R; i++) ar[i] = ncr(R, i);
	for (int i = 0; i <= G; i++) ag[i] = ncr(G, i);
	for (int i = 0; i <= B; i++) ab[i] = ncr(B, i);

	// Step #3. FFT
	vector<long long> p1(R + 1, 0), p2(G + 1, 0), p3;
	for (int i = R_left; i <= R_right; i++) p1[i] = ar[i];
	for (int i = G_left; i <= G_right; i++) p2[i] = ag[i];
	p3 = atcoder::convolution(p1, p2);

	// Step #4. 答えを求める
	long long Answer = 0;
	for (int i = B_left; i <= B_right; i++) {
		long long ret1 = 0, ret2 = ab[i];
		if (0 <= K - i && K - i <= (int)p3.size()) ret1 = p3[K - i];
		Answer += ret1 * ret2;
		Answer %= mod;
	}
	cout << Answer << endl;
	return 0;
}
```
