## Statement (English translation)
There are N cards, and the i-th card has a positive integer A[i] written on it.
E869120 and square each chose one or more cards from these cards.
The following is known about how the two chose their cards.
- The sums of the numbers written on the cards chosen by the two were equal.
- For each i = 1, 2, ..., Q, neither of the two chose both the X[i]-th card and the Y[i]-th card (at least one of the two was not chosen).
- The sets of cards chosen by the two were not equal.

Output one possible way for the two to have chosen their cards.

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** P1: 鳩ノ巣原理を活用しよう (put the pigeonhole principle to work). P2: DFS に慣れる (get used to DFS).
- **Core idea:** The sum of all cards is at most 8888, so any selection's total is one of only 8889 values (0 … 8888). Therefore, if we can list 8890 selections that each satisfy all Q conditions "at most one of X[i], Y[i] is taken", two of them must share the same total — and because they are different selections, that colliding pair is exactly a valid answer. The problem thus reduces to *enumerating many legal selections cheaply*, which a DFS probing cards in index order 1, 2, …, N does while maintaining one conflict counter per card.
- **Editorial steps:**
  - **Step 1 (P1, ステップ 1 — the pigeonhole property):** 鳩ノ巣原理 (pigeonhole principle): putting M+1 objects into M boxes always leaves a box holding at least 2 objects. The slide's everyday instances: among 5 people, two must share a blood type (4 types exist); among 367 people, two must share a birthday. Applied to this problem: a selection's total lives in [0, 8888], i.e. 8889 boxes, so 8890 enumerated selections force some box to hold two.
  - **Step 2 (P1 — the binning picture):** Bins are drawn as 総和 0, 総和 1, …, 総和 176, each row showing, in red, which of cards 1, 87, 88 are taken. Bin 0 contains nothing chosen (only the empty selection); bin 1 contains {1}; the bin labelled 総和 ??? contains two *different* selections, {1, 87} and {88}; the bottom bin 総和 176 contains {1, 87, 88}, i.e. every card. Footnote: because this example's total is 176, only boxes 0 … 176 need to be considered.
  - **Step 3 (P1, ステップ 2 — 上手くいかない方法, the approach that fails):** Randomization (乱択アルゴリズム, frequent in Heuristics-style contests): pick one of the 2^N subsets uniformly at random, keep it if it satisfies all Q conditions and has not been collected yet, and repeat until 8890 selections are gathered or about 2 seconds have passed. This collapses on the hard instance N = 88, Q = 44 with (X[i], Y[i]) = (1,2), (3,4), …, (87,88): each pair independently rules out 1 of its 4 take/leave combinations, so a random subset is legal with probability (3/4)^44 = 0.000003. At 10^8–10^9 operations per second only about 10^6 selections can be tried, which yields roughly 3 legal selections — nowhere near 8890.
  - **Step 4 (P2, ステップ 2 — 上手くいく方法, the approach that works):** Recursive exhaustive search (深さ優先探索, depth-first search; →典型 072). Rules: (1) decide cards in the order 1, 2, …, N; (2) from any state there are two branches — "do not take card i" (always allowed) and "take card i", the latter explored only while it still breaks no condition (marked (※)). Bookkeeping: keep an array c[t] = the number of indices i with Y[i] = t for which card X[i] has already been taken; card t may then be taken exactly when c[t] = 0. This works because X[i] < Y[i] always holds (noted on the slide as (注)), so each condition is examined once, at the moment its larger-index endpoint is decided. Store X[i] → Y[i] as the adjacency list of a directed graph (→典型 043): when card p is taken, add 1 to c[u] for every out-neighbour u of p, and subtract 1 again on backtracking. Trace shown in the figure: card 1 already taken leaves c = [0,0,1,1,0] (cards 3 and 4 already blocked, c[3] = c[4] = 1); taking card 2 touches exactly its out-neighbours 3 and 5, giving c = [0,0,2,1,1], after which cards 3 and 5 can no longer be used.
  - **Step 5 (P2 — why the search stays small):** Every state still keeps at least one completion, because taking none of the remaining cards obviously satisfies all conditions; hence a dead end — the ✗ branch in the search-tree figure, whose levels are 1枚目, 2枚目, 3枚目, 4枚目 and whose leaves are labelled 1, 2, 3 for the selections emitted — can never occur. Consequently at most T·N state transitions enumerate T selections: 8890 × 88 = 782,320 states, so the operation count is comfortably within AC. Footnote: cutting off a branch once it is certain to fail is called 枝刈り (pruning); known examples are A* and IDA*, used e.g. to solve the 15-puzzle.
- **Complexity:** O(N²·ΣA[i]) overall, as stated on P2 for combining the pigeonhole principle with the recursive DFS. The slide's concrete bound is 8890 × 88 = 782,320 state transitions (8890 sum boxes × N cards). Memory: Not stated on the slides.
- **Author's takeaway / typical pattern (典型):** (i) Pigeonhole as a counting reduction: when the number of possible "values" is small, a large pile of candidates necessarily repeats one — so "find two equal-something objects" becomes "enumerate a fixed number of candidates". (ii) DFS with an incrementally maintained counter array (via a directed adjacency list) so illegal branches are never entered, rather than checked afterwards. (iii) The slide's DFS repertoire: enumerate all patterns (→典型 072, 025), shortest paths on a tree (→典型 003), DP on a tree (→典型 039, 073), bipartite-graph testing and properties (→典型 026); understand DFS together with its relative 幅優先探索 (BFS). The pigeonhole principle is also tied to 典型 058: "there are only 10^5 states, so by the 10^5 + 1-th step periodicity must appear".
- **Related problems (類題):** ABC100-A 「Happy Birthday!」, ABC200-D 「Happy Birthday! 2」, 第一回日本最強プログラマー学生選手権決勝 A 「Equal Weight」. (Also referenced by number in the text: 典型 072, 025, 003, 039, 073, 026, 043, 058.)
- **Flags:** (1) The pigeonhole count needs *more legal selections than boxes*; the slide moves straight from "8889 boxes" to "enumerate 8890 selections" without showing that 8890 legal selections exist — for small N (e.g. N = 2, A = {1, 4444}: 3 selections, 4445 boxes; or N = 13: 2^13 = 8192 < 8890) it does not. The gap is closed only by the input guarantee 「条件を満たすカードの選び方が存在する」, which the slides never invoke — boundary to test. (2) Both people must take ≥ 1 card, yet the 2^N enumeration includes the empty set; this is harmless only because A[i] ≥ 1 makes box 0 contain solely ∅ (drawn as 総和 0 with nothing chosen), so a colliding pair can never be {∅, …} — asserted nowhere on the slides. (3) "Two colliding selections are distinct" is implicit; it holds only because the recursion branches binary on every card, so each subset is emitted exactly once — unproven on the slides. (4) Correctness of the single counter array rests on X[i] < Y[i], which the slide only parenthesises ((注)) instead of arguing that each condition is checked exactly once, when the larger endpoint is decided. (5) The bound 「T·N 個以内の状態遷移で T 通りの選び方を列挙できる」 is asserted from the one-line reason that no state is a dead end; the step from "no dead ends" to "at most T·N states" (stop at the first box holding two entries, each emitted selection lying on a path of ≤ N states) is not written out. (6) The stated O(N²·ΣA[i]) is looser than its own 8890 × 88 = O(N·ΣA[i]) state count; the extra factor N is unexplained (presumably the per-leaf O(N) list handling) — test at N = 88, ΣA[i] = 8888. (7) "About 10^6 selections in the time limit" is not derived from the quoted 10^8–10^9 operations/second (2 s would give 2·10^8–2·10^9 operations); it follows only if one candidate costs O(N) — terse, and only the single instance N = 88, Q = 44 is analysed.

## Author's Reference Solution
`088.cpp` — DFS over all card subsets, bucketing chosen sets by their total sum, then prints the first bucket containing two distinct sets.

```cpp
#include <iostream>
#include <vector>
using namespace std;

// Input
int N, A[10007];
int Q, X[10007], Y[10007];

// Other Variables
int c[10007];
vector<int> G[10007];
vector<int> vec;
vector<vector<int>> Answer[10007];
bool flag = false;

void dfs(int pos, int dep) {
	if (flag == true) return;
	if (pos == N + 1) {
		Answer[dep].push_back(vec);
		if (Answer[dep].size() == 2) flag = true;
		return;
	}

	// Don't Choose
	dfs(pos + 1, dep);

	// Choose
	if (c[pos] == 0) {
		vec.push_back(pos);
		for (int i : G[pos]) c[i]++;
		dfs(pos + 1, dep + A[pos]);
		for (int i : G[pos]) c[i]--;
		vec.pop_back();
	}
}

int main() {
	// Step #1. Input
	cin >> N >> Q;
	for (int i = 1; i <= N; i++) cin >> A[i];
	for (int i = 1; i <= Q; i++) cin >> X[i] >> Y[i];
	for (int i = 1; i <= Q; i++) G[X[i]].push_back(Y[i]);

	// Step #2. DFS
	dfs(1, 0);

	// Step #3. Output The Answer
	for (int i = 0; i <= 10000; i++) {
		if (Answer[i].size() <= 1) continue;
		cout << Answer[i][0].size() << endl; 
		for (int j = 0; j < Answer[i][0].size(); j++) { if (j != 0) cout << " "; cout << Answer[i][0][j]; } cout << endl;
		cout << Answer[i][1].size() << endl;
		for (int j = 0; j < Answer[i][1].size(); j++) { if (j != 0) cout << " "; cout << Answer[i][1][j]; } cout << endl;
		return 0;
	}
	return 0;
}
```
