# 030 — Count Numbers with at Least K Distinct Prime Factors

**Difficulty:** ★×5 (author's star rating)

## Statement (original Japanese)
2 以上 N 以下の整数のうち、K 種類以上の素因数を持つものの個数を求めてください。

## Statement (English translation)
Find the number of integers between 2 and N inclusive that have at least K distinct prime factors.

(The slide defines f(x) = [the number of distinct prime factors of x], with examples f(12) = 2 and f(30) = 3, and asks for the count of x with 2 ≦ x ≦ N and f(x) ≥ K.)

## Constraints
・2 ≦ N ≦ 10^7
・1 ≦ K ≦ 8
・入力はすべて整数

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 素因数列挙の計算量は O(N log log N)
- **Core idea:** Sieve-like counting: keep an array c[x] = number of distinct prime factors found so far. Scan i from 2 to N; if c[i] = 0 then i is prime, so add 1 to c[j] for every multiple j of i. After the sieve, c[x] is exactly the number of distinct prime factors of x; count x with c[x] ≥ K.
- **Editorial steps:**
  - The following method counts the number of prime factors. Here c_i records the number of distinct prime factors of i:
    1. Add 1 to c₂, c₄, c₆, c₈, c₁₀, … .
    2. Add 1 to c₃, c₆, c₉, c₁₂, c₁₅, … .
    3. Add 1 to c₅, c₁₀, c₁₅, c₂₀, c₂₅, … .
    4. Add 1 to c₇, c₁₄, c₂₁, c₂₈, c₃₅, … (and so on).
  - An implementation of this idea:
    ```cpp
    for (int i = 2; i <= N; i++) {
        if (c[i] != 0) continue; // 素数かどうか判定
        for (int j = i; j <= N; j += i) c[j] += 1;
    }
    ```
  - In fact the complexity of this method is O(N log log N), because the sum of the reciprocals of the primes is O(log log N). This is the same complexity analysis used for the sieve of Eratosthenes, so it is useful to know: 1/2 + 1/3 + 1/5 + 1/7 + 1/11 + 1/13 + … + 1/N = O(log log N).
  - Since the complexity analysis is difficult, a simple proof that it is O(N log N) is introduced. Let the number of operations be F(N); then F(N) < N(1/2 + 1/3 + 1/4 + 1/5 + … + 1/N). Because 1/1 + 1/2 + … + 1/N < (1 + ∫₁² (1/x) dx + ∫₂³ (1/x) dx + … + ∫_{N−1}^N (1/x) dx) = (1 + ∫₁^N (1/x) dx) = (1 + log N), F(N) is bounded above by O(N log N). A quantity expressed as 1/1 + 1/2 + 1/3 + … + 1/k is called the harmonic number, and its sum is O(log k). This property is also used in algorithms such as the divisor-enumeration algorithm.
- **Complexity:** O(N log log N) (the editorial notes the easier upper bound O(N log N))
- **Author's takeaway / typical pattern (典型):** This gives an O(N log log N) solution; even though N ≤ 10^7 is a large constraint, there is enough time to get AC. The related algorithms — the sieve of Eratosthenes and divisor enumeration — are frequent topics, so review them.
- **Related problems (類題):**
  - ABC177-E 「Coprime」
  - ABC084-D 「2017-like Number」
  - ABC152-E 「Flatten」
- **Flags:** The keyword says O(N log log N) while the boxed analysis only proves O(N log N); the editorial is explicit that the O(N log log N) bound is the true one and the O(N log N) proof is an easier substitute. Not inaccurate, just a softer bound.

## Author's Reference Solution
`030.cpp` — sieve over i = 2..N: if cnt[i] is still 0, i is prime, so increment cnt[j] for all multiples j; finally count i with cnt[i] ≥ K.

```cpp
#include <iostream>
using namespace std;

int N, K;
int cnt[1 << 24];

int main() {
	// Step #1. Input
	cin >> N >> K;

	// Step #2. Count Number
	for (int i = 2; i <= N; i++) {
		if (cnt[i] >= 1) continue;
		for (int j = i; j <= N; j += i) cnt[j] += 1;
	}

	// Step #3. Get Answer
	int Answer = 0;
	for (int i = 1; i <= N; i++) {
		if (cnt[i] >= K) Answer += 1;
	}
	cout << Answer << endl;
	return 0;
}
```
