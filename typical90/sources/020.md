## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 整数で処理して誤差をなくそう (do everything in integers to eliminate the error)
- **Core idea:** Comparing log2 a with b·log2 c in floating point can give the wrong verdict, because reals are stored approximately. Since log2 is monotone, log2 a < b log2 c ⇔ log2 a < log2(c^b) ⇔ a < c^b, so the question can be answered exactly by comparing the integers a and c^b, with c^b computed by a for loop.
- **Editorial steps:**
  - **Step 1 (the natural, wrong solution):** read A, B, C as long double and print Yes iff log2(A) < B * log2(C), else No — the slide's code is `if (log2(A) < B * log2(C)) cout << "Yes" << endl; else cout << "No" << endl;`.
  - **Step 2 (counterexample):** the case (a, b, c) = (8650415919381337932, 17, 13) gives WA.
  - **Step 3 (the experiment):** `printf("%.30Lf\n", log2(8650415919381337932.0L));` and `printf("%.30Lf\n", 17.0L * log2(13.0L));` both print 62.907475208398566726697431761295 — 「なんと同じ値になってしまいました」 — so the comparison sees them as equal and answers No, even though the true values differ (13^17 = 8650415919381337933 = a + 1, so the correct answer is Yes).
  - **Step 4 (why):** the two values are really different, yet they are judged equal because in the floating-point types (float, double, long double) the program handles real numbers approximately.
  - **Step 5 (the integer solution):** use log2 a < b log2 c ⇔ log2 a < log2(c^b) ⇔ a < c^b; the chain holds, so in the end it is enough to decide whether a < c^b, and c^b is computed with a for loop. Note that C++ has std::pow, but it is implemented internally with floating point, so it can still WA through error.
  - **Step 6 (general countermeasures):** when handling floating point, be aware that error can cause WA; the representative countermeasures are ・use long double rather than double, ・do all arithmetic in integers, ・treat values within eps as equal.
- **Complexity:** Not stated on the slides (the integer version is b multiplications, i.e. O(b)).
- **Author's takeaway / typical pattern (典型):** 「すべて整数で計算処理を行うと正解を出すことができます」 — doing the whole comparison in integers removes the error; when floating point is unavoidable, know the three standard countermeasures (long double, integers, eps).
- **Related problems (類題):** ABC169-C 「Multiplication 3」, PANASONIC2020-C 「Sqrt Inequality」, JOI 2013 春合宿 「JOI Poster」
- **Flags:** (1) The slide asserts the two log2 values are 「本来は違う値」 but never shows how far apart they are; the trace only works because 13^17 = 8650415919381337933 = a + 1, so the exact test a < c^b answers Yes while the floating-point test calls them equal and answers No — that gap is the claim the experiment supports, not a proof. (2) Computing c^b with a for loop is stated with no overflow caution: here 13^17 = 8650415919381337933 < 2^63, so a signed 64-bit integer just fits (the reference code relies on it), but nothing in the slide states that bound. (3) The boundaries a = 1 (so log2 a = 0) and c = 1 (c^b = 1, b·log2 1 = 0) are never tested or discussed. (4) The slide states no complexity, and the ⇔ chain silently uses the monotonicity of log2.

## Author's Reference Solution
`020.cpp` — Multiplies C exactly B times and prints Yes when A is smaller than the product, otherwise No.

```cpp
#include <iostream>
using namespace std;

long long A, B, C;
long long E = 1;

int main() {
	cin >> A >> B >> C;
	for (int i = 1; i <= B; i++) E *= C;
	if (A < E) cout << "Yes" << endl;
	else cout << "No" << endl;
	return 0;
}
```
