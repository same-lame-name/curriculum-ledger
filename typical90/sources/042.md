# 042 — Multiple of 9 (Divisible Digit Strings with Digit Sum K)

**Difficulty:** ★×4 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_ap
**Source:** AtCoder Typical90 #042 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
非負整数 N を 10 進法表記で表した時の各桁の数字の和を f(N) とします。

0 以外の数字のみを使ってかける非負整数 X のうち、以下の条件を満たすものが何通りあるかを求め、10^9 + 7 で割った余りを出力してください。
・X は 9 の倍数である
・f(X) = K


【制約】
・1 ≦ K ≦ 100000
・K は整数
```

## Statement (English translation)
Let f(N) denote the sum of the digits when the non-negative integer N is written in decimal notation.

Among the non-negative integers X that can be written using only non-zero digits, find the number of X satisfying both of the following conditions, and output it modulo 10^9 + 7:
- X is a multiple of 9.
- f(X) = K.

## Constraints
```
【制約】
・1 ≦ K ≦ 100000
・K は整数
```

## Samples
```
# 入力形式
K

----------

# 入力例 1
1

# 出力例 1
0

# 入力例 2
234

# 出力例 2
757186539
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 9 の倍数の性質 (the property of multiples of 9).
- **Core idea:** Since (N mod 9) equals (the digit sum of N mod 9), the condition "X is a multiple of 9" is exactly the condition "f(X) ≡ 0 (mod 9)". Because f(X) = K is fixed, the case K not divisible by 9 gives 0, and if 9 | K then every number whose digit sum is K is automatically a multiple of 9, so the answer is simply the number of positive integers with digit sum K — i.e. the number of ways to write K as an ordered sum of parts from 1 to 9.
- **Editorial steps:**
  - **Step 1 (the property of 9):** 「9」 has the following property: (N mod 9) = (N の各桁の数字の和 mod 9). (Footnote ※: mod 9 means "the remainder on division by 9"; for N = 589 the digit sum 5 + 8 + 9 = 22 has the same remainder on division by 9 as 589 itself.)
  - **Step 2 (case split):** The answer is therefore: ① if K is not a multiple of 9, the answer is 0 ways; ② if K is a multiple of 9, every 「各桁の数字の和が K となる整数」 is a multiple of 9, so the answer is the number of positive integers whose digit sum is K.
  - **Step 3 (the DP over the digit sum):** For case ② the answer is computed by a dynamic program over the array dp[各桁の数字の和] = number of ways. Stated precisely, as in the slide's sample code, for i = 1, 2, …, K in that order set dp[i] = dp[i − 1] + dp[i − 2] + … + dp[i − 9], and then dp[K] is the answer (essentially the value modulo 10^9 + 7 must be produced). The slide's code: `dp[0] = 1; for (int i = 1; i <= K; i++) { int B = min(i, 9); for (int j = 1; j <= B; j++) dp[i] += dp[i - j]; }`.
  - **Step 4 (why the recurrence holds):** The integers made only of the digits 1～9 whose digit sum is K split, according to the digit in the leading position, into the nine groups shown in the slide's figure: leading digit 1 with the remaining digits summing to K − 1, leading digit 2 with the remaining digits summing to K − 2, …, leading digit 9 with the remaining digits summing to K − 9. That classification is exactly the sum dp[i − 1] + … + dp[i − 9].
- **Complexity:** Not stated on the slides. The slide's double loop runs i = 1…K and j = 1…min(i, 9), i.e. at most 9 terms per state, so the derived bound is O(9K) = O(K). Memory also not stated on the slides (the reference code keeps a vector of size K + 1).
- **Author's takeaway / typical pattern (典型):** Various divisibility properties are used in various problems — memorize them all: 2 の倍数 = last digit 2, 4, 6, 8, 0; 3 の倍数 = digit sum divisible by 3; 4 の倍数 = last two digits divisible by 4; 5 の倍数 = last digit 0 or 5; 8 の倍数 = last three digits divisible by 8; 9 の倍数 = digit sum divisible by 9; 11 の倍数 = (sum of the digits in odd positions) − (sum of the digits in even positions) divisible by 11.
- **Related problems (類題):** ABC 182-C「To 3」(3 の倍数), ABC 181-D「Hachi」(8 の倍数), DDCC2020 予選 D「Digit Sum Replace」(9 の倍数), AOJ 2182「Eleven Lover」(11 の倍数) — each listed with the divisibility rule it uses.
- **Flags:** (1) The slide's code omits the modulus (`dp[i] += dp[i - j]` with no `% mod`) even though the text says 「本質は mod 10^9 + 7 を求める必要あり」 — copied literally it overflows, so the mod must be added. (2) The left panel writes dp[i] = dp[i−1] + … + dp[i−9] without the clamp; for i < 9 that would reference negative indices, so the code's `B = min(i, 9)` is the actual boundary and the formula is only shorthand. (3) Step ② silently relies on the statement's "only non-zero digits" restriction: every digit string over 1～9 is a valid X with no leading zero, which is why counting digit-sum-K strings costs nothing extra — the slide never says this, and under digits 0～9 it would be false. (4) The DP counts ordered compositions of K with parts 1～9 (the length of X varies), not fixed-length numbers; the slide's leading-digit figure is what makes that reading explicit. (5) Boundaries to test: K = 1 gives 0 (sample 1); K = 9 gives 2^8 = 256; and 9 | K is the only branch where any counting happens, so the `K % 9 == 0` gate is the whole of case ①.

## Author's Reference Solution
`042.cpp`

```cpp
#include <vector>
#include <iostream>
using namespace std;
const int mod = 1000000007;
int main() {
	int K;
	cin >> K;
	if (K % 9 == 0) {
		vector<int> dp(K + 1);
		dp[0] = 1;
		for (int i = 1; i <= K; ++i) {
			for (int j = i - 1; j >= i - 9 && j >= 0; --j) {
				dp[i] += dp[j];
				if (dp[i] >= mod) dp[i] -= mod;
			}
		}
		cout << dp[K] << endl;
	}
	else {
		cout << 0 << endl;
	}
	return 0;
}
```
