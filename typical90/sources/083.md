# 083 — Graph Vertex Coloring with Neighbor Recoloring Queries

**Difficulty:** ★×6 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_ce
**Source:** AtCoder Typical90 #083 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
N 頂点 M 辺の連結な単純無向グラフが与えられます。グラフの頂点は、それぞれ 1 から N までの番号が振られています。 i 番目の辺は、頂点 a[i] と b[i] を双方向に結んでいます。

10^9 種類の色があり、各色には 1 から 10^9 までの番号が振られています。最初、すべての頂点は色 1 で塗られています。

以下の形式のクエリが Q 個与えられるので、順に処理してください。

- 整数 x, y が与えられる。現在の頂点 x の色の番号を出力し、頂点 x とそれに隣接するすべての頂点を色 y で塗り替える。

## Statement (English translation)
You are given a connected simple undirected graph with N vertices and M edges. Vertices are numbered 1 to N. The i-th edge connects vertices a[i] and b[i] bidirectionally.

There are 10^9 colors, numbered 1 to 10^9. Initially every vertex is colored with color 1.

You are given Q queries of the following form, process them in order:

- Integers x, y are given. Print the current color number of vertex x, then recolor vertex x and all vertices adjacent to it with color y.

## Constraints
・1 ≦ N ≦ 2×10^5
・N-1 ≦ M ≦ min(N(N-1)/2, 2×10^5)
・1 ≦ a[i], b[i] ≦ N
・1 ≦ Q ≦ 2×10^5
・1 ≦ x ≦ N
・1 ≦ y ≦ 10^9
・与えられるグラフは単純グラフである
・与えられるグラフは連結
・入力はすべて整数

【小課題】
1. (2 点) N, Q ≦ 2000
2. (4 点) 追加の制約はない

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 「どんなケースで TLE するか」を考える (P1) ／ 適切に場合分けして処理 (P2) ／ 平方分割でゴリ押す (P3) ／ <別解> クエリ平方分割 (P4)
- **Core idea:** Naive simulation is O(NQ) and TLEs when a high-degree vertex is recolored repeatedly. The intended fix is square-root decomposition over vertices: a vertex of degree ≥ B is "large". For large vertices only their own color is updated lazily; for small vertices the colors of neighbors are updated directly. Querying a vertex's color takes the most recent update affecting it. An alternative square-root decomposition splits the Q queries into √Q blocks and recomputes per block.
- **Editorial steps:**
  - **小課題1:** N, M, Q ≦ 2000 なので愚直シミュレーション O(NQ) で間に合う。配列 c[i] に現在の頂点 i の色を管理し、隣接リストを使い、各クエリで c[x] を出力後、c[x] と隣接頂点 d_{x,1}, d_{x,2}, … を y に更新すれば良い（実装は 083-01.cpp）。
  - スターダイグラフ（頂点1の次数 N−1）では、各クエリが O(N) となり全体 O(NQ) で TLE する。「どうして TLE するのか？」を考えることは考察テクニックとして重要。
  - **満点解法 ステップ1:** 頂点1の場合と頂点1以外の場合に分けて考える。「頂点1」は、どのクエリでも色が塗り替えられるので、直前のクエリにおける y の値が答え。「頂点1以外」は、頂点 t (≧2) の色が塗り替えられるパターンは「x=1 のクエリが飛んでくる」「x=t のクエリが飛んでくる」の2通りしかない。それぞれのうち最も直前のクエリにおける y の値が答え。そこで「最後に x=t のクエリが飛んできたのはいつか」を表す配列 e[t] を用意すると、計算量 O(N+Q) で解ける。
  - **満点解法 ステップ2:** 頂点1の次数だけが非常に多く、他の頂点の次数は3以下というグラフに対して Q 個のクエリを処理する。x≠1 のクエリはステップ1と同様、「その時点で最後に x=t のクエリがあったのはいつか」を表す配列 e[t] を用意し、max(e[x], e[d_{x,1}], e[d_{x,2}], …) 番目のクエリで塗り替えられた色が答え。x=1 のクエリは「愚直に色を更新しなければ良い」——頂点1に限り色を更新すれば、各クエリの計算量は O(1) になる。全体 O(N+Q)。
  - **満点解法 ステップ3（平方分割）:** 一般のグラフでは、ある定数 B を決めて次数が B 以上の頂点を「大きい頂点」、B 未満の頂点を「小さい頂点」とする。大きい頂点はステップ2の x=1 の場合と同様に、愚直に色を更新していく。小さい頂点はステップ2の x≠1 の場合と同様に計算する。大きい頂点の個数は高々 2M/B、それらの色を愚直に更新する影響は Q×(2M/B)；小さい頂点の次数は B 以下なので e[t] の max を求める計算回数は Q×B。よって全体計算量は f(B)=Q×((2M/B)+B) となり、B=√(2M) で最小化され O(Q√M)。制約 N,M,Q ≦ 200000 で余裕を持って AC。
  - **別解（クエリ平方分割）:** クエリを √Q 個ごとに区切り、(処理1) あるクエリ時点での各頂点の色 c[1],…,c[N] が与えられたとき、そこから連続する √Q 個のクエリを一気に処理する、(処理2) √Q 個のクエリが全部終わった後の各頂点の色を求める、を交互に行う。処理1は「x≠1 のとき」と同様に最後に x=t のクエリが来たのは何番目かを表す配列 e[t] を使い、頂点 i の色は max(e[i], e[d_{i,1}], e[d_{i,2}], …) 番目のクエリで指定された色（次数の合計は 2M なので O(M)）。処理2は O(M)。全体 O((Q+M)√Q)。実装は 083-02b.cpp。
- **Complexity:** 満点解法 O(Q√M)（別解のクエリ平方分割は O((Q+M)√Q)）
- **Author's takeaway / typical pattern (典型):** 「どうして TLE するのか？」を考えることは、コンテストでペナルティを出さないだけでなく、考察テクニックとしても重要。実際、TLE する代表的なケースに対する解法を考えることで、元の問題の解法が見えてくることが少なくない。√M のような適切な定数で分けることで解くアルゴリズムを平方分割といい、素因数分解の計算量解析 (典型075) やバケット法にも応用できる。別解のクエリ平方分割はデータ構造を上手く扱えないクエリ処理問題などに利用でき、関連話題として Mo's Algorithm がある。

## Author's Reference Solution
`083-01.cpp` — Subtask 1 only: naive simulation, O(NQ); maintains color array and updates vertex + neighbors each query.

```cpp
#include <vector>
#include <iostream>
using namespace std;
int main() {
	int N, M, Q;
	cin >> N >> M;
	vector<vector<int> > G(N);
	for (int i = 0; i < M; ++i) {
		int a, b;
		cin >> a >> b; --a, --b;
		G[a].push_back(b);
		G[b].push_back(a);
	}
	cin >> Q;
	vector<int> col(N, 1);
	for (int i = 0; i < Q; ++i) {
		int x, y;
		cin >> x >> y; --x;
		cout << col[x] << endl;
		col[x] = y;
		for (int j : G[x]) {
			col[j] = y;
		}
	}
	return 0;
}
```

`083-02a.cpp` — Full solution via vertex square-root decomposition: precomputes "large" vertices (degree ≥ √(2M)), stores link flags, keeps last-update timestamps for vertices and for large vertices; O(Q√M).

```cpp
#include <cmath>
#include <vector>
#include <iostream>
#include <algorithm>
using namespace std;
int main() {
	int N, M, Q;
	cin >> N >> M;
	vector<vector<int> > G(N);
	for (int i = 0; i < M; ++i) {
		int a, b;
		cin >> a >> b; --a, --b;
		G[a].push_back(b);
		G[b].push_back(a);
	}
	cin >> Q;
	vector<int> x(Q), y(Q);
	for (int i = 0; i < Q; ++i) {
		cin >> x[i] >> y[i]; --x[i];
	}
	int B = int(sqrt(2 * M));
	vector<int> large;
	for (int i = 0; i < N; ++i) {
		if (G[i].size() >= B) {
			large.push_back(i);
		}
	}
	vector<vector<bool> > link(N, vector<bool>(large.size(), false));
	for (int i = 0; i < large.size(); ++i) {
		for (int j : G[large[i]]) {
			link[j][i] = true;
		}
		link[large[i]][i] = true;
	}
	vector<int> update(N, -1);
	vector<int> update_large(large.size(), -1);
	for (int i = 0; i < Q; ++i) {
		int last = update[x[i]];
		for (int j = 0; j < large.size(); ++j) {
			if (link[x[i]][j]) {
				last = max(last, update_large[j]);
			}
		}
		cout << (last != -1 ? y[last] : 1) << endl;
		if (G[x[i]].size() < B) {
			update[x[i]] = i;
			for (int j : G[x[i]]) {
				update[j] = i;
			}
		}
		else {
			int ptr = find(large.begin(), large.end(), x[i]) - large.begin();
			update_large[ptr] = i;
		}
	}
	return 0;
}
```

`083-02b.cpp` — Alternative: query square-root decomposition; processes queries in blocks of √Q, within a block resolving colors by scanning earlier queries in the block, then commits block results to the color array; O((Q+M)√Q).

```cpp
#include <cmath>
#include <vector>
#include <iostream>
#include <algorithm>
using namespace std;
int main() {
	int N, M, Q;
	cin >> N >> M;
	vector<vector<int> > G(N);
	for (int i = 0; i < M; ++i) {
		int a, b;
		cin >> a >> b; --a, --b;
		G[a].push_back(b);
		G[b].push_back(a);
	}
	cin >> Q;
	vector<int> x(Q), y(Q);
	for (int i = 0; i < Q; ++i) {
		cin >> x[i] >> y[i]; --x[i];
	}
	for (int i = 0; i < N; ++i) {
		sort(G[i].begin(), G[i].end());
	}
	vector<int> col(N, 1);
	int B = int(sqrt(Q));
	for (int i = 0; i < B; ++i) {
		int ql = i * Q / B, qr = (i + 1) * Q / B;
		for (int j = ql; j < qr; ++j) {
			int current_col = col[x[j]];
			for (int k = ql; k < j; ++k) {
				if (x[j] == x[k] || binary_search(G[x[k]].begin(), G[x[k]].end(), x[j])) {
					current_col = y[k];
				}
			}
			cout << current_col << endl;
		}
		for (int j = ql; j < qr; ++j) {
			bool update = true;
			for (int k = j + 1; k < qr; ++k) {
				if (x[k] == x[j]) {
					update = false;
				}
			}
			if (update) {
				col[x[j]] = y[j];
				for (int k : G[x[j]]) {
					col[k] = y[j];
				}
			}
		}
	}
	return 0;
}
```
