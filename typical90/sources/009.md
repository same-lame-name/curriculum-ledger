# 009 — Three Point Angle (Angular Sweep per Pivot)

**Difficulty:** ★×6 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_i
**Source:** AtCoder Typical90 #009 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
二次元平面上に N 個の点が存在し、点 i は座標 (X_i, Y_i) にあります。
あなたは相異なる 3 つの整数 A, B, C (1 ≦ A, B, C ≦ N) を選び、角 ABC (点 A → 点 B → 点 C の折れ線で構成される角) の大きさを最大にしたいです。
そのときの角の大きさを 0 ～ 180 度の範囲で表される度数法で出力してください。
```

## Statement (English translation)
There are N points on the two-dimensional plane, and point i is at coordinates (X_i, Y_i).
You choose three distinct integers A, B, C (1 ≦ A, B, C ≦ N), and you want to maximize the size of angle ABC (the angle formed by the polyline point A → point B → point C).
Output the size of the angle at that time in degrees, expressed in the range of 0 to 180 degrees.

## Constraints
```
【制約】
・3 ≦ N ≦ 2000
・0 ≦ X[i], Y[i] ≦ 10^9
・(X[i], Y[i]) ≠ (X[j], Y[j])
・入力はすべて整数
・絶対誤差または相対誤差が 10^{-8} 以内であれば正解とみなされる
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 真ん中決め打ち ＋ 偏角ソート (fix the middle vertex, then sort by polar angle)
- **Core idea:** Fix the middle point B of A, B, C and regard it as the origin. With t1, t2 the polar angles of A and C, the angle reduces to the closed form min(|t1 − t2|, 360° − |t1 − t2|), which is why fixing B is convenient. For a fixed A the angle grows as C approaches t1 + 180° (mod 360), so sort the other points by polar angle and binary-search the entry closest to that target. Trying every B gives O(N² log N).
- **Editorial steps:**
  - **Step 1 (fix the middle):** enumerate which of A, B, C is the middle point — B. The slide calls 「3 つある場合 2 つを固定するテクニック」 (fixing two of three) a typical technique. With B as the origin, the angle at B is written as min(|t1 − t2|, 360° − |t1 − t2|), a simple formula, which is the payoff.
  - **Step 2 (the picture):** five points surround B at polar angles 40°, 125°, 180°, 250°, 300°; the shaded red wedge at B is the angle being maximised.
  - **Step 3 (where the best C is):** ・if A is point 1, whose polar angle is 40°, then C is better the closer its polar angle is to the opposite 220°; ・if A is point 5, whose polar angle is 300°, then C is better the closer it is to the opposite 120°. In general, when A has polar angle t degrees, the angle at B grows as C's polar angle approaches (t + 180) mod 360 degrees.
  - **Step 4 (find that C by binary search):** the point C closest to that target is located with the 二分探索 / `std::lower_bound` element search introduced in problem 007, in O(log N).
  - **Step 5 (total):** polar-angle sort plus binary search for every pivot → O(N² log N).
- **Complexity:** O(N² log N) — 「偏角ソートと二分探索を用いることで、全体計算量 O(N^2 log N) でこの問題を解くことができました」. Memory not stated on the slides.
- **Author's takeaway / typical pattern (典型):** 偏角ソート (sorting by polar angle) combined with binary search; the polar angles themselves are computed with trigonometry — in C++ by `atan2(y, x) * 180 / 3.1415926...`.
- **Related problems (類題):** JOI2016-本選2 「スタンプラリー」（真ん中固定）, ABC033-D 「三角形の分類」, ABC139-F 「Engines」, yukicoder No.1144 「Triangles」
- **Flags:** (1) 「点 C の偏角が (t + 180) mod 360 度に近いほど角が大きくなる」 is asserted from two examples, not proved (it is the maximisation of min(|Δ|, 360 − |Δ|) over a discrete set of angles). (2) The slide says only that binary search finds C, but the sorted angle array is circular, so the candidates are the two entries around the target with wrap-around (the reference code checks `pos1 % size` and `(pos1 + size - 1) % size`); the wrap and the array-end boundaries are the places to test. (3) Degenerate configurations are not discussed: two points with the same polar angle as seen from B, or A, B, C collinear, give 0° or 180°, and the statement's 10^-8 tolerance and 0…180 output range are never mentioned on the slide. (4) The slide's 300° example calls 120° 「反対」 — 300 + 180 = 480 ≡ 120 ✓ — but the step from that to the binary search is intuitive rather than justified.

## Author's Reference Solution
`009.cpp` — For each point taken as the pivot B, sorts the other points by polar angle, binary-searches for each angle the candidate closest to angle + 180° (checking it and its predecessor), keeps the maximum, and prints it with 12 decimals.

```cpp
#include <iostream>
#include <cmath>
#include <vector>
#include <algorithm>
using namespace std;

struct Point {
	double px, py;
};

Point operator-(const Point& a1, const Point& a2) {
	return Point{ a1.px - a2.px, a1.py - a2.py };
}

double getangle(Point G) {
	// 点 G の偏角を求める
	if (G.py >= 0.0) {
		double I = G.px / sqrt(G.px * G.px + G.py * G.py);
		double kaku = acos(I) * 180.0 / 3.14159265358979;
		return kaku;
	}
	else {
		double I = G.px / sqrt(G.px * G.px + G.py * G.py);
		double kaku = acos(I) * 180.0 / 3.14159265358979;
		return 360.0 - kaku;
	}
}

double getangle2(double I1, double I2) {
	// [偏角 I1] - [原点] - [偏角 I2] のなす角度を求める
	// 例えば I1 = 240°、I2 = 30°のとき、求める角度は 150°
	double res = abs(I1 - I2);
	if (res >= 180.0) return 360.0 - res;
	return res;
}

int N;
Point G[2009];

double solve(int pos) {
	// 最初に偏角の昇順にソートする
	vector<double> vec;
	for (int i = 1; i <= N; i++) {
		if (i == pos) continue;
		Point SA = G[i] - G[pos];
		double angle = getangle(SA);
		vec.push_back(angle);
	}
	sort(vec.begin(), vec.end());

	// 点 A を全探索して、最も偏角の大きくなる点 C を二分探索（std::lower_bound）で求める
	double ret = 0.0;
	for (int i = 0; i < vec.size(); i++) {
		double target = vec[i] + 180.0;
		if (target >= 360.0) target -= 360.0;
		int pos1 = lower_bound(vec.begin(), vec.end(), target) - vec.begin();

		// 点 C の候補は高々 2 つに絞れる
		int CandIdx1 = pos1 % vec.size();
		int CandIdx2 = (pos1 + vec.size() - 1) % vec.size();
		double Candidate1 = getangle2(vec[i], vec[CandIdx1]);
		double Candidate2 = getangle2(vec[i], vec[CandIdx2]);
		ret = max({ ret, Candidate1, Candidate2 });
	}
	return ret;
}

// O(N^3) のアルゴリズム（点 A, B, C を全探索）
double solve_Slow() {
	double Answer = 0.0;
	for (int i = 1; i <= N; i++) {
		for (int j = 1; j <= N; j++) {
			for (int k = 1; k <= N; k++) {
				if (i == j || i == k || j == k) continue;
				double I1 = getangle(G[i] - G[j]);
				double I2 = getangle(G[k] - G[j]);
				Answer = max(Answer, getangle2(I1, I2));
			}
		}
	}
	return Answer;
}

// O(N^2 log N) のアルゴリズム
double solve_Fast() {
	// 点 B を全探索
	double Answer = 0.0;
	for (int i = 1; i <= N; i++) {
		double ret = solve(i);
		Answer = max(Answer, ret);
	}
	return Answer;
}

int main() {
	// Step #1. 入力
	cin >> N;
	for (int i = 1; i <= N; i++) {
		cin >> G[i].px >> G[i].py;
	}

	// Step #2. 出力
	double FinalAns = solve_Fast();
	printf("%.12lf\n", FinalAns);
	return 0;
}
```
