# 024 — Can A Be Made Equal to B in Exactly K Operations?

**Difficulty:** ★×1 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_x
**Source:** AtCoder Typical90 #024 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
長さ N の正整数列 A = (A[1], A[2], ..., A[N]) および B = (B[1], B[2], ..., B[N]) が与えられます。
次の操作をちょうど K 回行うことで A を B に一致させることができるか判定してください。
操作：1 ≦ i ≦ N を満たす i をひとつ選び、A[i] を A[i]-1 または A[i]+1 に置き換える

## Statement (English translation)
You are given length-N sequences of positive integers A = (A[1], A[2], ..., A[N]) and B = (B[1], B[2], ..., B[N]).
Determine whether A can be made to coincide with B by performing the following operation exactly K times.
Operation: choose one i with 1 ≦ i ≦ N, and replace A[i] by A[i]−1 or A[i]+1.

(The slide adds: "ただし、操作の途中で数列の値を 0 以下にすることも許されます。" — "However, it is also permitted to make a value in the sequence 0 or less during the operations.")

## Constraints
・1 ≦ N ≦ 1000
・1 ≦ K ≦ 10^9
・1 ≦ A[i], B[i] ≦ 10^6
・入力はすべて整数

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** パリティを考える
- **Core idea:** Moving one element by one step costs one operation, so the minimum number of operations is Diff = Σ|A[i] − B[i]|. If Diff > K it is impossible. Otherwise we need to "waste" the extra K − Diff operations; each wasted pair of moves adds 2, so the parity of K must equal the parity of Diff. These two conditions are also sufficient.
- **Editorial steps:**
  - First consider N = 1. "Can we change the integer A to B in exactly K operations?" (each operation adds or subtracts 1). Looking at the transitions, each operation flips an even number to odd and an odd number to even. This shows the goal can be achieved iff both of the following two conditions hold:
    - 条件 1: |B − A| is at most K.
    - 条件 2: If K is even, A and B have the same parity; if K is odd, A and B have different parity.
  - The same reasoning works for N values, because the total sum goes even → odd → even → odd → … alternating with each operation.
  - To turn A into B, at least |A₁ − B₁| + |A₂ − B₂| + … + |A_N − B_N| operations are necessary. On that premise, judge whether the parity of the total is "realizable".
- **Complexity:** not stated explicitly; O(N).
- **Author's takeaway / typical pattern (典型):** The property "even or odd" is called parity (偶奇性). Problems solvable by considering parity appear frequently in competitive programming and are a typical mathematical-reasoning pattern.
- **Related problems (類題):**
  - ABC086-C 「Traveling」
  - AGC002-A 「Range Product」
  - AGC020-A 「Move and Win」
- **Flags:** none. (The statement of the two conditions is stated for N = 1 first, then extended; the editorial glosses over why the conditions are sufficient, but the code makes it clear.)

## Author's Reference Solution
`024.cpp` — compute Diff = Σ|A[i] − B[i]|; output "No" if Diff > K or if Diff % 2 ≠ K % 2, otherwise "Yes".

```cpp
#include <iostream>
#include <cmath>
using namespace std;

long long N, K;
long long A[1 << 18], B[1 << 18];

int main() {
	// Step #1. Input
	cin >> N >> K;
	for (int i = 1; i <= N; i++) cin >> A[i];
	for (int i = 1; i <= N; i++) cin >> B[i];

	// Step #2. Check Difference
	long long Diff = 0;
	for (int i = 1; i <= N; i++) Diff += abs(A[i] - B[i]);
	if (Diff > K) {
		cout << "No" << endl;
		return 0;
	}

	// Step #3. Check Parity
	if (Diff % 2 != K % 2) {
		cout << "No" << endl;
		return 0;
	}

	// Step #4. Output Yes
	cout << "Yes" << endl;
	return 0;
}
```
