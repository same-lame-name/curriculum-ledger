# 048 — I will not drop out (Partial vs Full Marks under a Time Budget)

**Difficulty:** ★×3 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_av
**Source:** AtCoder Typical90 #048 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
N 問からなる試験があります。i 番目の問題は満点が A[i] 点、部分点が B[i] 点です。
ここで、部分点は満点より小さく満点の半分より大きいです。つまり A[i]/2 < B[i] < A[i] を満たします。

E869120 君はどの問題についても 1 分かけると部分点を取ることができ、さらに 1 分かけると満点を取ることができます。
試験時間 K 分間で E869120 君が得られる合計得点の最大値を求めてください。

【制約】
・1 ≦ N ≦ 2 × 10^5
・1 ≦ K ≦ 2N
・3 ≦ A[i] ≦ 10^9
・A[i]/2 < B[i] < A[i]
・入力は全て整数
```

## Statement (English translation)
There are N exam problems. The i-th problem has A[i] full marks and B[i] partial marks.
Here, the partial marks are less than the full marks and greater than half of the full marks; that is, A[i]/2 < B[i] < A[i].

For any problem, E869120 can earn the partial marks by spending 1 minute, and can then earn the full marks by spending 1 more minute.
Find the maximum total score E869120 can obtain during the K-minute exam.

## Constraints
```
【制約】
・1 ≦ N ≦ 2 × 10^5
・1 ≦ K ≦ 2N
・3 ≦ A[i] ≦ 10^9
・A[i]/2 < B[i] < A[i]
・入力は全て整数
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 上界と下界を見積もる (estimate an upper bound and a lower bound)
- **Core idea:** Each minute is exactly one of two moves — 手段X i = solve a not-yet-started problem for B_i points, 手段Y i = upgrade an already-partially-solved problem for A_i − B_i points — so there are only 2N moves with values [B_1, …, B_N, A_1−B_1, …, A_N−B_N], each usable once, and K minutes buy K of them. Step 1: no strategy can beat the sum of the K largest values (the upper bound). Step 2: taking the K largest *is* realizable, because a 手段Y move is legal when its turn comes: A_i/2 < B_i gives B_i > A_i − B_i, so B_i is itself among the larger values and was taken earlier. Hence the answer is simply the sum of the K largest of the 2N values, obtained by sorting.
- **Editorial steps:**
  - **Step 1 (the upper bound):** 「まず、「これ以上の答えが絶対あり得ない」ような上界値を考えてみましょう。1 分を使うことで、以下のうちいずれかの手段が選べます。」 ● 手段 X の i: まだ部分点を取っていない問題を解き、B_i 点を得る. ● 手段 Y の i: 部分点を取った問題で満点を取り、A_i − B_i 点を得る. 「そして、同じ手段を二度選べないので、2N 個の手段で得られる点数 [B_1, B_2, …, B_N, A_1−B_1, A_2−B_2, …, A_N−B_N] を降順にソートして 1〜K 番目の要素を足した得点を超えることはできません。（上界を見積もる）」 Numeric example: K = 3 with A = (4, 9, 15, 8), B = (3, 5, 8, 6); the 2N values are +3, +5, +8, +6 (partial marks) and +1, +4, +7, +2 (upgrades), so the top three are 8, 7, 6 and the bound is 8 + 7 + 6 = 21 (the table highlights the +8 and +6 partials and the +7 upgrade of problem 3).
  - **Step 2 (the bound is attained by greedy):** 「次に、上界値を達成する方法について考えてみましょう。実は、「今選べる手段の中で、最も多くの得点を取れるものを選ぶ」といった感じで貪欲に選ぶと、実は合計得点がそのまま上界値になるのです」 — verified on several cases, then proven: 「【証明】n 回目に「全体で n 番目に大きい点数を得る手段を選ぶ」ことができるから。」 【1】n = 1 のとき：明らか. 【2】n ≥ 2 のとき（k = 1, 2, …, n−1 で成り立つと仮定する）：まず全体で n 番目の点数が得られるものが部分点だった場合明らかに選べる。満点の場合でも、(B_i > A_i − B_i であるため) n−1 回目までにその問題の部分点が取られているので、選ぶことができる.
  - **Step 3 (implementation):** 「最後に、数列のソートは std::sort などを使って O(N log N) で行えます」 — put the 2N values in one array, sort descending, sum the first K.
- **Complexity:** O(N log N), as stated (「全体計算量 O(N log N) でこの問題を解くことができます」). Memory: not stated on the slides (an array of 2N values).
- **Author's takeaway / typical pattern (典型):** The two-step pattern 「上界を見積もった後、実際に上界となる答えや方法を構成する」 — bound first, construction second — is what makes the problem collapse to sorting in O(N log N); once the bound is the sum of the K largest, "greedy = take the sorted top K" is immediate.
- **Related problems (類題):** ABC 141-D「Powerful Discount Tickets」, ARC 115-C「N Coloring」, ARC 119-B「Electric Board」, JOI 2017 本選 2「準急電車」
- **Flags:** (1) The induction is compressed into two lines and its whole load sits in one parenthetical: 「満点の場合でも、(B_i > A_i − B_i であるため) n−1 回目までにその問題の部分点が取られているので、選ぶことができる」. The claim being used is: if A_i − B_i is among the top n values then B_i is too (because B_i > A_i − B_i), so 手段X i has already been chosen. That is exactly where the constraint A_i/2 < B_i earns its keep, and it is never spelled out. Boundary to test: drop B_i > A_i/2 — e.g. N = 1, K = 1, A = 10, B = 3 gives values 3 and 7; the top-1 sum is 7 but 7 is unreachable in one minute, so the "sum of the top K" formula breaks. That is the constraint's real role. (2) Ties among the 2N values are never discussed, although the legality argument silently assumes any order among equal values is fine. (3) All values are positive (B_i > A_i/2 ≥ 1.5 and A_i − B_i > 0), so wasting a minute never helps — true, but never said. (4) Overflow: the answer can reach 2·10^5 × 10^9 = 2·10^14, so 64-bit accumulation is required and is not mentioned (the reference uses `long long`); boundary N = 2·10^5, K = 2N, all A_i = 10^9. (5) The statement's K ≤ 2N is what makes "the K largest of 2N values" well defined; K = 2N (everything fully solved) is the extreme case to test.

## Author's Reference Solution
`048.cpp`

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

long long N, K, A[1 << 18], B[1 << 18];
vector<long long> vec;

int main() {
	// Step #1. 入力など
	cin >> N >> K;
	for (int i = 1; i <= N; i++) {
		cin >> A[i] >> B[i];
		vec.push_back(B[i]);
		vec.push_back(A[i] - B[i]);
	}

	// Step #2. 答えを求める
	long long Answer = 0;
	sort(vec.begin(), vec.end());
	reverse(vec.begin(), vec.end());
	for (int i = 0; i < K; i++) Answer += vec[i];

	// Step #3. 出力
	cout << Answer << endl;
	return 0;
}
```
