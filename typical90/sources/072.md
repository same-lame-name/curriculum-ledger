# 072 — Longest simple cycle in a grid avoiding mountain cells

**Difficulty:** ★×4 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_bt
**Source:** AtCoder Typical90 #072 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
ABC 王国は H 行 W 列のマス目で表されます。各マスは山のマスと平野のマスのどちらかです。上から i 行目、左から j 列目にあるマスが山のマスなら c[i][j] は '#'、平野のマスなら c[i][j] は '.' です。

あなたは鉄道路線をすべて作りたいです。鉄道路線の経路は、以下の条件をすべて満たす必要があります。
[条件 1]　あるマスを始点とし、辺を共有して隣接するマスに移動することを k 回 (3 ≦ k) 繰り返し、始点で終わる経路である。
[条件 2]　 k 回の移動について、移動先は相異なる。（始点と終点は一致してよい）
[条件 3]　山のマスを通らない。

この鉄道路線が通るマスの数の最大値を求めてください。条件を満たす鉄道路線がない場合は、代わりにそれを報告してください。

## Statement (English translation)
The ABC Kingdom is represented by an H-row, W-column grid. Each cell is either a mountain cell or a plain cell. If the cell at row i from the top and column j from the left is a mountain cell then c[i][j] is '#', and if it is a plain cell then c[i][j] is '.'.

You want to build every railway line. A railway route must satisfy all of the following conditions.
[Condition 1] Starting from some cell, repeat k times (3 ≦ k) moving to an edge-adjacent cell, and end at the starting cell.
[Condition 2] For the k moves, the destinations are all distinct. (The start and end may coincide.)
[Condition 3] It does not pass through mountain cells.

Find the maximum number of cells that this railway route passes through. If no route satisfying the conditions exists, report that fact instead.

## Constraints
・H,W は正整数
・HW ≦ 16
・c[i][j] は '#' または '.' である
・c[i][j] が '.' である i, j (1 ≦ i ≦ H, 1 ≦ j ≦ W) が 1 つ以上存在する

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** "何通りか" の感覚／バックトラック (a feel for "how many ways" / backtracking)
- **Core idea:** With HW ≤ 16 the number of simple cycles is small enough to enumerate exhaustively. Backtracking (recursive DFS) from each start cell, trying all four directions, enumerating paths that never revisit a cell and return to the start, gives the answer.
- **Editorial steps:**
  - **解法.** In this problem, even for (H, W) = (4, 4), the number of routes that move up/down/left/right without visiting the same cell twice is at most 28512, so a brute-force over all routes is effective. Having the feeling that "the number of cases is not that large, so exhaustive search is fine!" is very important in competitive programming. However, the structure is complex, so the techniques used for "searching over all cases" (`for`-loop full search → typical 055 / bit full search → typical 002 / permutation full search → typical 032) cannot be used as-is. So we enumerate all start cells (sx, sy) and use recursion. Concretely: 1. recurse into each of the four possible next moves; 2. when a move gets stuck, or when all directions from the next cell have already been tried, backtrack. This technique is called *backtracking*; an implementation is in the `sol` folder of GitHub (see the animation in the slide). Backtracking makes it possible to exhaustively search even complex structures, and although recursion is notoriously hard to understand, once you get used to it it is simple, so learn it well.
- **Complexity:** The editorial does not state a closed-form complexity; it only argues the search is feasible because the number of simple grid routes is small (≤ 28512 for 4×4). (See Flags.)
- **Author's takeaway / typical pattern (典型):** Backtracking is the standard tool when the state space is small but has a complex structure that neither a plain loop, bit search, nor permutation search can capture. The author also notes the problem can be solved with bit DP (typical 045).
- **Related problems (類題):**
  - 第五回アルゴリズム実技検定-G「へび」
  - ABC196-D「Hanjo」
  - PANASONIC2020-D「String Equivalence」
  - ABC119-C「Synthetic Kadomatsu」
- **Flags:** The editorial gives no formal complexity bound (only the heuristic count ≤ 28512). It also does not spell out the "answer = number of moves k" correspondence nor the k ≥ 3 handling; the reference code infers this (it returns -1 when the best cycle length is ≤ 2).

## Author's Reference Solution
- `072.cpp` — Backtracking DFS: for every plain start cell, recursively extend a path that never revisits a cell (except returning to the start), maximizing the number of moves; output -1 if the best is ≤ 2.

```cpp
#include <iostream>
#include <algorithm>
using namespace std;

int H, W;
char c[20][20];
int dx[4] = { 0, 1, 0, -1 };
int dy[4] = { 1, 0, -1, 0 };
bool used[20][20];

int dfs(int sx, int sy, int px, int py) {
	if (sx == px && sy == py && used[px][py] == true) return 0;
	used[px][py] = true;

	int ret = -10000;
	for (int i = 0; i < 4; i++) {
		int nx = px + dx[i], ny = py + dy[i];
		if (nx < 1 || ny < 1 || nx > H || ny > W || c[nx][ny] == '#') continue;
		if ((sx != nx || sy != ny) && used[nx][ny] == true) continue;
		int v = dfs(sx, sy, nx, ny);
		ret = max(ret, v + 1);
	}
	used[px][py] = false;
	return ret;
}

int main() {
	// Step #1. Input
	cin >> H >> W;
	for (int i = 1; i <= H; i++) {
		for (int j = 1; j <= W; j++) cin >> c[i][j];
	}

	// Step #2. DFS
	int Answer = -1;
	for (int i = 1; i <= H; i++) {
		for (int j = 1; j <= W; j++) {
			Answer = max(Answer, dfs(i, j, i, j));
		}
	}
	if (Answer <= 2) Answer = -1;
	cout << Answer << endl;
	return 0;
}
```
