# 062 — Paint All (reverse simulation / queue expansion)

**Difficulty:** ★×6 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_bj
**Source:** AtCoder Typical90 #062 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
N 個の白いボールと N 個のアイテムがあります。
ボールとアイテムにはそれぞれ 1 から N までの番号がついています。

ここで、アイテム i について以下のことがわかっています。
・ボール A[i], B[i] の少なくとも一方が白である時、またその時に限り使える。
・これを使うと、ボール i を黒く塗ることができる。

N 個のアイテムを適切な順序で使うことで、全てのボールを黒く塗ることは可能でしょうか？
可能ならば、使う順序の一例を求めてください。
```

## Statement (English translation)
There are N white balls and N items.
The balls and the items are each numbered from 1 to N.

Here, the following is known about item i.
・It can be used when, and only when, at least one of ball A[i] and ball B[i] is white.
・Using it paints ball i black.

Is it possible to paint all the balls black by using the N items in an appropriate order?
If it is possible, find one example of an order in which to use them.

## Constraints
```
【制約】
・1 ≦ N ≦ 10^5
・1 ≦ A[i], B[i] ≦ N
・入力は全て整数
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 後ろから考える (think it through backwards / reverse the process)
- **Core idea:** Going forwards you cannot decide which item to use, because usability depends on balls that later items will paint. So reverse time: start from all balls black and "un-paint" — a ball turns white and stays white, and item i becomes performable as soon as A_i = i or B_i = i, or one of balls A_i, B_i is already white. In this reversed world 「一度「操作 i ができる状態」になったら二度と「操作 i ができない状態」にならない」, so greedily performing any currently-available operation is safe; the only issue is finding the newly-enabled items without rescanning all N of them after every step. Store 「あるボールを白色に変えたら、どの操作を行うことが可能か」 as a directed graph (edges A_i → i and B_i → i) and drive the process with a queue → O(N).
- **Editorial steps:**
  - **Step 1 — the forward attempt fails, so reverse (O(N²) 解法):** 「この問題は、前から適当な順序で操作していくなどの方法を考えても失敗します。そんなときは「後ろから考える」というテクニックを使いましょう。つまり、以下の問題に言い換えることができます」: 「最初、ボールは全部黒色で塗られているとする。ボール i を白色に変える操作（以後、操作 i とする）は、A_i = i または B_i = i であるか、ボール A_i と B_i のうち少なくとも一方が白で塗られている場合に行える。全部のボールを白にできるか？」 (the reason for the extra 「A_i = i または B_i = i」 clause: ball i is still black at the moment 操作 i fires, so if both A_i and B_i are black it can only be fired when one of them *is* i itself).
  - **Step 2 — monotonicity makes greedy valid:** 「一度「操作 i ができる状態」になったら二度と「操作 i ができない状態」にならない」, therefore 「今行える操作を 1 つ選び貪欲に行う手法が通用します。（そのとき、どんな操作を選んでも結果は変わりません）」.
  - **Step 3 — why the naive greedy is too slow:** 「操作は高々 N 回なので、「今どの操作を行えるのか」を全て調べ上げた場合、全体計算量 O(N²) となり TLE します」.
  - **Step 4 — the graph (O(N) 解法):** 「「あるボールを白色に変えたら、どの操作を行うことが可能になるか」を有向グラフの形で表してみましょう。例えば、1 ≦ i ≦ N について A_i → i, B_i → i の辺を追加するとします」. The slide's example is N = 4 with (A_1, A_2, A_3, A_4) = (1, 1, 2, 1) and (B_1, B_2, B_3, B_4) = (2, 4, 4, 3), giving the edges 1→1 (self-loop, from A_1 = 1), 2→1, 1→2, 4→2, 2→3, 4→3, 1→4, 3→4 — the drawn figure has 1, 2, 3, 4 as vertices with the loop on 1 and both directions between 1 and 2. And: 「ボール i を白色に変えたら、頂点 i から頂点 P_1, P_2, …, P_T に辺が出ている場合、操作 {P_1, P_2, …, P_T} を新たに行うことができます」.
  - **Step 5 — queue/BFS:** 「したがって、グラフの情報を隣接リスト形式で管理した上で、queue に「今どの操作を行えるか」を入れれば、全体計算量を O(N) まで減らせます」 — 「今行える操作であればどれを選んでも良いので、queue の先頭になっている操作を行う、などで問題ありません」. 「なお、queue を使うアルゴリズムの一例として幅優先探索が挙げられます。典型 043 などでも出題されていますが、理解していない方は改めて確認しておきましょう」. The queue is seeded with every i such that A_i = i or B_i = i (the slide's rephrased rule, first clause), and the order in which the reversed process whitens the balls is the *reverse* of a legal forward order.
- **Complexity:** O(N) (「全体計算量を O(N) まで減らせます」 / 「計算量 O(N) でこの問題を解くことができます」); the rescan-per-step version is explicitly 「O(N²) となり TLE します」. Memory: not stated on the slides (the reference code uses an adjacency list of 2N edges plus `usable[]` and a queue).
- **Author's takeaway / typical pattern (典型):** 後ろから考える — when the forward direction depends on the future, reverse the process so that it becomes monotone, then greedily drive it with a queue/BFS that stores 「今どの操作が行えるか」.
- **Related problems (類題):** ABC 120-D「Decayed Bridge」, ABC 137-D「Summer Vacation」, AGC 033-B「LRUD Game」.
- **Flags:** (1) The equivalence of the reversed problem with the original is asserted, never proved. The two claims needing proof are (a) if the reversed greedy whitens all N balls, then the reverse of its order is a legal forward order (each item is usable at its moment), and (b) if some forward order exists then the reversed process cannot run out early. Boundaries to test: N = 1, and an item with A_i = B_i. (2) The monotonicity sentence is unqualified: it is true only in the *reversed* process, where white never becomes black again; in the original process painting a ball black can make an item unusable. Boundary: a case where an item becomes permanently unusable (sample 5 of this problem, answer −1). (3) The O(N) paragraph never states the queue's initial contents; the seeding 「A_i = i または B_i = i」 is only visible in the rephrased rule and in `062.cpp`'s `if (A[i] == i || B[i] == i) { usable[i] = true; Q.push(i); }`. (4) The slide never says that the collected order must be printed reversed, nor what to output when the process stops before N items (the problem's 出力形式 says −1; the code prints −1 when `vec.size() != N`). (5) Ball i and item i are used as one vertex in both the figure and the code (`G[pos]` is indexed by an item id) — legitimate only because item i paints ball i in this problem; the slide never remarks on the identification, so the graph can be misread as bipartite balls/items. (6) The real cost is O(N + Σ|G[i]|) = O(N) because each of the 2N edges is relaxed once and `usable[]` prevents re-queueing; the slide only says 「O(N) まで減らせます」 without saying each edge/vertex is handled once — an unguarded `push` can enqueue an item twice when A_i = B_i.

## Author's Reference Solution
`062.cpp` — Seeds a queue with every item i such that `A[i] == i` or `B[i] == i`, expands to items sharing the balls of processed items through an adjacency list, then reverses the collected order and prints it, or `-1` if fewer than N items were collected.

```cpp
#include <iostream>
#include <vector>
#include <queue>
#include <algorithm>
using namespace std;

int N;
int A[1 << 18], B[1 << 18];
bool usable[1 << 18];
vector<int> G[1 << 18];
queue<int> Q;

int main() {
	// Step #1. 入力
	cin >> N;
	for (int i = 1; i <= N; i++) {
		cin >> A[i] >> B[i];
		G[A[i]].push_back(i);
		G[B[i]].push_back(i);
		if (A[i] == i || B[i] == i) {
			usable[i] = true;
			Q.push(i);
		}
	}

	// Step #2. 後ろからシミュレーション
	vector<int> vec;
	while (!Q.empty()) {
		int pos = Q.front(); Q.pop();
		vec.push_back(pos);
		for (int i : G[pos]) {
			if (usable[i] == true) continue;
			usable[i] = true;
			Q.push(i);
		}
	}

	// Step #3. 答えを求める
	reverse(vec.begin(), vec.end());
	if (vec.size() != N) {
		cout << "-1" << endl;
	}
	else {
		for (int i = 0; i < vec.size(); i++) cout << vec[i] << endl;
	}
	return 0;
}
```
