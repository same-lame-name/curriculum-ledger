# 017 — Crossing Segments (Counting Intersecting Chords)

**Difficulty:** ★×7 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_q
**Source:** AtCoder Typical90 #017 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
円周上に N 個の点があり、時計回りに 1, 2, ..., N と番号付けられています。
M 個の線分があり、線分 i は点 L[i] と R[i] を結んでいます。

組 (s, t) [1 ≦ s < t ≦ M] のうち、次の条件を満たすものの個数を出力してください。
・線分 s と t が端点以外で交わる。

## Statement (English translation)
There are N points on a circle, numbered 1, 2, ..., N in clockwise order.
There are M line segments, and segment i connects point L[i] and point R[i].

Among the pairs (s, t) [1 ≦ s < t ≦ M], output the number of those that satisfy the following condition.
・Segments s and t intersect at a place other than their endpoints.

**Subtasks (小課題)**
1. N ≦ 1000, M ≦ 1000
2. N ≦ 1000
3. No additional constraints

## Constraints
【制約】
・3 ≦ N ≦ 10^5
・3 ≦ M ≦ 10^5
・1 ≦ L[i] < R[i] ≦ N
・(L[i], R[i]) ≠ (L[j], R[j]) [i ≠ j]

【小課題】
1. N ≦ 1000、M ≦ 1000
2. N ≦ 1000
3. 追加の制約はない

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** P1: 条件を式で表してみる (try writing the condition as a formula). P2: 余事象を考える (count the complement). P3: BIT で高速化 (speed up with a BIT).
- **Core idea:** Chords (L_s, R_s) and (L_t, R_t) with L < R cross (away from their endpoints) iff the four endpoints alternate: L_s < L_t < R_s < R_t or L_t < L_s < R_t < R_s. P1 tests this for all M(M−1)/2 pairs in O(M²). P2 instead counts the complement — the non-crossing pairs — split into three patterns that are each easy to count, in O(NM). P3 replaces the O(N) per-segment counting inside pattern 3 with a BIT, reaching O(N + M log N).
- **Editorial steps:**
  - **P1 Step 1 (the condition as a formula):** first write down when two segments s, t intersect: 「L_s < L_t < R_s < R_t または L_t < L_s < R_t < R_s」. Drawing all relative positions on paper gives the six cases: L_s < R_s < L_t < R_t and L_t < R_t < L_s < R_s (disjoint arcs), L_s < L_t < R_t < R_s and L_t < L_s < R_s < R_t (one interval inside the other), and the two above (the chords cross). 「このように、条件を式で表すのは大切です」.
  - **P1 Step 2 (brute force, O(M²)):** enumerate all pairs (s, t); there are M(M−1)/2 of them, so the cost is O(M²), which is efficient enough for subtask 1 (M ≤ 1000). The snippet increments Answer once for each of the two inequalities (`if (L[s] < L[t] && L[t] < R[s] && R[s] < R[t]) Answer += 1;` and the symmetric one). 「最初は全探索を考えることも大切です」— many ABC B–C problems are solved by full search.
  - **P1 Step 3 (why it is not enough):** for M ≤ 10^5 about 10^10 operations are needed, so this TLEs.
  - **P2 Step 1 (switch to the complement):** the condition 「L_s < L_t < R_s < R_t」 is complicated, so count instead the pairs that do NOT satisfy it — 余事象 — and split them into three patterns: (1) two of L_s, L_t, R_s, R_t coincide, i.e. the segments meet at an endpoint; (2) R_s < L_t, the intervals are disjoint along the circle (the green cases); (3) with respect to the two intervals [L_s, R_s] and [L_t, R_t], one interval completely contains the other (the pink cases).
  - **P2 Step 2 (pattern 1, O(N)):** with cnt_i = the number of segments at point i, Answer1 = Σ_(i=1..N) cnt_i (cnt_i − 1) / 2.
  - **P2 Step 3 (pattern 2, O(N+M)):** first compute v_i = #{s : R_s ≤ i} for i = 1…N; a prefix sum does it in O(N + M). Then Answer2 = Σ_(i=1..M) v_(L_i − 1).
  - **P2 Step 4 (pattern 3, the essence, O(N) per segment):** add the segments in increasing order of R_s. When segment s (with value L_s = cl) is added, the segments already added that stand in pattern 3 with it are exactly those with L_s < L_t. Memorising w_i = #{t : L_t = i} lets this be counted in O(N), so pattern 3 costs O(NM) overall and is the bottleneck.
  - **P2 footnote (ties):** when R_i are equal, adding the segments in increasing order of L_i counts them without overlap.
  - **P3 Steps 1–2 (the operations needed):** pattern 3 requires two operations: (1) add one segment, each carrying its value L; (2) count how many of the currently added segments satisfy cl < L — equivalently, subtract the number with L ≤ cl from the total.
  - **P3 Step 3 (BIT):** a Binary Indexed Tree supports init() (lay out a_1…a_N, O(N)), add(x, y) (a_x += y, y may be negative) and query(x) (a_1 + … + a_x) in O(log N) each, so all M queries cost O(N + M log N). The implementation is omitted 「紙面の都合上割愛」.
- **Complexity:** P1 O(M²); P2 O(NM); P3 O(N + M log N) with a BIT of size N.
- **Author's takeaway / typical pattern (典型):** write the condition as an inequality and start from brute force; if the direct condition is messy, count the 余事象 and split it into patterns that are easy to count; and even when a solution 「一見 O(N²) から落とせないように見えても」, a data structure such as a BIT can remove a factor.
- **Related problems (類題):** P1: ABC181-C 「Collinearity」（条件を整理）, JOI Open 2020 「白黒の点」4点解法（円環の問題）. P2: ABC193-C 「Unexpressed」, ABC156-D 「Bouquet」, ABC178-C 「Ubiquity」. P3: JSC2021-F 「Max Matrix」, ABC136-F 「Enclosed Points」, JOI 2019 春合宿 「Examination」
- **Flags:** (1) The three-way split of the complement is asserted to be exhaustive and disjoint without proof — that any two chords either share an endpoint, are disjoint along the circle, or one contains the other — which is the claim to establish. (2) 「点 i にある線分の個数 cnt_i」 is ambiguous; the reference code counts endpoints at i (a segment contributes to both its endpoints), and the Σ cnt(cnt−1)/2 formula then counts each shared-endpoint pair once only because (L_i, R_i) are all distinct, so two segments cannot share both endpoints. (3) Pattern 3 counts the added segments with L_t > L_s; the slide does not say that this automatically restricts L_t to (L_s, R_s) (true because every added segment has R_t ≤ R_s), which is what makes the count equal to the number of nested pairs. (4) The final subtraction Answer = M(M−1)/2 − (Answer1 + Answer2 + Answer3) is never written on the slides; only 「余事象を考える」 implies it. (5) The R-tie footnote is stated without justification. (6) P3 phrases the operation as counting cl < L while a BIT naturally answers ≤ cl, so the implemented query is the complement 「全体から L ≤ cl の個数を引けばよい」; the boundary is cl close to N (the statement's L < R ≤ N keeps it in range).

## Author's Reference Solution
`017-01.cpp` — Tries every pair of segments, sorts the four endpoints by position and counts the pairs whose endpoints alternate.

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int N, M;
int L[1 << 18], R[1 << 18];

int main() {
	// Step #1. Input
	cin >> N >> M;
	for (int i = 1; i <= M; i++) {
		cin >> L[i] >> R[i];
	}

	// Step #2. Brute Force
	int Answer = 0;
	for (int i = 1; i <= M; i++) {
		for (int j = i + 1; j <= M; j++) {
			if (L[i] == L[j] || L[i] == R[j] || R[i] == L[j] || R[i] == R[j]) continue;
			vector<pair<int, int>> vec;
			vec.push_back(make_pair(L[i], 1));
			vec.push_back(make_pair(R[i], 1));
			vec.push_back(make_pair(L[j], 2));
			vec.push_back(make_pair(R[j], 2));
			sort(vec.begin(), vec.end());
			if (vec[0].second == 1 && vec[1].second == 2 && vec[2].second == 1 && vec[3].second == 2) Answer++;
			if (vec[0].second == 2 && vec[1].second == 1 && vec[2].second == 2 && vec[3].second == 1) Answer++;
		}
	}

	// Step #3. Output The Answer!
	cout << Answer << endl;
	return 0;
}
```

`017-02.cpp` — Counts the pairs that share an endpoint, the pairs of disjoint segments and the pairs where one segment lies inside the other, then prints M(M-1)/2 minus their sum.

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

// Input
long long N, M;
long long L[1 << 18], R[1 << 18];

// Kazoeage
long long V1[1 << 18], V2[1 << 18], V3[1 << 18];
long long cnt[1 << 18];

int main() {
	// Step #1. Input
	cin >> N >> M;
	for (int i = 1; i <= M; i++) cin >> L[i] >> R[i];

	// Step #2. Get Answer1
	long long Answer1 = 0;
	for (int i = 1; i <= M; i++) V3[L[i]] += 1;
	for (int i = 1; i <= M; i++) V3[R[i]] += 1;
	for (int i = 1; i <= N; i++) Answer1 += V3[i] * (V3[i] - 1LL) / 2LL;

	// Step #3. Get Answer2
	long long Answer2 = 0;
	for (int i = 1; i <= M; i++) V1[R[i]] += 1;
	for (int i = 1; i <= M; i++) V2[L[i] - 1] += 1;
	for (int i = 1; i <= N; i++) V1[i] += V1[i - 1];
	for (int i = 1; i <= N; i++) Answer2 += V1[i] * V2[i];

	// Step #4. Sorting
	vector<pair<long long, long long>> vec;
	for (int i = 1; i <= M; i++) vec.push_back(make_pair(R[i], L[i]));
	sort(vec.begin(), vec.end());

	// Step #5. Get Answer3
	long long Answer3 = 0;
	for (int i = 0; i < vec.size(); i++) {
		long long cl = vec[i].second, cr = vec[i].first;
		long long ret = 0;
		for (int j = cl + 1; j <= cr; j++) ret += cnt[j];
		Answer3 += ret;
		cnt[cl] += 1;
	}

	// Step #6. Output The Answer!
	long long Total = M * (M - 1) / 2LL;
	long long SumAns = Answer1 + Answer2 + Answer3;
	cout << Total - SumAns << endl;
	return 0;
}
```

`017-03.cpp` — Same counting as 017-02, but the contained-pair count uses a BIT instead of a linear scan.

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

class BIT {
public:
	int size_ = 1;
	vector<long long> bit;

	void init(int sz) {
		size_ = sz + 2;
		bit.resize(size_ + 2, 0);
	}
	void add(int pos, long long x) {
		pos++;
		while (pos <= size_) {
			bit[pos] += x;
			pos += (pos & -pos);
		}
	}
	long long sum(int pos) {
		long long s = 0; pos++;
		while (pos >= 1) {
			s += bit[pos];
			pos -= (pos & -pos);
		}
		return s;
	}
};

// Input
long long N, M;
long long L[1 << 18], R[1 << 18];

// Kazoeage
long long V1[1 << 18], V2[1 << 18], V3[1 << 18];

int main() {
	// Step #1. Input
	cin >> N >> M;
	for (int i = 1; i <= M; i++) cin >> L[i] >> R[i];

	// Step #2. Get Answer1
	long long Answer1 = 0;
	for (int i = 1; i <= M; i++) V3[L[i]] += 1;
	for (int i = 1; i <= M; i++) V3[R[i]] += 1;
	for (int i = 1; i <= N; i++) Answer1 += V3[i] * (V3[i] - 1LL) / 2LL;

	// Step #3. Get Answer2
	long long Answer2 = 0;
	for (int i = 1; i <= M; i++) V1[R[i]] += 1;
	for (int i = 1; i <= M; i++) V2[L[i] - 1] += 1;
	for (int i = 1; i <= N; i++) V1[i] += V1[i - 1];
	for (int i = 1; i <= N; i++) Answer2 += V1[i] * V2[i];

	// Step #4. Sorting
	vector<pair<long long, long long>> vec;
	for (int i = 1; i <= M; i++) vec.push_back(make_pair(R[i], L[i]));
	sort(vec.begin(), vec.end());

	// Step #5. Get Answer3
	long long Answer3 = 0;
	BIT Z; Z.init(N + 2);
	for (int i = 0; i < vec.size(); i++) {
		long long cl = vec[i].second, cr = vec[i].first;
		long long ret = Z.sum(cr) - Z.sum(cl);
		Answer3 += ret;
		Z.add(cl, 1);
	}

	// Step #6. Output The Answer!
	long long Total = M * (M - 1) / 2LL;
	long long SumAns = Answer1 + Answer2 + Answer3;
	cout << Total - SumAns << endl;
	return 0;
}
```
