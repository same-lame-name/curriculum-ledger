# 056 — Lucky Bag (subset-sum DP with reconstruction)

## Statement (original Japanese)
```
デパートの高橋屋では N 日にわたって初売りが行われます。
i 日目には A[i] 円の福袋 A と B[i] 円の福袋 B が売られます。

低橋くんは N 日間、毎日高橋屋で福袋 A か福袋 B のどちらかを購入します。
N 日間で購入した N 個の福袋の総額が S 円になるような購入の方法が存在するかを判定し、存在するならばその一例を求めてください。

【出力形式】
存在する場合　｜N 文字の文字列 T を出力してください。文字列 T の i (1 ≦ i ≦ N) 文字目を T[i] とするとき、i 日目に福袋 A を購入する場合 T[i] = 'A'、福袋 B を購入する場合は T[i] = 'B' にしてください。
存在しない場合｜"Impossible" と出力してください。
```

## Statement (English translation)
At the department store Takahashi-ya, a first sale is held over N days.
On day i, lucky bag A priced at A[i] yen and lucky bag B priced at B[i] yen are sold.

Hikobashi-kun buys either lucky bag A or lucky bag B at Takahashi-ya every day for N days.
Determine whether there exists a way of buying such that the total price of the N lucky bags bought over the N days is S yen, and if such a way exists, find one example of it.

【Output format】
If it exists: output a string T of N characters. Let T[i] be the i-th (1 ≦ i ≦ N) character of the string T; set T[i] = 'A' if lucky bag A is bought on day i, and T[i] = 'B' if lucky bag B is bought.
If it does not exist: output "Impossible".

## Constraints
```
【制約】
・1 ≦ N ≦ 100
・1 ≦ S ≦ 10^5
・1 ≦ A[i], B[i] ≦ 10^5 (1 ≦ i ≦ N)
・入力はすべて整数
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** DP 復元 (reconstructing the answer of a DP)
- **Core idea:** Split the task in two. First answer only the decision problem 「買い物計画が存在するか」 with dp[i][j] = whether exactly j yen can be spent in the first i days; then recover one plan by walking that table backwards from (N, S). On day i you may choose A if dp[i−1][j−A_i] is true and B if dp[i−1][j−B_i] is true; if dp[i][j] is true then at least one of the two is, so the choice is determined at every step and the reconstruction never backtracks.
- **Editorial steps:**
  - **Step 1 (the decision DP):** Define dp[i][j] = 「i 日目までに合計 j 円の買い物が可能か (true/false)」 and fill it in increasing order of (i, j): for i = 0 only dp[0][0] = true (「i = 0 のとき、j = 0 のときだけ dp[i][j] = true になる」); for i ≥ 1, dp[i][j] = true exactly when 「dp[i−1][j−A_i] と dp[i−1][j−B_i] の片方でも true」. The answer to the decision problem is dp[N][S], and the total cost is O(N × S). The slide's diagram shows the two incoming transitions: 「直前までに j−A_i 円の買い物ができる」 or 「直前までに j−B_i 円の買い物ができる」 ⇒ 「j 円の買い物ができる」.
  - **Step 2 (reconstruction, decided in reverse):** 「DP で求めた答えの復元は『逆順に決めていく』ことで実現できます」. For day N: A may be chosen if dp[N−1][S−A_N] = true, and B may be chosen if dp[N−1][S−B_N] = true. One of them must hold — 「そうじゃないと dp[N][S] = false になる」 — so day N's choice is determined; then continue with N−1, N−2, …, 1 in the same way.
  - **Step 3 (the slide's worked table):** N = 3, S = 15, (A, B) = (4,2), (7,3), (5,8). The reachable totals per row are day 0: {0}; day 1: {2, 4}; day 2: {5, 7, 9, 11}; day 3: {10, 12, 13, 14, 15}, so dp[3][15] = true. Walking backwards: from 15 both 15 − 5 = 10 and 15 − 8 = 7 are reachable, and the slide's red path takes B (15 → 7); from 7 only 7 − 3 = 4 is reachable (7 − 7 = 0 is false), so B again (7 → 4); from 4 only 4 − 4 = 0 works, so A (4 → 0). The reconstructed plan is A B B = 4 + 3 + 8 = 15, with the slide's arrows labelled A, B, B on the way back to (0, 0); the dotted arrows are the transitions that were not taken.
  - **Step 4 (generalisation):** The same backwards walk works for DPs whose table is not true/false — e.g. knapsack — by repeatedly choosing something that can still be part of an optimal solution, and the same idea reconstructs a shortest path (「これと同様の考え方を、最短経路問題の復元にも使えます」).
- **Complexity:** O(N × S) time for the DP (stated on the slide); the reconstruction itself adds only O(N). Memory not stated on the slides — the backtrack needs the table, so O(N × S) unless the choices are stored differently.
- **Author's takeaway / typical pattern (典型):** 「DP の答えの復元は『DP を求めたのと逆順』で決めていく」 — and the idea generalises: solving the decision problem is only half of it, reconstructing the answer is 「意外と本質的な事」, both in contests and in real problems.
- **Related problems (類題):** Educational DP Contest 問題 F 「LCS」, ABC 168-D 「.. (Double Dots)」, ABC 200-D 「Happy Birthday! 2」.
- **Flags:** (1) The rule 「どちらかは true になる」 presumes the states j − A_i and j − B_i are inside the table: the slide draws j only for 0 ≤ j ≤ S and never states the guard j ≥ A_i / j ≥ B_i, although the constraints allow A_i, B_i up to 10⁵ > S — and a negative index is exactly what the transition reads. (2) The choice is not unique: in the worked table day 3 could equally take A (15 − 5 = 10 is reachable), and A_i = B_i is not forbidden by the constraints, so the reconstruction needs a tie-breaking rule (and must not double-count); the card's sample 2 says explicitly that both BABBA and BAAAB are accepted. (3) The slide never says what dp[i][j] means for j < 0, which is the boundary the transition depends on (it must be false, not out of range). (4) The complexity is quoted only for the DP; the reconstruction's cost, and the fact that the printed plan must be exactly N characters long, are left implicit.

## Author's Reference Solution
`056.cpp` — DP over days and total price: `dp[i][j]` records whether exactly j yen is reachable after i days, then reconstructs one purchase sequence backwards from S and prints it (or `Impossible`).

```cpp
#include <string>
#include <vector>
#include <iostream>
using namespace std;
int main() {
	int N, S;
	cin >> N >> S;
	vector<int> A(N), B(N);
	for (int i = 0; i < N; ++i) {
		cin >> A[i] >> B[i];
	}
	vector<vector<bool> > dp(N + 1, vector<bool>(S + 1, false));
	dp[0][0] = true;
	for (int i = 0; i < N; ++i) {
		for (int j = 0; j <= S; ++j) {
			if (j >= A[i] && dp[i][j - A[i]]) dp[i + 1][j] = true;
			if (j >= B[i] && dp[i][j - B[i]]) dp[i + 1][j] = true;
		}
	}
	if (!dp[N][S]) {
		cout << "Impossible" << endl;
	}
	else {
		string res(N, '?');
		int pos = S;
		for (int i = N - 1; i >= 0; --i) {
			if (pos >= B[i] && dp[i][pos - B[i]]) {
				res[i] = 'B';
				pos -= B[i];
			}
			else {
				res[i] = 'A';
				pos -= A[i];
			}
		}
		cout << res << endl;
	}
	return 0;
}
```
