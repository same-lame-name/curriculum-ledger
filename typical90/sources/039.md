# 039 — Tree Distance (Sum of All Pairwise Distances)

**Difficulty:** ★×5 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_am
**Source:** AtCoder Typical90 #039 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
N 頂点の木が与えられます。木の頂点にはそれぞれ 1 から N までの番号が振られています。 
i 番目の辺は頂点 a[i] と頂点 b[i] を双方向に結んでおり、長さはすべて 1 です。

---
dist(1, 2) + dist(1, 3) + dist(1, 4) + ... + dist(1, N) + dist(2, 3) + ...  + dist(2, N) + ... + dist(N-2, N-1) + dist(N-2, N) + dist(N-1, N)
---

の値を計算してください。ただし、dist(u, v) は頂点 u から v までの最短距離とします。

## Statement (English translation)
A tree with N vertices is given. The vertices of the tree are each numbered 1 through N.
The i-th edge connects vertex a[i] and vertex b[i] bidirectionally, and all its lengths are 1.

---
dist(1, 2) + dist(1, 3) + dist(1, 4) + ... + dist(1, N) + dist(2, 3) + ...  + dist(2, N) + ... + dist(N-2, N-1) + dist(N-2, N) + dist(N-1, N)
---

Compute the value of the above. However, dist(u, v) is the shortest distance from vertex u to vertex v.

## Constraints
【制約】
・2 ≦ N ≦ 10^5
・1 ≦ a[i], b[i] ≦ N
・与えられるグラフは木である
・入力はすべて整数

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** 答えへの貢献度を考える (think about each edge's degree of contribution to the answer).
- **Core idea:** The required quantity is a sum over vertex pairs, so reverse the summation: for every edge count how many pairs have it on their shortest path (its 「貢献度」). In a tree, deleting an edge splits the vertices into the subtree side (say r vertices) and the rest (N − r), and exactly the r(N − r) cross pairs use that edge. One DFS computing subtree sizes gives every r, so the answer is the sum of r(N − r) over the N − 1 edges in O(N).
- **Editorial steps:**
  - **Step 1 (root the tree and ask per edge):** Regard the tree as a rooted tree with vertex 1 as the root. Then ask 「ある辺は何個の頂点対に対する最短経路に含まれるか？」 — how many vertex pairs (u,v) have this edge on their shortest path, i.e. that edge's contribution to the answer.
  - **Step 2 (worked example):** For edge 1−5 the pairs whose shortest path goes through it are (1,3), (1,4), (1,5), (2,3), (2,4), (2,5) — six pairs — so this edge's contribution to the answer is 6.
  - **Step 3 (the general formula):** What formula gives each edge's contribution when the number of vertices is N? Take the group A of vertices on the near side of the edge (「頂点 x の部下みたいな感じの頂点」, including x itself) and the other group B; a pair (u,v) has the red edge on its shortest path exactly when u and v belong to different groups. Hence the contribution is |A| × (N − |A|), where |A| is the number of vertices in group A. (The slide notes that the edge is drawn with a direction in the figure only for convenience — edges are actually undirected.)
  - **Step 4 (computing |A| by tree DP):** With dp[x] = the number of vertices 「部下みたいな感じ」 of x, and y1, y2, …, yk the direct children of x (the vertices connected to x by an edge), dp[x] = dp[y1] + dp[y2] + … + dp[yk] + 1. Hence a single DFS from the root fills every dp: `void dfs(int pos, int pre){ dp[pos] = 1; for (int i : G[pos]) { if (i != pre) { dfs(i, pos); dp[pos] += dp[i]; } } }`. Summing r(N − r) over the N − 1 edges with r the subtree size of the lower endpoint gives the answer.
- **Complexity:** O(N) overall (「答えへの貢献度を考えた上で木 DP を行うと、全体計算量 O(N) でこの問題を解くことができます」). Memory not stated on the slide (the reference code keeps an adjacency list, a subtree-size array and the edge list).
- **Author's takeaway / typical pattern (典型):** The transferable pattern is 「答えへの貢献度を考えるテクニック」 combined with a tree DP. The slide says this way of counting is one of the techniques called 主客転倒 (swapping the subject and the object of the sum), and that it is also usable in problems that evaluate a Σ-expression.
- **Related problems (類題):** ABC 186-D「Sum of difference」, ABC 172-D「Sum of Divisors」, ABC 147-D「Xor Sum 4」, ARC 117-C「Tricolor Pyramid」.
- **Flags:** (1) The text says the formula is as in 「次ページの図」 but the derivation sits on the same slide's right panel; the equality "sum over edges of r(N − r) = sum over pairs of dist" is only illustrated on the one example, never proved (the "only cross pairs use the edge" step is the one to prove). (2) The slide's dp recurrence silently assumes the DFS is rooted at 1 and that the parent check is enough — true for a tree, but never stated. (3) The reference code uses r = min(dp[a], dp[b]), the smaller side, rather than the subtree of the lower endpoint; r(N − r) is symmetric so both agree, but the slide never mentions taking the smaller side. (4) Boundary: N = 2 gives one edge with r = 1, answer 1 (sample 1); at N = 10^5 the answer reaches ~1.7 × 10^14, so 64-bit is required — the slide never mentions the magnitude or the type. (5) The DFS is written recursively with no depth guard; a path-shaped tree of 10^5 vertices is the boundary where the reference code's recursion depth matters.

## Author's Reference Solution
`039.cpp` — Roots the tree at 1, computes subtree sizes with a DFS and adds r(N-r) for every edge, where r is the size of the smaller side.

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

long long N;
long long A[1 << 18], B[1 << 18];
long long dp[1 << 18];
vector<int> G[1 << 18];

void dfs(int pos, int pre) {
	dp[pos] = 1;
	for (int i : G[pos]) {
		if (i == pre) continue;
		dfs(i, pos);
		dp[pos] += dp[i];
	}
}

int main() {
	// Step #1. 入力
	cin >> N;
	for (int i = 1; i <= N - 1; i++) {
		cin >> A[i] >> B[i];
		G[A[i]].push_back(B[i]);
		G[B[i]].push_back(A[i]);
	}

	// Step #2. 深さ優先探索（DFS）
	dfs(1, -1);

	// Step #3. 答えを求める
	long long Answer = 0;
	for (int i = 1; i <= N - 1; i++) {
		long long r = min(dp[A[i]], dp[B[i]]);
		Answer += r * (N - r);
	}
	cout << Answer << endl;
	return 0;
}
```
