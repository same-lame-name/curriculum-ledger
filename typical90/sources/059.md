# 059 — Many Graph Queries (bitset reachability over a DAG)

**Difficulty:** ★×7 (author's star rating)
**Link:** https://atcoder.jp/contests/typical90/tasks/typical90_bg
**Source:** AtCoder Typical90 #059 — official statement and samples; editorial essence distilled from the official Japanese slides.

## Statement (original Japanese)
```
N 頂点 M 辺の有向グラフが与えられます。このグラフにおいて、辺 i (1 ≦ i ≦ M) は頂点 X[i] から Y[i] に向かいます。

Q 個の、次の形式のクエリに答えてください。
・頂点 A[j] から B[j] まで、辺を向きのとおりに通って移動することは可能か？
```

## Statement (English translation)
A directed graph with N vertices and M edges is given. In this graph, edge i (1 ≦ i ≦ M) goes from vertex X[i] to vertex Y[i].

Answer Q queries of the following form.
・Is it possible to travel from vertex A[j] to vertex B[j] by traversing edges in the direction they point?

Subtasks
1. (2 points) N, M, Q ≦ 2000
2. (5 points) No additional constraints

## Constraints
```
【制約】
・2 ≦ N ≦ 100000
・1 ≦ M ≦ 100000
・1 ≦ Q ≦ 100000
・1 ≦ X[i] < Y[i] ≦ N
・1 ≦ A[j] < B[j] ≦ N
・入力はすべて整数

【小課題】
1. (2 点) N, M, Q ≦ 2000
2. (5 点) 追加の制約はない
```

## Author's Editorial — Concept & Essence
- **Keyword (キーワード):** P1: DAG を使いこなそう (get comfortable wielding the DAG structure). P2: ビット演算で 64 倍高速化 (a 64× speedup by bit operations). P3 (おまけ, bonus): SCC → DAG (decompose into strongly connected components, then work on the resulting DAG).
- **Core idea:** Because the statement guarantees X[i] < Y[i], every edge points at a larger vertex number, so the given numbering is already a topological order and the graph is a DAG. One query then becomes a single sweep: dp[v] = 「s から v に到達可能か」 computed for v = s+1, s+2, …, N as the OR over v's in-neighbours — O(N+M) per query (subtask 1). The sweep is identical for every query and differs only in where the `true` is seeded, so pack 64 queries' booleans into the 64 bits of one integer and answer 64 queries per sweep (full score). For a general graph the same trick survives: contract each SCC to a single vertex first — the result is a DAG — and run the same bitset DP (P3, 「おまけ」).
- **Editorial steps:**
  - **Step 1 (P1, 「DAG について」) — the two properties of a DAG:** ① 頂点をある順番（トポロジカル順）に番号付けすると、どの辺も「番号が大きい方向にしか行かない」ようにできる; ② この性質を使って、動的計画法（DP）などの手法が使えることもある. Footnote: such a numbering is called トポロジカルソート (topological sort), 「ですが、本問題では最初から辺の向きが頂点番号の順になっているので、トポロジカルソートをする必要はありません」. The illustration is a 9-vertex example (1→2, 1→3, 2→7, 3→5, 3→4, 5→6, 4→6, 7→8, 8→9, 6→9) captioned 「DAG の一例（番号はトポロジカル順）」.
  - **Step 2 (P1, subtask 1, O(Q(N+M))) — reachability as a DP:** 「本問題では、以下のような質問に答えなければなりません：頂点 s から頂点 t に到達可能か？」. DFS or BFS can do this, 「ですが、満点解法につなげるためにも、今回は DAG の性質を用いた DP による解法を紹介します」: dp[v] = 頂点 s から頂点 v に到達可能か (true/false), computed in increasing order of v — (1) 最初に dp[s] = true にセットする; (2) v = s+1, s+2, …, N の順に、頂点 v に入ってくる辺の始点を a₁, a₂, …, a_k として、どれか 1 つでも dp[a_i] = true であれば dp[v] = true にする. 「質問 1 回あたりの計算量は O(N+M) になり、小課題 1 に通ります」, hence 「全体計算量 O(Q × (N+M))」.
  - **Step 3 (P2, full score) — pack 64 queries into one word:** the premise is N, M, Q ≦ 100000, so 「より高速な解法が求められます。しかしながら、計算量 O(QM) より高速に解くのは困難です」; what remains is 「ビット演算を使って 64 個の質問の答えを一気に求める」 (for the sake of exposition the slide answers queries 0, 1, …, 63 in one go). Idea: subtask 1 recorded dp[v] as true/false; 「64 列並で処理するために、各クエリに対する 64 個の dp[v] を一つまとめて 0 から 2^64 − 1 までの 2 進法の値として記録する」. Definition: dp[v] = 「クエリ q (0 ≦ q ≦ 63) において、頂点 s_q から頂点 v に到達可能なときだけ 2 進法の 2^q の位を 1 にした値」. Steps, mirroring subtask 1: (1) 「最初 dp[v] を (s_q = v となる 2^q の総和) にセットする」; (2) v = 1, 2, …, N の順に、頂点 v に入ってくる辺の始点を a₁, …, a_k として、i = 1, 2, …, k の順に 「dp[v] = dp[v] or dp[a_i]」 に更新する (footnote: 「ここでの or はビット演算の OR を表します」). 「これで、ビット演算の力を存分に使って、クエリ 0〜63 の答えを一気に求められました。一般の場合でも、64 クエリごとに処理することで、計算回数を 1/64 程度に減らせるのです」.
  - **Step 4 (P3, 「おまけ」 さらなる考察) — SCC → DAG:** 「本問題では、各辺が「番号が大きい方向にしか行かない」という制約がありました。しかし、この制約がなく DAG とは限らない一般のグラフの場合でも、高速に解くことができます」. The tool is 強連結成分分解 (SCC): partition the vertices into groups so that ① お互いに行き来できる場合、同じグループにする; ② お互いに行き来できない場合、違うグループにする. Each group is called a 強連結成分, with the two listed properties 「強連結成分内の頂点は、互いに行き来できる」 and 「強連結成分外の頂点は、互いに行き来できない」; and 「この性質より、それぞれの強連結成分を一つの頂点にまとめて作ったグラフは DAG になります」. Procedure: (1) run SCC; (2) replace each SCC by one vertex to build a DAG; (3) answer each query: same SCC as start and goal → 「到達可能」; different SCCs → it becomes a reachability question on the DAG built in (2). The picture's three components are {1,2,7}, {4,5,6,9}, {8,3}.
  - **Step 5 (P3 conclusion + 補足):** 「最後に、DAG において到達可能性を判定する問題は、満点解法で問われた問題と同じなので、64 倍高速化できます。よって、一般の場合でも 64 倍高速化できました」. 補足 on hardness: 「本問題はよく知られた問題ですが、O(N²) よりも高速に解くことは難しいです。なお、特殊な形のグラフであれば高速に解く方法が知られています」 — e.g. 「有向グラフが平面的である場合、Thorup のアルゴリズム（2004）を使うと O(N log N + Q) で解けます」.
- **Complexity:** P1: O(N+M) per query, O(Q × (N+M)) overall (valid for subtask 1's N, M, Q ≦ 2000). P2: the slide keeps the same expression and only shrinks the constant: 「計算量を O(Q × (N + M)) から変えずとも、ビット演算の力で 64 倍高速化することで本問題を AC できます」 — i.e. O(Q(N+M)/64) in effect, never written as a fraction. P3: same bound as P2 on the condensed DAG; the cost of the SCC pass itself is not discussed. Thorup (planar digraphs): O(N log N + Q). Memory: not stated on the slides (`059-02.cpp` keeps one N-word `unsigned long long` array per block of 64 queries).
- **Author's takeaway / typical pattern (典型):** 「DAG の性質を使って解く問題もあるので、みなさんも DAG の性質を知っておきましょう」 — a topological order turns reachability into one swept DP. On the bit side: 「この問題に限らず、ビット AND・ビット OR・ビット XOR・ビットシフトを使いこなすことで、64 倍高速化できる事例が数多くあります」, and 「C++ には std::bitset という標準ライブラリがあるので、ぜひ知っておきましょう」.
- **Related problems (類題):** P1: Educational DP Contest G「Longest Path」, ABC 037-D「経路」, ABC 188-E「Peddler」. P2: AGC 020-C「Median Sum」, AOJ 2955「Two Colors Sort」, yukicoder No. 387「パンコ」, M-SOLUTIONS 2019 F「Random Tournament」. P3 (おまけ): Not listed (059-03 carries no 類題 box).
- **Flags:** (1) The two complexity statements do not match: P1's box quotes 「全体計算量 O(Q × (N+M))」 while P2's box starts from 「計算量 O(QM) より高速に解くのは困難です」 — the N term is silently dropped between slides (M ≧ 1, so they differ). (2) P2's bound is asserted only qualitatively: 「計算回数を 1/64 程度に減らせる」 / 「64 倍高速化することで本問題を AC できます」; the boundary to test is Q < 64 and Q not a multiple of 64 (a partial last block), which `059-02.cpp` handles with `j < (i+1)*64 && j < Q`. (3) The claim 「強連結成分外の頂点は、互いに行き来できない」 is imprecise as printed: two distinct SCCs can still have one-way reachability; what holds is that they cannot reach each other in both directions. The load-bearing consequence — contracting SCCs gives a DAG — is asserted without proof. (4) Why the sweep may start at v = s+1 is never argued: it is valid exactly because every edge satisfies X[i] < Y[i], so any path out of s only visits larger numbers — the property P3 drops, which is why P3 must switch to SCC rather than reuse the sweep. (5) Step 3's initialisation 「s_q = v となる 2^q の総和」 needs 64-bit unsigned words (`1ULL << 63`) and needs duplicate start vertices inside a block to OR together; neither is said, and `int` would be wrong at q = 63. (6) 補足's 「O(N²) よりも高速に解くことは難しい」 carries no qualifier about the model (all-pairs? offline? data structure?) and sits beside P2's O(NM/64) block DP and Thorup's O(N log N + Q); do not quote it as 「no faster algorithm is known」, and test the contradiction on a sparse graph (M ≪ N²), where P2 already beats N².

## Author's Reference Solution
`059-01.cpp` — Subtask 1: sorts the edges by (X, Y), then for each query marks A as visited and makes a single pass over the sorted edge list propagating the visited flag.

```cpp
#include <vector>
#include <iostream>
#include <algorithm>
using namespace std;
int main() {
	cin.tie(0);
	ios_base::sync_with_stdio(false);
	int N, M, Q;
	cin >> N >> M >> Q;
	vector<int> X(M), Y(M);
	for (int i = 0; i < M; ++i) {
		cin >> X[i] >> Y[i];
		--X[i], --Y[i];
	}
	vector<long long> g(M);
	for (int i = 0; i < M; ++i) {
		g[i] = 1LL * Y[i] * N + X[i];
	}
	sort(g.begin(), g.end());
	for (int i = 0; i < M; ++i) {
		X[i] = g[i] % N;
		Y[i] = g[i] / N;
	}
	for (int i = 0; i < Q; ++i) {
		int A, B;
		cin >> A >> B;
		--A, --B;
		vector<bool> vis(N, false);
		vis[A] = true;
		for (int j = 0; j < M; ++j) {
			if (vis[X[j]]) {
				vis[Y[j]] = true;
			}
		}
		cout << (vis[B] ? "Yes\n" : "No\n");
	}
	return 0;
}
```

`059-02.cpp` — Full solution: processes the queries in blocks of 64, packing the starting vertices of each block into one 64-bit bitset per vertex and propagating the bitsets along the topologically sorted edge list.

```cpp
#include <vector>
#include <iostream>
#include <algorithm>
using namespace std;
int main() {
	cin.tie(0);
	ios_base::sync_with_stdio(false);
	int N, M, Q;
	cin >> N >> M >> Q;
	vector<int> X(M), Y(M);
	for (int i = 0; i < M; ++i) {
		cin >> X[i] >> Y[i];
		--X[i], --Y[i];
	}
	vector<long long> g(M);
	for (int i = 0; i < M; ++i) {
		g[i] = 1LL * Y[i] * N + X[i];
	}
	sort(g.begin(), g.end());
	for (int i = 0; i < M; ++i) {
		X[i] = g[i] % N;
		Y[i] = g[i] / N;
	}
	vector<int> A(Q), B(Q);
	for (int i = 0; i < Q; ++i) {
		cin >> A[i] >> B[i];
		--A[i], --B[i];
	}
	for (int i = 0; i * 64 < Q; ++i) {
		vector<unsigned long long> dp(N, 0);
		for (int j = i * 64; j < (i + 1) * 64 && j < Q; ++j) {
			dp[A[j]] |= 1ULL << (j - i * 64);
		}
		for (int j = 0; j < M; ++j) {
			dp[Y[j]] |= dp[X[j]];
		}
		for (int j = i * 64; j < (i + 1) * 64 && j < Q; ++j) {
			cout << (((dp[B[j]] >> (j - i * 64)) & 1) == 1 ? "Yes\n" : "No\n");
		}
	}
	return 0;
}
```
